## 一、算法的定义与描述

> [!important] Definition 算法 Algorithm
> In mathematics and computer science, an algorithm is a **finite sequence of well-defined instructions**, typically used to **solve a class of specific problems** or to **perform a computation**.
> （算法是一个**有限的、定义明确的指令序列**，用于解决**一类**特定问题或完成某种计算。）

**Description 描述方式**（课件列了四种）：Natural Language 自然语言、Programming Language 程序设计语言、Flowchart 流程图、Pseudo Code 伪代码。

> [!important] 四种描述方式按「精确度」排序
> $$\text{自然语言（最不精确）} \;<\; \text{流程图} \approx \text{伪代码} \;<\; \text{程序设计语言（最精确）}$$
> - **自然语言最不精确**：想到一个好解法，用自然语言讲给同桌听，他做出来的常常跟你想的完全不一样。最典型的反例是**菜谱**——"加盐少许""酱油少许""油几勺"，每家的勺子大小都不同，这种描述放到算法里是不合格的（它违反算法的**确定性 Definiteness**）。
> - **程序设计语言最精确**：直接把代码给对方，一定不出错，因为每一步都已经被机器可执行地固定下来。
> - **流程图与伪代码居中**，是日常最常用的两种：既比自然语言严谨，又不像代码那样绑定具体语言。
>
> 实用建议：读学术论文时会发现，计算机方向的论文大多用**流程图 + 伪代码**描述算法。做数学建模等竞赛时，报告里用流程图或伪代码呈现思路，**比直接贴代码或用自然语言描述加分很多**。

> [!note] 定义里两个词值得抠
> - "**a class of** specific problems"：算法解决的是**一类**问题（对任意输入都有效），不是某一个具体输入。只对某组数据奏效的不叫算法。
> - "**finite**"：有限——这直接引出下面的第一条特性。

## 二、算法的五大特性（Characteristics，考试必背）

> [!important] 五条特性原文 + 中译
> 1. **Finiteness 有穷性**：An algorithm should have a finite number of steps and it should end after a finite time.（步数有限，且在有限时间内结束。）
> 2. **Input 输入**：An algorithm may have **many inputs or no inputs at all**.（可以有多个输入，也可以没有输入。）
> 3. **Output 输出**：It should result **at least one output**.（至少要有一个输出。）
> 4. **Definiteness 确定性**：Each step must be clear, well-defined and precise. There should not be any ambiguity.（每一步都清晰无歧义。）
> 5. **Effectiveness 可行性**：Each step must be simple and should take a finite amount of time.（每一步都简单且能在有限时间内完成。）

> [!warning] 三个高频判断题陷阱（第三条为拓展）
> - **输入可以为 0 个，输出不能为 0 个**（"输出至少一个"）。"算法必须有输入"是错的。
> - **有穷性 ≠ 可行性**：有穷性说的是"会停"，可行性说的是"每一步都能真的做出来"。写一步"求出哥德巴赫猜想的证明"违反的是可行性而非有穷性。
> - **【拓展】程序 ≠ 算法**：操作系统是程序但不满足有穷性（设计上就是永不停止）。
>
> 另外要理解"没有输入"和"没有输出"的不对称：一个算法可以不接收输入（比如打印固定内容），但**如果既没有输入又没有输出，就完全看不出它在干什么，也就失去了意义**。

## 三、算法的评价 Evaluation of Algorithms

> [!important] 四项指标（课件四色图标）
> - **Correctness 正确性**
> - **Readability 可读性**
> - **Robustness 健壮性**（中文也常按音译叫**鲁棒性**，就是 robust 的音译）
> - **Efficiency 效率**（Time and Space，时间与空间）

> [!important] 效率的两个维度：时间与空间
> - **时间 Time**：跑得多快。
> - **空间 Space**：占多少**内存 (memory space)**——不是硬盘空间，不是 CPU 寄存器空间。
>
> 需要更新的一点：过去说 memory 只指内存；**现在还必须包括显存 (GPU memory)**，因为显存承担了大量计算任务。做深度学习项目时这一点体感最直接：第一考虑要有好的 CPU/GPU 让它跑得快，第二是显存不够就根本处理不了那么多数据或视频。

> [!note] 顺序不是随便排的
> 正确性排第一：跑得再快的错答案没有价值。可读性排第二——**代码是写给电脑执行的，但是是写给人看的**，所以不要把代码写得很丑。健壮性指非法输入不崩溃——所以第 2 章每个函数开头都有 `if (index < 0 || index >= length) exit(ERROR);` 那一行合法性检查，那不是凑代码，是"健壮性"这条指标的落实。
> 效率排最后，但它是**本课唯一能量化**的指标，所以整节剩下的内容都在讲它。

## 四、为什么不用真实运行时间（Why not real time）

课件用两个反问建立动机：

1. 每年都有新芯片、新手机、新 PC，测试软件说性能提升了 100%，**为什么你感觉不到？**
2. 在**两台不同的机器**上比较两个算法，公平吗？（配图：老人机 vs 旗舰手机）
3. 用**两种不同的语言**实现再比呢？（配图：C++ vs Python）

> [!important] 三个反问背后的具体解释
> **① 为什么感觉不到 100% 的性能提升？**
> 工业界有一句老话：**"英特尔生产了多少，微软就消耗了多少。"** 在摩尔定律（处理速度翻倍约需 **18 个月**）还成立的年代，操作系统和软件的更新速度总能把硬件的提升吃干净，所以用户端几乎感觉不到。
> 补充一句时效性说明：**摩尔定律现在已经不再成立**——芯片已接近物理极限，很难再做得更小更密。这一页幻灯片是大约 5 年前做的，那时这个例子更贴切。
>
> **② 为什么不能在两台机器上比？**
> 有人写了很好的算法但跑在诺基亚老人机上，有人写了很差的算法却跑在 iPhone 上，后者的执行时间大概率更短——但这**不能说明前一个算法差**。现实中同学之间的机器差距同样悬殊：有人能用云计算，有人只有一台笔记本。
>
> **③ 为什么不能跨语言比？**
> 同一个算法，**原生 C++ 大约比原生 Python 快 10 倍**（前提是不调用 Python 里那些底层用 C/C++ 实现的库）。原因很直接：**Python 的解释器本身就是 C/C++ 写的**，所以纯 Python 不可能快过 C++。

> [!warning] 两种口径：理论上不用实际时间，实践中越来越用
> 课件的立场是"实际时间不可比"，这在理论分析上完全正确。但要知道当下的另一套口径：
> **在大数据与人工智能时代，实际时间反而被越来越频繁地使用**——论文和工程报告里常直接写"多少块 GPU、跑了多少小时"，因为这给出的是"我到底要花多少钱才能做成这件事"的直观感受。
> 转折点在于：理论曾断言让 AI 学会下棋（搜索空间指数级增长）几乎不可能，而深度强化学习用 1 块 GPU、6 个月就击败了最强人类棋手。**理论上表现好的，实际不一定表现好**，反之亦然。
> 本课的口径：**仍以严谨的数学分析为主**。

### 算法复杂度
**算法复杂度**是衡量算法运行效率和资源消耗的核心指标，它描述了当输入规模 **$n$** 增大时，算法所需的**时间**或**空间**增长的趋势。🚀

#### 1. 核心分类
算法复杂度主要分为两大维度：
* **时间复杂度 (Time Complexity)**：评估算法执行所需的时间随输入规模 $n$ 增长的变化趋势。它通常不计算绝对的运行时间（因为受硬件影响），而是估算**基本操作的执行次数**。⏱️
* **空间复杂度 (Space Complexity)**：评估算法在运行过程中临时占用存储空间随 $n$ 增长的变化趋势。它计算的是除了存储输入数据本身之外，算法运行所需的**额外辅助空间**。💾

#### 2. 渐进符号 (Asymptotic Notation)
为了描述增长率，数学上通常使用大O符号来表达最坏情况下的上界：
* **大O符号 ($O$)**：表示渐进**上界**，代表算法在最坏情况下的性能表现，也是工程中最常用的符号。例如 $T(n) = O(f(n))$。📉
* **大Omega符号 ($\Omega$)**：表示渐进**下界**，代表算法在最好情况下的性能。
* **大Theta符号 ($\Theta$)**：表示渐进**确界**，代表算法的上下界相同，精确描述了增长趋势。

#### 3. 常见的复杂度量级
从优到劣，常见的复杂度阶数排列如下：

| 复杂度 | 名称 | 常见场景/例子 |
| :--- | :--- | :--- |
| **$O(1)$** | 常数阶 | 数组根据索引直接访问元素、哈希表查找 ⚡ |
| **$O(\log n)$** | 对数阶 | 二分查找、平衡二叉树搜索 🌲 |
| **$O(n)$** | 线性阶 | 单层循环遍历未排序数组、简单查找 🚶 |
| **$O(n \log n)$** | 线性对数阶 | 高效排序算法（快速排序、归并排序、堆排序） 📦 |
| **$O(n^2)$** | 平方阶 | 双层嵌套循环（冒泡排序、选择排序、朴素矩阵乘法） 🔄 |
| **$O(2^n)$** | 指数阶 | 递归实现的斐波那契数列、子集生成问题 💥 |
| **$O(n!)$** | 阶乘阶 | 全排列生成问题、旅行商问题（TSP）的穷举解法 🧩 |

性能对比规律：
$$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)$$

#### 4. 复杂度分析的基本法则
在实际分析一段代码时，可以遵循以下规则快速推导：
1. **加法法则（顺序结构）**：总复杂度等于量级最大的那部分。例如 $O(n) + O(n^2)$ 最终等于 **$O(n^2)$**。
2. **乘法法则（嵌套结构）**：嵌套循环的复杂度等于内外层复杂度的乘积。外层循环执行 $n$ 次，内层执行 $n$ 次，则整体为 **$O(n^2)$**。
3. **忽略常数与低阶项**：例如 $3n^2 + 5n + 2$ 在渐进分析中，常数系数 $3$、低阶项 $5n$ 和常数 $2$ 都可以忽略，直接简化为 **$O(n^2)$**。因为当 $n$ 足够大时，最高次项起决定性作用。🎯
****
> [!important] 结论：真实运行时间不可比
> 运行时间同时取决于**机器、语言、编译器、输入数据、当时系统负载**，换一个条件结论就变。因此需要一个**与机器无关 (machine-independent)** 的度量。

> [!important] Asymptotic Analysis 渐进分析的三点要求（课件原文）
> Given an algorithm:
> - We need to be able to describe these values **mathematically**（能用数学方式描述）
> - We need a **systematic means** of using the description of the algorithm together with the properties of an associated data structure（有系统的方法，把算法描述与数据结构性质结合起来）
> - We need to do this in a **machine-independent way**（做到与机器无关）

> [!note] C++ 与 Python 差多少
> 同一个 $O(n^2)$ 算法，Python 可能比 C++ 慢 50–100 倍——但**慢的是常数因子，不是增长率**。而一个 $O(n\log n)$ 的 Python 实现，在 $n$ 足够大时一定会赢过 $O(n^2)$ 的 C++ 实现。这正是"只看增长率，不看常数"的合理性所在，也是深度学习框架"Python 前端 + C++ 后端"能成立的原因：前端只跑 $O(1)$ 次调度，真正 $O(n)$ 的计算在后端。

## 五、直观证据：线性查找 vs 二分查找

### 5.1 先看一次真实实测

课堂上用大模型（豆包）现场生成了两份代码来对照：**线性查找 linear search** 与**二分查找 binary search**，都统计"找到目标所需的比较次数 comparison count"。

- 线性查找：从第一个元素扫到最后一个；因为数组**已排序**，一旦当前值已经大于目标就可以提前停止并返回 $-1$。
- 二分查找：维护 `left`、`right` 两个边界，每次检查 `middle`；中间值等于目标就返回，小于目标则 `left = middle + 1`（目标在右半），大于目标则 `right = middle - 1`（目标在左半）。**每次砍掉一半的搜索范围。**

实测结果（数组容量 12、值域约为容量的 2 倍多）：

| 测试用例 | 线性查找比较次数 | 二分查找比较次数 |
| --- | --- | --- |
| 查找存在的值（下标 7） | **15** | **7** |
| 查找不存在的随机值 | **18** | **8** |

> [!note] 从这次实测能得出什么、不能得出什么
> **能**：在这个具体规模、这个具体数组上，二分查找明显更少比较。
> **不能**：这只是**一个 case**。如果不知道数组多大、要找的值是什么，怎么比较两个算法的优劣？
> 答案是：**要么穷举所有情况，要么改用数学描述所有情况下的趋势**——把"比较次数随规模增长"的曲线画出来。这就是渐进分析的出发点，也是本章第一次作业要你亲手做的事（见 [[C1.6 代码复杂度的计算方法]] 末尾）。

## 六、核心论证：只有最高次项要紧

### 6.1 二次的例子

考虑 $f(n)=n^2$ 与 $g(n)=n^2-3n+2$。

**在 $n=0$ 附近，二者看起来完全不同：**

![[C1-二次函数近处差异.png]]

**但在 $n\in[0,1000]$ 上，二者（相对而言）无法区分：**

![[C1-二次函数远处趋同.png]]

> [!important] 用数字说话（Quadratic Growth 页）
> 绝对差很大：
> $$f(1000)=1\,000\,000,\qquad g(1000)=997\,002$$
> 但相对差非常小：
> $$\left|\frac{f(1000)-g(1000)}{f(1000)}\right| = 0.002998 < 0.3\%$$
> 且当 $n\to\infty$ 时这个差趋于 0。

> [!important] 把这两个数字当成"秒"来体会
> 假设这两个函数就是两个算法在规模 1000 时要等的**秒数**：一个要等 **1 000 000 秒**，另一个要等 **997 002 秒**。
> 已经等了 99 万多秒了，你还在乎多等那两千多秒吗？——**从数学上看，这两个算法没有本质区别。**
> 反过来，在很小的规模（比如 $n=3$ 或 4）上，$g$ 确实更小、确实"更好"；但问题规模一旦放大，这点差别就被稀释掉了。**渐进分析关心的永远是规模变大以后的事。**

> [!note] 课件省略的验算（自己补上）
> $g(1000)=1000^2-3\times1000+2=1\,000\,000-3000+2=997\,002$。
> 差值 $=2998$，相对差 $=2998/1\,000\,000=0.002998$。
> 一般地：$\dfrac{|f-g|}{f}=\dfrac{3n-2}{n^2}\approx\dfrac{3}{n}\to 0$。**相对误差按 $1/n$ 衰减**，这就是"$n$ 越大越像"的定量原因。

### 6.3 得到的启示（Enlightenment）

> [!important] 课件结论
> 两对多项式之所以"像"，是因为它们**拥有相同的最高次项 (same leading term)**：第一对是 $n^2$，第二对是 $n^6$。
> 那如果**最高次项的系数不同**呢？
> —— In this case, both functions would exhibit the **same rate of growth**, however, **one would always be proportionally larger**.
> （增长率相同，只是其中一个恒定地按比例更大。）

> [!note] 这一步为什么关键
> 它把"函数相似"拆成了两层：
> 1. **最高次的次数相同** → 增长率 (rate of growth) 相同 → 属于同一个复杂度类；
> 2. **最高次的系数不同** → 只差一个常数倍 → 仍属同一类。
>
> 于是"忽略常数系数、忽略低次项"不再是拍脑袋的偷懒，而是有极限意义的等价划分。下面的 $f\sim g$ 定义就是把这句话写成数学。

> [!important] 系数不同意味着什么：可以用钱买回来
> 设 $f(n)=2n^2$，$g(n)=n^2$。先问哪个更好——**当然是 $g$，更小就更好**。但"更好"在现实中值多少钱？
> 你用一台主频 **1 GHz** 的电脑跑 $g(n)=n^2$，旁边的同学用一台主频 **2 GHz** 的电脑跑 $f(n)=2n^2$，**两人花的时间基本一样**。
> 结论：**只差常数倍的算法劣势，永远可以用常数倍的计算资源补回来**——而且与问题规模无关，他花 1 万块，你花 2 万块就够了。
> 这正是下一节"能不能干脆买台更快的电脑"的答案的前半段；后半段（$n^2$ 与 $n\log n$ 之间的差距买不回来）见第七、八节。

## 七、指令计数：插入排序 vs 快速排序

比较两个算法的通用做法是**数指令条数 (counting instructions)**——在查找的例子里数的是比较次数，一般情况下数的是执行的指令数。课件用三张图展示插入排序与快速排序在不同规模下的指令数对比。

> [!warning] 先说清楚哪条线是哪个算法（极易看反）
> 按名字猜"quick sort 更快、所以红线（下方那条）是快排"是**错的**。正确对应是：
> - **蓝线 = Quick sort 快速排序**
> - **红线 = Insertion sort 插入排序**
>
> 之所以在第一张图里蓝线（快排）反而在上方（指令更多），是因为**横轴范围极小，只到 5**——这时快排的常数开销 (overhead) 占了主导。

**小规模 $n=1..5$：蓝线（快排）在上方，此时插入排序反而更划算**

![[C1-插入排序与快排指令数-小n.png]]

**$n$ 到 20：两条线开始靠近**

![[C1-插入排序与快排指令数-n20.png]]

**$n$ 到 1000：红线（插入排序，$n^2$）急剧上升，蓝线（快排，$n\lg n$）几乎贴地**

![[C1-插入排序与快排指令数-n1000.png]]

> [!important] 课件的两段结论
> - Insertion sort 以 $n^2$ 的速率增长，quicksort 以 $n\lg n$ 增长。尽管如此，图形提示**排小数组时用插入排序更划算——快排的常数开销 (overhead) 很大**。
> - 当表长**大于约 20** 时，快排的额外开销迅速变得可忽略，快排显著更优。
> - 随后的提问："**can we just buy a faster computer?**"（我们能不能干脆买台更快的电脑？）

> [!important] 这次买电脑救不了
> 上一节说过，只差**常数倍**的劣势可以用更贵的机器补回来。但插入排序与快排的差距是 $n^2$ 与 $n\lg n$ 的差距，**两者之间的鸿沟随规模越拉越大，不是等比的**。
> 所以答案是：**不能**。无论问题规模多大都能靠买机器抹平的，只有同一等价类内部的差距。

> [!note] 这个"20"是工业界的真实做法（拓展）
> STL 的 `std::sort` 是 **introsort**：快排为主，**递归到小区间（典型阈值 16）时切换插入排序**，递归过深时切堆排。这正是课件这三张图的工程落地。
> "买台更快的电脑"的答案在下一节 Weak Ordering 里给出，而且是**否定**的——这是本节最有力的一句话。

## 八、弱序：把"增长得更快"定义出来

> [!important] 两个定义（Weak Ordering 页）
> - 称两个函数**等价**，记 $f \sim g$，若
> $$\lim_{n\to\infty}\frac{f(n)}{g(n)} = c,\qquad 0 < c < \infty$$
> - 称 $f < g$，若
> $$\lim_{n\to\infty}\frac{f(n)}{g(n)} = 0$$
>
> 对我们关心的函数而言，这两条定义构成一个**弱序 (weak ordering)**。

> [!note] 为什么正好是"弱序"而不是"线性序"
> 回看 [[C1.3 数据元素间的六种关系]]：**弱序 = 等价类之间的线性序**。这里 $\sim$ 把所有函数划成等价类（$n^2$、$3n^2$、$n^2+5n$ 同属一类），$<$ 在类与类之间排出先后（$\Theta(1) < \Theta(\log n) < \Theta(n) < \dots$）。
> **第 1.2 节讲的六种关系，在这里第一次被真正用上**——离散数学的关系理论被直接搬来给复杂度分类。这是本章前后呼应最漂亮的一处。

> [!important] "买更快的电脑"能不能解决问题（关键论断）
> - 若 $f(n) \sim g(n)$，那么**总可以通过买一台更快的机器**让其中一个函数的表现超过另一个。
> - 若 $f(n) < g(n)$，那么你 **never**（永远不可能）买到一台足够快的机器，使得第二个函数总是比第一个跑得快。
>
> 另注：对**小的 $n$**，使用一个渐进上更贵的算法可能是合理的，但这要**逐例判断** (on a one-by-one basis)。

> [!warning] "总可以买更快的机器"只是理论上的
> 严格说这句话成立的前提是"常数比例不大"。如果一个算法的系数前面顶着个 100 万，你要买的就不是贵一倍的电脑，而是贵 100 万倍的——现实中并不可行。**理论上等价，工程上仍可能天差地别。**

> [!important] 逐例判断有多重要：一个真实的反面案例
> 工作以后要按**实际情况**分析，而不是一上来就用理论上最好的算法。
> 一个真实例子：某研究做"全球数据中心之间的工作流调度"，论文论证问题规模随数据中心数量增长到不可接受，于是上了机器学习等高阶算法，文章做得很漂亮也发表了。但被追问一句：**全世界能承载这类任务的数据中心总共有多少个？** 把所有大公司的都算上，也就一二十个。按笔记本电脑的速度**把所有可行方案穷举一遍，只需要 10 分钟**。
> 教训：**不是问题在理论上被定义成什么类型，就一定要用对应的高级算法。** 先估算你真实面对的规模——比如全国就 14 亿人、流量上限就摆在那里——在这个范围内最好的算法才是你要的算法。

> [!note] **为什么"买机器"只能救常数**
> 机器快 $k$ 倍，相当于把运行时间整体除以 $k$——这只改变常数因子，也就是只在**同一个等价类内部**移动。而 $f<g$ 意味着比值趋于 0，任何有限的 $k$ 都补不上这个差距。**硬件解决常数，算法解决增长率**——这是全课最值钱的一句话。

## 九、五个 Landau 符号

> [!important] 定义表（课件原表）
> | 记号 | 极限条件 | 含义 |
> | --- | --- | --- |
> | $f(n)=\mathbf{o}(g(n))$ | $\displaystyle\lim_{n\to\infty}\frac{f(n)}{g(n)}=0$ | 严格小于（小 o） |
> | $f(n)=\mathbf{O}(g(n))$ | $\displaystyle\lim_{n\to\infty}\frac{f(n)}{g(n)}<\infty$ | 小于等于（大 O，**上界**） |
> | $f(n)=\mathbf{\Theta}(g(n))$ | $\displaystyle 0<\lim_{n\to\infty}\frac{f(n)}{g(n)}<\infty$ | 同阶（**确界**） |
> | $f(n)=\mathbf{\Omega}(g(n))$ | $\displaystyle\lim_{n\to\infty}\frac{f(n)}{g(n)}>0$ | 大于等于（**下界**） |
> | $f(n)=\mathbf{\omega}(g(n))$ | $\displaystyle\lim_{n\to\infty}\frac{f(n)}{g(n)}=\infty$ | 严格大于（小 ω） |

> [!important] 表里的 $f(n)$、$g(n)$ 到底指什么
> 它们分别是**两个算法在问题规模为 $n$ 时需要执行的指令条数**。$f$ 是一个算法，$g$ 是另一个算法，Landau 符号描述的就是"规模趋于无穷时，这两个指令数之比"。
>
> 使用频率：**大 $O$ 用得最多，其次是 $\Theta$；$o$、$\Omega$、$\omega$ 很少用。** 记不住定义时，不要背中文的"上界/上确界/下界/下确界"，而是回到表里那一列极限值（$0$、$<\infty$、$0<c<\infty$、$>0$、$=\infty$），从小 $o$ 顺到小 $\omega$ 排一遍，自然就知道哪个算法更差。

**图形总结（课件原图）：**

![[C1-Landau符号图形总结.png]]

> [!note] 这张彩条图的读法
> 横条按极限值分成三段：**0**（蓝）、**$0<c<\infty$**（黄）、**$\infty$**（红）。
> - $\mathbf{o}$ 只覆盖 0 这一段；
> - $\mathbf{O}$ 覆盖 0 和中段（绿条横跨左中）；
> - $\mathbf{\Theta}$ 只覆盖中段；
> - $\mathbf{\Omega}$ 覆盖中段和 $\infty$（橙条横跨中右）；
> - $\mathbf{\omega}$ 只覆盖 $\infty$。
>
> 一句话记忆：**o/ω 是"严格"，O/Ω 是"含等号"，Θ 是"正好卡住"**。

> [!important] 对偶关系（课件原文）
> $$f(n)=\Theta(g(n)) \iff g(n)=\Theta(f(n))$$
> $$f(n)=O(g(n)) \iff g(n)=\Omega(f(n))$$
> $$f(n)=o(g(n)) \iff g(n)=\omega(f(n))$$

> [!important] 大 $O$ 的实践含义：最坏情况
> **Big-$O$ 描述的是最坏情况 (the worst case)。** 如果有人让你分析"最坏情况下的时间复杂度"，那就是要你给出大 $O$。
>
> 由此引出一个很现实的问题：**假设你设计的算法复杂度是 $\Theta(n)$，你愿意对外说它是 $O(n)$ 吗？**
> 说 $O(n)$ 完全正确，而且更"好听"——它给人的印象是"最坏才要 $n$ 条指令，一般情况可能更少"；而事实上你的算法**每一次都要跑 $n$ 条**。所以多数人会选择说 $O(n)$。
> 但反过来，如果你的算法是 $\Theta(n^2)$，你会对外说它是 $O(n^3)$ 吗？**不会**——那虽然也"正确"，却是没有信息量的自贬。
> **结论：报告里普遍用 $O$，但心里要清楚真实的阶是 $\Theta$。**

> [!warning] 易错点：`=` 不是等号（拓展）
> $f=O(g)$ 中的等号是**历史遗留的滥用**，正确读法是"$f$ **属于** $O(g)$ 这个函数集合"。所以 **$O(g)=f$ 不能反着写**，$O(n)=O(n^2)$ 成立而 $O(n^2)=O(n)$ 不成立。

### 9.1 Θ 的另一种（更常用的）定义

> [!important] 课件给出的 ε–N 式定义
> A function $f(n)=\Theta(g(n))$ if there exist positive $N$, $c_1$, and $c_2$ such that
> $$c_1\,g(n) < f(n) < c_2\,g(n) \quad \text{whenever } n>N$$

**证明（课件完整给出，务必看懂）**：设 $f,g$ 满足 $\displaystyle\lim_{n\to\infty}\frac{f(n)}{g(n)}=c$。由极限定义，给定 $c>\varepsilon>0$，存在 $N>0$ 使得当 $n>N$ 时
$$\left|\frac{f(n)}{g(n)}-c\right|<\varepsilon$$
即
$$c-\varepsilon<\frac{f(n)}{g(n)}<c+\varepsilon$$
两边同乘 $g(n)>0$：
$$g(n)(c-\varepsilon) < f(n) < g(n)(c+\varepsilon)$$

> [!note] 补上课件没写的最后一步（拓展）
> 课堂上对这几行只说了一句"就是把定义用更严谨的数学方式重写了一遍，记不住也没关系"，下面是补全的推导。
> 取 $c_1=c-\varepsilon>0$、$c_2=c+\varepsilon$，就得到了 $\Theta$ 的 ε–N 定义。
> 这段推导说明：**极限定义与夹逼定义是等价的**（前者要求极限存在，后者更宽松，能处理振荡的函数，所以教材通常用后者）。要求 $\varepsilon<c$ 是为了保证 $c_1>0$——这一步课件没点破，是理解的关键。

## 十、Big-Θ 是一个等价关系

> [!important] 三条性质（正好是等价关系的三条）
> 1. $f(n)=\Theta(g(n))$ **if and only if** $g(n)=\Theta(f(n))$ —— **对称性**
> 2. $f(n)=\Theta(f(n))$ —— **自反性**
> 3. If $f(n)=\Theta(g(n))$ and $g(n)=\Theta(h(n))$, then $f(n)=\Theta(h(n))$ —— **传递性**
>
> 因此可以把所有函数划分成**等价类 (equivalence classes)**，同一类中的函数彼此互为 $\Theta$。

课件给的同类样例（全部同属 $\Theta(n^2)$）：

$$n^2,\quad 100000n^2-4n+19,\quad n^2+1000000$$
$$323n^2-4n\ln(n)+43n+10,\quad 42n^2+32$$
$$n^2+61n\ln^2(n)+7n+14\ln^3(n)+\ln(n)$$

例如：$42n^2+32=\Theta(323n^2-4n\ln(n)+43n+10)$。

> [!important] 课堂提问与答案
> "Thus, we would like to pick **only one element to represent the entire class**. Which one do you prefer?"
> —— 当然是**最简单的那个：$n^2$**。这就是为什么我们写 $\Theta(n^2)$ 而不是 $\Theta(42n^2+32)$。**代表元的选择原则：去掉所有常数系数和低次项。**

> [!note] 与 1.2 节的呼应
> 这里第二次用到 [[C1.3 数据元素间的六种关系]]：**等价关系用来分类，弱序用来在类之间排序**。整个复杂度理论 = 等价关系 + 弱序。绪论里铺垫的关系理论在这里被完整兑现。

### 常见复杂度类的命名（必背）

> [!important] The most common classes are given names
> | 类 | 名称 | 典型算法 |
> | --- | --- | --- |
> | $\Theta(1)$ | constant 常数 | 数组随机存取、栈的进出 |
> | $\Theta(\ln n)$ | logarithmic 对数 | 二分查找 |
> | $\Theta(n)$ | linear 线性 | 顺序查找、遍历 |
> | $\Theta(n\ln n)$ | "n log n" | 归并/快排/堆排 |
> | $\Theta(n^2)$ | quadratic 二次 | 选择/插入/冒泡排序 |
> | $\Theta(n^3)$ | cubic 三次 | 朴素矩阵乘法、Floyd |
> | $2^n,\ e^n,\ 4^n,\ \dots$ | exponential 指数 | 子集枚举、朴素 TSP |
>
> 其中 $\Theta(n)$ 到 $\Theta(n^3)$ 这一段统称**多项式 polynomial**。

> [!important] 多项式与指数之间是「可计算 / 不可计算」的分界线
> 在**计算复杂性理论**里，以多项式为门槛：
> - 复杂度在**多项式及以下**（$n$、$n\log n$、$n^2$、$n^3$…）→ 认为该问题是**可计算的**；
> - 复杂度到了**指数级**（$2^n$、$k^n$）→ 认为该问题是**不可计算的**（规模稍大就永远算不完）。
>
> **最贴身的例子就是你的开机密码。** 在没有任何先验信息时，破解只能穷举：先试所有 1 位的组合，再固定第 1 位遍历第 2 位……若密码长 $n$ 位、键盘有 $k$ 个键，复杂度是 $k^n$，**指数级，所以你的密码才是安全的**。
> 反过来说：**哪一天有人发明出一个多项式时间就能猜出密码的算法，整套密码系统当天就失效了。**

> [!note] 顺带一提：P vs NP（拓展）
> 千禧年七大数学难题之一（每题悬赏 100 万美元）就是 **P 是否等于 NP**。
> - **P** = **P**olynomial，多项式时间可解的问题；
> - **NP** = **N**on-deterministic **P**olynomial，非确定性多项式——可以粗略地（并不严格地）理解成"指数级以上的那类难题"。
>
> 问的是：是否存在多项式算法能把这些指数级难题全部解决掉？至今**既没有被证明，也没有被证否**；直觉上大多数人认为 P ≠ NP。证明或证否任何一个方向都可以拿到那 100 万美元。

> [!warning] 为什么写 $\ln n$ 而不区分底数
> $\log_a n=\dfrac{\ln n}{\ln a}$，换底只差一个常数因子，而常数因子在 $\Theta$ 下被忽略，因此 **$\Theta(\log_2 n)=\Theta(\ln n)=\Theta(\lg n)$，底数无所谓**。但注意：**指数的底数不能忽略**，$2^n$ 和 $4^n$ 不同阶（$4^n/2^n=2^n\to\infty$）。这一条几乎年年考。

> [!note] 排序算法的复杂度（课件在 1.6 节顺带给出，先记住）
> - 选择排序 Selection sort：$\Theta(n^2)$ 时间
> - 归并、快排、堆排：$\Theta(n\ln n)$ 时间
> - 额外空间：归并 $\Theta(n)$、快排 $\Theta(\ln n)$（递归栈）、堆排 $\Theta(1)$

## 本节自测 Self-Test

> [!question] Q1：算法五大特性是什么？"输入至少一个"对吗？
> **A**：有穷性、输入、输出、确定性、可行性。错——输入可以为 0 个，**输出**至少一个。

> [!question] Q2：为什么不能用实际运行秒数比较两个算法？
> **A**：秒数依赖机器、语言、编译器、输入和负载，不可比；需要与机器无关的增长率度量。

> [!question] Q3：$n^2$ 与 $n^2-3n+2$ 在 $n=1000$ 处的相对差是多少？说明什么？
> **A**：约 0.2998% < 0.3%，且随 $n$ 按 $3/n$ 趋于 0，说明低次项在大 $n$ 时可忽略。

> [!question] Q4：若 $f<g$（即 $\lim f/g=0$），买一台快 1000 倍的机器能让 g 算法总是赢吗？
> **A**：不能。更快的机器只改变常数因子，无法改变增长率；$n$ 足够大时 f 一定赢。

> [!question] Q5：写出 $\Theta$ 的 ε–N 定义，并说明为什么要求 $\varepsilon<c$。
> **A**：存在 $N,c_1,c_2>0$ 使 $n>N$ 时 $c_1g(n)<f(n)<c_2g(n)$。要求 $\varepsilon<c$ 是为了让 $c_1=c-\varepsilon$ 保持为正。

> [!question] Q6：$\Theta(\log_2 n)$ 与 $\Theta(\ln n)$ 是否同阶？$\Theta(2^n)$ 与 $\Theta(4^n)$ 呢？
> **A**：对数同阶（换底只差常数）；指数**不**同阶（$4^n/2^n\to\infty$）。

> [!question] Q7：为什么 STL 的 sort 在小区间上改用插入排序？（拓展）
> **A**：快排常数开销大，小规模（约 n<20）时 $n^2$ 的插入排序实际更快；这是常数因子占主导的区间。

> [!question] Q8：$f=2n^2$ 与 $g=n^2$ 的差距能靠换电脑抹平吗？$n^2$ 与 $n\lg n$ 呢？
> **A**：前者能——主频翻倍即可，且与规模无关；后者不能，两者差距随规模越拉越大。

> [!question] Q9：大 $O$ 在实践中代表什么情况？若你的算法是 $\Theta(n)$，对外该怎么说？
> **A**：代表最坏情况。对外说 $O(n)$ 正确且常见，但要清楚它每次都跑满 $n$；说成 $O(n^3)$ 则是没有信息量的自贬。

> [!question] Q10：为什么说密码系统的安全性建立在"指数级不可计算"上？
> **A**：暴力破解 $n$ 位密码的复杂度是 $k^n$（$k$ 为字符集大小），指数级增长使其在实践中无法完成；若出现多项式时间的破解算法，密码系统即失效。

> [!question] Q11：算法的四种描述方式按精确度如何排序？为什么自然语言最差？
> **A**：自然语言 < 流程图/伪代码 < 程序设计语言。自然语言有歧义（如菜谱的"盐少许"），违反算法的确定性。
