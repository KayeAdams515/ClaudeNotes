## 4. 概念必须被"逼出来"

每个新概念按这个链条推进，**不许跳步**：

**提出问题 → 让读者先猜（`> [!question] 停一下，先自己想想`）→ 给出朴素尝试 → 撞墙
→ 引出概念 → 正式定义（`> [!important]`）→ 手算验证（`> [!example]`）→ 回头看我们刚才干了什么**

- **"撞墙"是重点**：朴素做法为什么不行，要讲透。读者看懂失败比记住结论更重要，考试也常考这些"为什么"。
- 每讲完一大块，用一段"停一下，我们刚才干了什么"把它放回全局。
- 暂时解释不了的细节，**明说"先记着，第 X 节专门解释"**，然后**一定要回收**。
- 每篇末尾的「下一讲预告」用一句悬念收尾，让 6 篇连起来读成一条线。

## 7. 配图

### 7.1 总原则

- **图的作用是替掉你本来要用手比划的那一段话。** 一段叙述出现「这边高那边低」「绕一圈回到前面」
  「落在这一块里」「差一个相位」这类空间描述，就该配图；一段文字已经能独立讲清，就别配。
- **图的多少跟着知识点走，不跟着小节数走。** 有的小节配三张还嫌不够，有的一张贴上去都多余。
- 判断取图方式只问一句：**这张图里的信息，你能不能无损地用坐标和文字重述？**
  - 能（规律、对比、走向、结构）→ **自绘**（比原图清楚）。
  - 不能（照片、真实器件、复杂排版、多子图）→ **从 PDF 裁**。
  - 纯数据对照、多方案比较 → **用 Markdown 表格**，不用图。

### 7.2 自绘

- 流程/结构/分支 → **mermaid**（节点标签一律用双引号包裹，数学符号用 Unicode 如 `⌈N/k⌉ ⟹`，
  **mermaid 里不要写 `$...$`**）。
- 坐标、曲线、三角形、星条、树 → **Python + matplotlib**。
  - **标签一律用英文**（中文会变方框）；`import matplotlib; matplotlib.use("Agg")`。
  - 运行前设 `MPLCONFIGDIR` 到可写目录：`MPLCONFIGDIR=/tmp/mpl_c6 python3 x.py`。
  - `--dpi 150` 以上，白底，字号够大（笔记里会被缩到 ~600px 宽）。
- 画之前先把「这张图要说明的那句话」写下来，画完对着念一遍，念不通就是画错了。

### 7.3 从 PDF 裁


有没有带进页码/页眉/邻页内容、缩到笔记宽度后字还看不看得清（不够就加 `--scale`）。
