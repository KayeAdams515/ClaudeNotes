# C8.4 归并排序

> [!abstract] 这一讲的任务
> 上一讲用"换结构"（堆）把 $\Theta(n^2)$ 压到 $\Theta(n\ln n)$，代价是常数大。这一讲换一条路：**换分法**——把表劈成两半，各自排好，再把两个有序段并起来。
> 核心只有一个小问题：**两段有序的表，怎么用最少的比较并成一段？** 三根指针，$\Theta(n_1+n_2)$。把这件事递归地套下去，就得到第一个真正意义上的**分治**算法：$\Theta(n\ln n)$，而且**稳定**。代价是它不是原地的——并的时候要一块和原数组一样大的缓冲区。

## 先切开，再合并

递归定义只有三行：

> [!important] 归并排序 Merge Sort
> - 表长为 1：已经有序，什么都不用做；
> - 否则：把表**分成两半**，两半各自递归排序，再把两个有序段**合并**成一个有序段。

这是这门课第一个真正重要的分治算法。分治的公式永远是三步：**分、治、合**。分和治都很平凡——切成两半、递归调用；整节课的重量全在"合"上：

> **问：两段已经排好的表，最快多久能并成一段？**

### 合并两个有序段

#### 三指针

![[C8-归并-三指针初始状态.png]]

两段各有一个指针指向当前待处理的元素，输出数组再有一个写指针：

```cpp
int i1 = 0, i2 = 0, k = 0;
```

每一步比较 `array1[i1]` 和 `array2[i2]`，把小的那个搬到输出，对应指针右移。

![[C8-归并-比较后搬走一个数.png]]

用 `3 5 18 21 24` 和 `2 7 12 16 33` 走一遍：

| 步 | 比较 | 搬走 | 输出 |
| --- | --- | --- | --- |
| 1 | 3 vs 2 | 2 | `2` |
| 2 | 3 vs 7 | 3 | `2 3` |
| 3 | 5 vs 7 | 5 | `2 3 5` |
| 4 | 18 vs 7 | 7 | `2 3 5 7` |
| 5 | 18 vs 12 | 12 | `2 3 5 7 12` |
| 6 | 18 vs 16 | 16 | `2 3 5 7 12 16` |
| 7 | 18 vs 33 | 18 | `… 18` |
| 8 | 21 vs 33 | 21 | `… 21` |
| 9 | 24 vs 33 | 24 | `… 24` |

**9 次比较，10 个元素**——每一趟至少搬走一个元素，所以比较次数不会超过 $n_1+n_2-1$。

#### 代码

```cpp
int i1 = 0, i2 = 0, k = 0;
while ( i1 < n1 && i2 < n2 ) {
    if ( array1[i1] < array2[i2] ) {
        arrayout[k] = array1[i1];
        ++i1;
    } else {
        arrayout[k] = array2[i2];
        ++i2;
    }
    ++k;
}
```

![[C8-归并-收尾与剩余直接复制.png]]

一段先走完，另一段剩下的直接抄过去：

```cpp
for ( ; i1 < n1; ++i1, ++k ) {
    arrayout[k] = array1[i1];
}
for ( ; i2 < n2; ++i2, ++k ) {
    arrayout[k] = array2[i2];
}
```

两个细节：

- **收尾不用比较**。剩下的那一段本身有序，原样接上就是有序的。
- **`<` 还是 `<=` 决定稳定性**。写成 `<`，相等时取右段，右段的相等元素排到前面——**不稳定**。要稳定必须写 `<=`（相等时取左段，左段原本就在前面）。

#### 代价与它的另一面

合并的循环体最多执行 $n_1+n_2$ 次，每次常数时间：

$$T_{\text{merge}}(n_1,n_2)=\Theta(n_1+n_2).$$

两段等长时就是 $\Theta(n)$。

但这一页还有一句更重要的话：

> [!warning] 归并不是原地的
> 合并必须**另开一个 $n_1+n_2$ 的数组**，不能在两段的原地完成。所以归并排序的额外空间是 $\Theta(n)$——这一点到代价一节会和堆排序正面比较。

"能不能原地归并？"有论文，但实现复杂、常数极大，本课程不要求。记住结论：**归并排序是 $\Theta(n)$ 额外空间的算法**。

### 递归算法：理论上分到 1，实践上分到 6

把合并套进递归，算法三行：

- 把表分成两半；
- 两半各自归并排序；
- 合并。

**理论上的基本情形**是长度 1：长度 1 天然有序，直接返回。

**实践上的基本情形**是"小于某个阈值"：

> [!important] 小段用插入排序
> 当子段长度不超过阈值 $N$ 时，**改用插入排序**，不再递归。

为什么？因为渐近性质好不代表每一层都划算。递归有函数调用的开销，而插入排序在小规模上常数极小——$N=6$ 时，排 6 个数最多 15 次比较，比递归切到 1 再合并上去便宜得多。

材料没有解释 $N$ 为什么取 6（这是实验值，不同机器上 8、16 也常见）。**记住这个事实，不要当作定理。**

### 实现

先约定合并函数的接口：

```cpp
template <typename Type>
void merge( Type *array, int a, int b, int c );
```

它假设 `array[a..b-1]` 和 `array[b..c-1]` 两段已经有序，把它们并成 `array[a..c-1]` 一段有序。

排序函数：

```cpp
template <typename Type>
void merge_sort( Type *array, int first, int last ) {
    if ( last - first <= N ) {
        insertion_sort( array, first, last );
    } else {
        int midpoint = (first + last) / 2;
        merge_sort( array, first, midpoint );
        merge_sort( array, midpoint, last );
        merge( array, first, midpoint, last );
    }
}
```

注意区间是**左闭右开**：`merge_sort(first, last)` 排的是 `[first, last)`，所以 `midpoint` 同时是左半的右端点和右半的左端点，两边都不重不漏。

小段用的插入排序也要能排子区间：

```cpp
template <typename Type>
void insertion_sort( Type *array, int first, int last ) {
    for ( int k = first + 1; k < last; ++k ) {
        Type tmp = array[k];
        for ( int j = k; j > first; --j ) {        // 原稿此处为 k > first
            if ( array[j - 1] > tmp ) {
                array[j] = array[j - 1];
            } else {
                array[j] = tmp;
                break;
            }
        }
        if ( array[first] > tmp ) {                // 原稿此处为 temp
            array[first] = tmp;
        }
    }
}
```

> [!warning] 这两行原稿印错了
> 内层循环写成 `for ( int j = k; k > first; --j )`：判断条件用的是**不会变的 `k`**，循环永远不退出，`j` 一路减到负数，越界读。必须写 `j > first`。
> 下面那个 `if` 写的是 `if ( temp < array[first] )`，可是 `temp` 根本没声明（上面声明的是 `tmp`）——编译不过。
> 两处都是**原始笔误**，改完才是能跑的代码。

### 一个 25 元的完整例子

![[C8-归并-二十五元数组与阈值六.png]]

`13 77 49 35 61 48 73 23 95 3 89 37 57 99 17 32 94 28 15 55 7 51 88 97 62`

$n=25$，阈值 $N=6$。调用过程：

![[C8-归并-当前区间与基本情形判断.png]]

- `merge_sort(0,25)`：$25>6$，中点 12 → `(0,12)` 与 `(12,25)`；
- `merge_sort(0,12)`：$12>6$，中点 6 → `(0,6)` 与 `(6,12)`；
- `merge_sort(0,6)`：$6\le6$，**插入排序**；
- `merge_sort(6,12)`：$6\le6$，**插入排序**；
- 回到 `(0,12)`：`merge(0,6,12)`；
- `merge_sort(12,25)`：$13>6$，中点 18 → `(12,18)` 与 `(18,25)`；
- `merge_sort(12,18)`：$6\le6$，**插入排序**；
- `merge_sort(18,25)`：$7>6$，中点 21 → `(18,21)` 与 `(21,25)`；
- `(18,21)`、`(21,25)` 各 $3\le6$、$4\le6$，**插入排序**；
- 回到 `(18,25)`：`merge(18,21,25)`；回到 `(12,25)`：`merge(12,18,25)`；回到根：`merge(0,12,25)`。

### 代价：递推式

![[C8-归并-运行时间的递归式.png]]

$$T(n)=\begin{cases}\Theta(1), & n=1\\ 2T(n/2)+\Theta(n), & n>1\end{cases}$$

三步的代价分别是：排左半 $T(n/2)$、排右半 $T(n/2)$、合并 $\Theta(n)$。

![[C8-归并-Maple解递归式.png]]

解出来是

$$T(n)=n+n\lg n=\Theta(n\ln n).$$

不靠工具也能展开：假设 $n=2^k$，逐层把式子代进去，

$$\begin{aligned}
T(n)&=2T(n/2)+n\\
&=2\bigl(2T(n/4)+n/2\bigr)+n=4T(n/4)+2n\\
&=\cdots=2^kT(1)+kn=n+n\lg n.
\end{aligned}$$

每一层都是 $n$ 的代价，一共 $\lg n+1$ 层。

| 情况 | 运行时间 | 说明 |
| --- | --- | --- |
| 最坏 | $\Theta(n\ln n)$ | 与最好没有区别 |
| 平均 | $\Theta(n\ln n)$ | |
| 最好 | $\Theta(n\ln n)$ | 同上 |

"没有最坏情况"在这里的意思是**最好与最坏没有区别**：不管数据怎么分布，归并排序都是"切到底、并上来"，代价恒定。这一点和堆排序一样，和快排相反。

### 为什么一次比较能消掉很多逆序

到目前为止，$\Theta(n^2)$ 的算法每次比较只消掉一个逆序。归并凭什么不是？

看合并时的一个具体动作：右段的 2 和左段的 3 比了一次，2 就被搬走了。**2 从来没有和左段的 5、18、21、24 比过**——但它一定比它们都小，因为左段是有序的。一次比较，排除了四个。

> [!important] 这是归并快的根本原因
> 合并时，一次比较不仅决定了"谁先出去"，还**顺带否定了另一段里整段元素的相对次序**。所以总比较次数是 $n\ln n$，不是 $n^2$。

材料在这里有一处表述不准确：它写"一次比较消掉 $n$ 个逆序"，实际消掉的是**另一段当前剩余的元素个数**（例子里是 5 个，不是 24 个）。见篇末勘误。

### 三个 $\Theta(n\ln n)$ 的取舍

材料在这段末尾给了三句评论：

- **实际速度**：归并通常比堆排序快，尽管两者渐近相同——堆的下标跳、缓存不友好（见 C8.3 的短板）。
- **内存**：归并要 $\Theta(n)$ 的额外数组，堆是 $\Theta(1)$。
- **下一讲**：快排平均比两者都快，额外内存 $\Theta(\ln n)$。

这三句把三个 $\Theta(n\ln n)$ 算法的取舍摆清楚了：**要稳定选归并，要省内存选堆，要平均最快选快排**。

![[C8-归并-vonNeumann与ENIAC首次实现.png]]

最后一个彩蛋：归并排序很可能是 **1945 年由 John von Neumann 在 ENIAC 上实现的**——就是那个提出"冯·诺依曼架构"的人。分治不是新技巧，它和计算机同龄。

## 速查

| 量 | 值 | 备注 |
| --- | --- | --- |
| 合并两段 | $\Theta(n_1+n_2)$ | 比较次数 $\le n_1+n_2-1$ |
| 归并排序 | $\Theta(n\ln n)$ | 最好 = 最坏 = 平均 |
| 额外空间 | $\Theta(n)$ | 合并必须另开数组 |
| 稳定性 | 稳定 | 判据写 `<=` |
| 递推式 | $T(n)=2T(n/2)+\Theta(n)$ | 解为 $n+n\lg n$ |
| 小段阈值 | 本课程取 $N=6$ | 小于等于 6 用插入排序 |

## 下一讲

归并的划分是**按位置**切的（一刀两半）。下一讲把划分改成**按值**切：选一个基准，把比它小的放左边、比它大的放右边，再递归两边——这就是快速排序。平均 $\Theta(n\ln n)$、原地（只花 $\Theta(\ln n)$ 的栈），但最坏会退化成 $\Theta(n^2)$。
