# C5.3 异常检测 vs 监督学习与特征选择

> [!abstract] 本讲任务
> 两组问题。第一组是**选路**：[[C5.2 异常检测算法与系统评估]] 里为了评估已经借了一批带标签的数据，那为什么不干脆训练一个分类器？什么时候该用异常检测，什么时候该用监督学习？
>
> 第二组是**选料**：算法第 1 步“选特征”一直被跳过了。特征不服从高斯分布怎么办？算法漏掉了一个异常，下一步该干什么？怎么造出原始数据里没有的新特征？

---

## 1. 异常检测还是监督学习

### 1.1 两个任务

先看两个任务。

**任务 A**：飞机引擎质检，10000 台正常、20 台有缺陷。
**任务 B**：垃圾邮件分类，10 万封正常邮件、10 万封垃圾邮件。

你会分别用哪种方法？判断依据是什么？

### 1.2 对照

把两种方法适用的情形并排放：

| | 异常检测 | 监督学习 |
|---|---|---|
| 正例（$y=1$）数量 | **极少**，0 到 20 个很常见 | 正例、负例**都很多** |
| 负例（$y=0$）数量 | 极多 | —— |
| 正例的样子 | **异常有很多种类型**。从这么少的正例里，算法很难学出“异常长什么样”；**未来的异常可能和见过的任何一个都不像** | 正例足够多，算法能学出“正例长什么样”；**未来的正例大概率和训练集里的相似** |

![[C5.3-板书-异常检测vs监督学习.png]]

左栏负例多，正好用来建 $p(x)$——这就是异常检测做的事。右栏的典型代表是垃圾邮件。

### 1.3 真正的判据

表里的几行并不是平等的。**正例数量少只是表象，根本原因是“异常的种类多到学不完”。** 所以判据可以浓缩成一句话：

> **未来的正例，会不会长得像我见过的正例？**

会，就用监督学习——算法可以从正例里学出规律，推广到未来。不会，就用异常检测——正例没有规律可学，只能反过来学“正常长什么样”，凡是不像正常的都报出来。

用这把尺子量一下。**垃圾邮件**的套路是有限的：中奖通知、钓鱼链接、卖药广告……明天收到的垃圾邮件和今天的大同小异，用监督学习。**飞机引擎**可能因为裂纹坏、因为轴承坏、因为材料杂质坏，也可能因为一个从没出现过的原因坏；你见过的 20 种坏法，完全代表不了第 21 种，用异常检测。

注意这个判断**和数据量无关**：就算你有 10 万台坏引擎，只要下一台的坏法可能是全新的，异常检测依然更稳妥。

### 1.4 两边的典型任务

| 异常检测 | 监督学习 |
|---|---|
| 欺诈检测 | 垃圾邮件分类 |
| 制造业质检（如飞机引擎） | 天气预报（晴 / 雨 / ……） |
| 机房机器监控 | 癌症分类 |

![[C5.3-板书-两类任务的例子.png]]

这两栏不是固定不变的。以**欺诈检测**为例：一家刚起步的公司，抓到的欺诈账号可能只有几十个，骗子的花样天天翻新，只能用异常检测；可等公司做大，每天能抓到成千上万个欺诈样本，主流手法也摸清了，这时就该**转成监督学习**——正例已经多到能学出规律了。所以同一个业务，在不同阶段可能属于不同的一侧。

那**癌症分类**为什么在监督学习一侧？乍看它也很偏斜：健康人远多于患者。关键在于，**同一种癌症的影像和指标是有共性的**，未来的患者和训练集里的患者相似，符合“正例可学”的条件。反过来，如果任务是“检查这份体检报告里有没有**任何**说不清的毛病”，那就成了异常检测。任务怎么表述，决定了它属于哪一边。

## 2. 特征不是钟形怎么办

### 2.1 先画直方图

我们的模型假设每个特征都服从高斯分布，$x_j\sim\mathcal{N}(\mu_j,\sigma_j^2)$。可真实的特征经常**根本不是钟形**。响应时间、交易金额、文件大小这类量，往往是**右偏的长尾分布**：大部分值很小，少数极大，直方图的峰挤在左边，尾巴拖向右边。

所以上手第一件事：**对每个特征画一张直方图**（比如 `hist(x)`）。长什么样一目了然，比任何统计检验都快。

### 2.2 用变换把它掰成钟形

如果不是钟形，就对特征做一个**单调变换**，把长尾压回去。常用的有：

$$x_1\leftarrow\log(x_1)$$
$$x_2\leftarrow\log(x_2+1)\qquad\text{或更一般地}\qquad x_2\leftarrow\log(x_2+c)$$
$$x_3\leftarrow\sqrt{x_3}=x_3^{1/2}$$
$$x_4\leftarrow x_4^{1/3}$$

比如一个右偏得很厉害的特征，取 $\log$ 之后，直方图就变成了一个相当漂亮的钟形。

![[C5.3-板书-非高斯特征的变换.png]]

为什么这些变换有效？$\log$、$\sqrt{\ }$、$x^{1/3}$ 都是**凹函数**：大数被压得多，小数被压得少，右边的长尾巴就被拉了回来，分布向对称靠拢。压缩力度从强到弱是

$$\log(x)\;>\;x^{1/3}\;>\;x^{1/2}\;>\;x$$

右偏越厉害，就用压缩力越强的变换。

$\log(x+c)$ 里的 $c$ 是干什么的？$\log0=-\infty$，如果特征可能取 0（比如“出错次数”），直接取对数就会出问题。加一个小常数就避开了；$c=1$ 最常见，因为 $\log1=0$。$c$ 也可以当超参数来调：试几个值，看哪个让直方图最像钟形。指数 $\frac12$、$\frac13$ 也是一样，都可以调。

有一条纪律：**训练时对某个特征做了什么变换，预测时对新样本就要做同样的变换**。训练时对 $x_3$ 开了根号，新样本的 $x_3$ 也要开根号，否则估出来的 $\mu_3,\sigma_3^2$ 完全对不上。这和 [[C2.3 多变量线性回归与梯度下降实践]] 里特征缩放的纪律一样。

不做变换会怎样？算法不会立刻崩——$\mu$、$\sigma^2$ 照样能算，$p(x)$ 照样能给出一个数。但后果是：右偏分布的长尾上本来就有很多正常样本，高斯模型却认为那里“不该有人”，给它们极小的 $p(x)$，于是**大量正常样本被误报**，精确率崩盘。

## 3. 算法漏掉了异常怎么办

### 3.1 最常见的问题

我们希望的是：正常样本的 $p(x)$ 大，异常样本的 $p(x)$ 小。最常见的失败是：**异常样本的 $p(x)$ 和正常样本差不多大**（比如都很大）。这时不管 $\varepsilon$ 怎么调都分不开——调小了漏报，调大了误报满天飞。

### 3.2 误差分析

应对办法是**误差分析**，和 [[C6.1 系统设计的起点：垃圾邮件分类与误差分析]] 讲的是同一个思路：

1. 在交叉验证集上跑一遍，找出**被漏掉的异常样本**（$y=1$ 但 $p(x)\ge\varepsilon$）；
2. **一个一个地人工看**：这台机器、这个账号到底哪里不对劲？
3. 问：**现有的特征里，有没有哪一个能把这份“不对劲”表达出来？** 没有的话，就**造一个新特征**；
4. 加上新特征重新跑，看 $F_1$ 有没有涨。

### 3.3 为什么常常是特征不够

看一个例子。只用一个特征 $x_1$ 时，数据在一条数轴上排开，拟合出一条高斯曲线；有一个异常样本恰好**落在数据最密集的地方**——在 $x_1$ 这一维上看，它完全正常，$p(x_1)$ 很大，算法抓不到它。

现在加上第二个特征 $x_2$，把数据画在二维平面上。同一个样本，在新加的 $x_2$ 方向上远离所有正常样本，**一下子跳到了所有等高线之外**，$p(x_1,x_2)$ 变得极小——抓到了。

![[C5.3-板书-误差分析.png]]

教训是：**漏报不一定是算法不好，很可能是特征不够。** 同一个异常，在一维里藏得住，在二维里就藏不住。误差分析的结果往往不是“换个模型”，而是“再加一个特征”。

## 4. 造出新特征

### 4.1 选特征的原则

以机房监控为例，原始特征是：

$$x_1=\text{内存占用},\quad x_2=\text{每秒磁盘访问次数},\quad x_3=\text{CPU 负载},\quad x_4=\text{网络流量}$$

选特征的总原则是：**选那些出事时会变得异常大或异常小的量。** 一个在正常和异常时都差不多的量（比如机器的序列号、机架编号），加进去只会稀释信号。

### 4.2 组合特征

设想一台机器陷入了**死循环**：CPU 满载，但因为卡在本地计算上，**网络流量几乎为零**。

单看 CPU 负载：满载很高，但机房里本来就有跑满载的计算任务，不稀奇。单看网络流量：接近 0 也不稀奇，很多机器本来就闲着。$p(x_3)$ 和 $p(x_4)$ 都不小，乘起来 $p(x)$ 也不小——**这台死循环的机器逃掉了**。

办法是造一个新特征，把 CPU 和网络的**关系**表达出来：

$$x_5=\frac{\text{CPU 负载}}{\text{网络流量}}$$

正常机器上，CPU 忙的时候网络一般也忙，这个比值在一个平常的范围里。死循环时分子大、分母接近 0，$x_5$ 变得**异常大**，远超正常范围——$p(x_5)$ 极小，连乘之后 $p(x)$ 塌下去，抓到了。

还可以更进一步：

$$x_6=\frac{(\text{CPU 负载})^2}{\text{网络流量}}$$

分子平方之后，对 CPU 负载更敏感：CPU 从 50% 升到 100%，$x_5$ 翻一倍，$x_6$ 翻四倍。**希望哪个量的偏离被放大，就给它加个指数。**

![[C5.3-板书-机房监控的组合特征.png]]

组合特征的本质是什么？[[C5.2 异常检测算法与系统评估]] 说过，独立性假设让模型**看不见特征之间的关系**。$x_5=\frac{x_3}{x_4}$ 正是**手工把这个关系塞进一个新的单变量里**：原本要看“$x_3$ 和 $x_4$ 的联合行为”才能发现的异常，变成了“$x_5$ 单独的极端值”——而单变量的极端值，恰恰是这个模型最擅长抓的东西。

这条路走得通，但每一个组合都得**靠人的领域知识想出来**。有没有办法让算法自动发现特征之间的关系？有，那就是下一讲的多元高斯分布。

> [!tip] 常见的组合方式（拓展）
> - **比值** $\frac ab$：抓“本该同步变化的两个量脱钩了”；
> - **差值** $a-b$：抓“本该相等的两个量对不上”，比如收到的包数和发出的包数；
> - **加权比** $\frac{a^k}{b}$：想放大 $a$ 的偏离就调大 $k$；
> - **变化率** $\frac{\Delta a}{\Delta t}$：抓“变化太快”。
>
> 做比值要防分母为零，常用 $\frac{a}{b+c}$，和 $\log(x+c)$ 里的 $c$ 是同一招。

## 5. 小结

这一讲没有新公式，全是做事的方法，串起来是一条工作流：先判断该用异常检测还是监督学习（看未来的异常会不会像见过的）；用异常检测的话，对每个特征画直方图，不像钟形就用 $\log$、开方等变换掰过来；跑一遍看 $F_1$；对漏掉的异常做误差分析，造出新的组合特征；再跑，再看。

异常检测的工作量大部分花在这个循环上，而不在模型本身——模型只有两行公式。

> [!important] 这一讲的三句话
> 1. **异常检测还是监督学习，看“未来的正例像不像见过的正例”**：异常种类繁多、正例极少（0 到 20 个常见）、未来的异常可能完全没见过 → 异常检测（欺诈检测、制造业、机房监控）；正负例都多、正例有共性、未来正例和训练集相似 → 监督学习（垃圾邮件、天气预报、癌症分类）。正例少只是表象，种类学不完才是根本；欺诈检测会随数据增多从异常检测转为监督学习。
> 2. **特征不是钟形就掰成钟形**：先画直方图，再用单调凹变换压长尾——$\log(x)$、$\log(x+c)$、$\sqrt{x}$、$x^{1/3}$，压缩力度 $\log>x^{1/3}>x^{1/2}$；新样本必须做同样的变换。不做变换会导致长尾上的正常样本被大量误报。
> 3. **最常见的失败是异常和正常的 $p(x)$ 差不多大，对策是误差分析、造新特征**：逐个看漏掉的异常，问哪个量能表达这份不对劲。选特征的原则是“出事时会异常大或异常小”。组合特征（机房例：$x_5=\frac{\text{CPU 负载}}{\text{网络流量}}$，$x_6=\frac{(\text{CPU 负载})^2}{\text{网络流量}}$）把“特征之间的关系”翻译成“单个特征的极端值”，从而绕过独立性假设的缺口。

### 速查表

| 名称 | 内容 |
|---|---|
| 选路判据 | 未来的正例会不会像见过的正例？会 → 监督学习；不会 → 异常检测 |
| 异常检测典型任务 | 欺诈检测、制造业、机房监控 |
| 监督学习典型任务 | 垃圾邮件、天气预报、癌症分类 |
| 会迁移的例子 | 欺诈检测：数据少用异常检测，做大后转监督学习 |
| 第一步 | 每个特征画直方图 |
| 变换 | $\log(x)$、$\log(x+c)$、$x^{1/2}$、$x^{1/3}$ |
| 压缩力度 | $\log>x^{1/3}>x^{1/2}>x$ |
| 纪律 | 新样本做同样的变换 |
| 最常见的失败 | 正常和异常的 $p(x)$ 差不多大 |
| 误差分析 | 找漏掉的异常 → 人工看 → 造特征 → 看 $F_1$ |
| 选特征原则 | 出事时会异常大或异常小 |
| 机房组合特征 | $x_5=\frac{\text{CPU}}{\text{网络}}$，$x_6=\frac{\text{CPU}^2}{\text{网络}}$ |

> [!abstract] 下一讲预告
> 手工造组合特征的硬伤是：每个组合都得靠人想。四个特征两两组合有 6 对，十个特征有 45 对，还有三个一组的……人想不过来。下一讲换一条路：**不再假设特征独立**，直接用一个能容纳相关性的分布——**多元高斯分布**。它的协方差矩阵 $\Sigma$ 装的正是特征之间的关系，等高线能自动斜过来贴合数据。你还会看到，这一讲用的模型其实就是多元高斯的一个特例。
