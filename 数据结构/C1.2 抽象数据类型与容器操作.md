## 一、ADT 的定义

> [!important] Definition 抽象数据类型 Abstract Data Type
> $$\mathrm{ADT} = (D,\ R,\ O)$$
> - **D: Data Object** 数据对象
> - **R: Relationship** 关系
> - **O: Operations** 操作
>
> 原文：In software, when storing objects and relationships in containers, there are **reoccurring containers** of elements and associated relationships where the actual queries and operations are **restricted**. We model such containers by ADTs.
> （软件中反复出现一些"元素 + 关系"的容器，其上的查询与操作是**受限**的；我们用 ADT 来给这类容器建模。）

> [!note] 三个字母怎么和上一节接上
> - $D$ 就是 [[C1.1 数据结构的基本概念]] 里的**数据对象**；
> - $R$ 就是那里说的**结构 / 关系**；
> - $O$ 是新增的一维：**你允许对它做什么**。
>
> 换句话说：**数据结构 = (D, R)，ADT = 数据结构 + 操作集合**。ADT 比数据结构多的正是"操作"这一层。
>
> 三点要记住：
> 1. **每学一个数据结构，都会先给出它对应的 ADT。** 这是本课固定的讲法。
> 2. **ADT 是纯抽象的**：它不涉及在计算机里如何实现。数据是什么、数据之间的关系是什么——**这里的关系也是抽象的、逻辑的**。
> 3. 第一个字母 D 写作 data object，但按 [[C1.1 数据结构的基本概念]] 说过的混用惯例，**多数时候按 data elements 理解即可**。
>
> "**受限 (restricted)**"这个词是关键。栈之所以是栈，不是因为它存得下东西，而是因为它**只允许**在一端进出。**限制本身就是数据结构的定义方式**——这是第 3 章栈、第 4 章队列的思想源头。

> [!warning] 易错点：ADT 是"规格说明"，不是"实现"
> ADT 只回答"有哪些操作、语义是什么"，不回答"用数组还是链表"。用数组实现的栈和用链表实现的栈是**同一个 ADT 的两种实现**。C++ 里 ADT 对应的是**类的 public 接口**，实现对应 private 成员。

## 二、Container ADT：最一般的抽象数据类型

> [!important] Container 容器
> The most general ADT is that of a **container**（最一般的抽象数据类型就是"容器"）。
> A container **describes structures that store and give access to elements**（容器描述"存放元素并提供访问"的结构）。
> 通俗说法：**先别管这个容器要做什么，任何数据你先放进来，它就叫一个容器。**
>
> 容器上感兴趣的查询与操作可以定义在两个层面：
> - **The container as an entity** —— 把容器当作一个整体
> - **The elements stored within a container** —— 容器里存的元素

> [!note] 你可能已经用过容器了
> C++ 标准模板库 **STL** 里的 `vector`、`set`、`map` 就是现成的容器。用过它们的人对"容器"会有直接的体感：你只管往里放东西、从里面取东西，至于它内部怎么存的并不需要知道——**这正是 ADT"接口与实现分离"的意思**。

> [!important] 设计任何容器前必须问的六个问题（ADT 页原文）
> 这六个问题**不需要背**，看一眼在脑子里留个印象即可：**当你要定义一个容器、定义一个 ADT 时，这些就是必须考虑的东西**，而且它们通常都会落实成你定义的那些函数。
> 只要你打算存对象，就必须先回答：
> 1. What are the **relationships** on the objects?（对象之间有什么关系？）
> 2. What **queries** will be made about the objects in the container?（会对元素做哪些查询？）
> 3. What **operations** will be performed on the objects in the container?（会对元素做哪些操作？）
> 4. What operations may be performed on the **container as a whole**?（会对容器整体做哪些操作？）
> 5. What queries will be made about the **relationships between the objects**?（会对元素间的关系做哪些查询？）
> 6. What operations may be made on the **relationships themselves**?（会对关系本身做哪些操作？）

> [!note] 这六问就是本课的目录（拓展：归纳整理）
> 逐条对应后面的章节：问题 1 → 六种关系（[[C1.3 数据元素间的六种关系]]）；问题 2、3 → 查找与增删；问题 4 → 构造/析构/清空/求长度；问题 5、6 → 树的"最近公共祖先"、并查集的 union、图的连通性。**你要是能对一个新结构答出这六问，就等于写出了它的 ADT。**

## 三、操作的取舍原则（Operations）

> [!important] 核心原则
> In any application, the actual required operations may be **only a subset** of the possible operations.
> （实际需要的操作往往只是全部可能操作的一个**子集**。）
> - 设计方案时要同时考虑**当前需求和未来需求** (both current and future requirements)。
> - **在特定条件下，减少特定操作可以换来速度提升或内存减少**（by reducing specific operations, the speed can be increased or the memory decreased）。

> [!important] "考虑未来需求"不是空话：两个真实的翻车案例
> **① 12306 春运抢票。** 铁路购票系统刚上线的那几年特别难用：平时买票的人很少，一到春节买票的人瞬间暴增，系统被挤到瘫痪。原因就是设计时**对短时间高峰流量的算法与硬件都没有准备好**。
> **② 微博宕机。** 微博历史上最严重的一次延迟发生在一条明星官宣微博发出时，流传的图片是工程师在度假期间临时打开电脑现场调云资源、紧急申请更多服务器。同样是**没有为突发情况和未来的极端情况做好设计**。
>
> 把它落到课堂本身的例子上：现在这间教室够坐，但如果下学期学生更多了呢？**任何时候设计数据结构，都要同时考虑"数据变多"和"数据变少"两种情况下，哪种设计最有效。**

> [!note] "少给操作换性能"的具体例子
> - 只允许一端进出 → 栈，插入删除变成 $O(1)$。
> - 放弃"任意位置插入" → 有序数组，可以二分查找 $O(\log n)$。
> - 放弃"保持顺序" → 哈希表，查找期望 $O(1)$。
> - AI 场景：推理时的 KV cache 只**追加**不**中间插入**，因此可以用连续内存 + 预分配，省掉链表指针和搬移开销。
>
> **能力越少，性能越高**——这是贯穿全课的交换律。

## 四、CRUD

> [!important] 数据结构处理的是什么
> - 它**不是**用来做数值计算的（It is **not** for numerical calculation）。
> - 它是用于计算机中对元素的基本操作：**Creating, Retrieving, Updating, Deleting**（增、查、改、删，简称 **CRUD**）。
> - 它也用于元素上的其他高级操作。

> [!note] 用班级做例子理解 CRUD
> - **Create / Insert**：别的班转进来一名学生 → 往容器里插入一个元素。
> - **Retrieve / Find**：查某位同学的信息 → 按位置或按值查找。
> - **Update**：期末登分登错了，某同学实际 80 分却录成 70 分，要找到他并改掉 → 访问并修改元素。
> - **Delete / Erase**：某同学觉得数据结构太难要转专业 → 从容器里移除一个元素。
>
> 再加上**遍历 (iterate)**，这就是全部的日常操作。

> [!note] 为什么强调"不是数值计算"
> 数值计算（矩阵求逆、求积分）的瓶颈在**浮点运算次数**，是"计算方法/数值分析"课的事；数据结构的瓶颈在**数据的组织与搬移次数**。同一个 $O(n^2)$，前者数的是乘法，后者数的是元素移动。第 2 章顺序表插入的平均移动次数 $n/2$（见 [[C2.4 顺序表实现]]）就是典型的"数搬移"。

## 五、两类操作清单（考试原样考）

> [!important] Operations on a Container（对容器整体）
> - Create a new container —— **constructor** 构造
> - Copy or destroy an existing container —— **copy constructor, destructor** 拷贝构造 / 析构
> - Empty a container —— **clear** 清空
> - Query how many elements are in a container —— **size** 求长度
> - Query the maximum number of elements a container can hold —— **capacity** 求容量
> - 给定两个容器：求**并 (merge)**，求**交 (intersection)**

> [!important] Operations on Elements in a Container（对元素）
> - Insert an element into a container —— **insert** 插入
> - Access or modify an element in a container —— **find** 访问/修改
> - Remove an element from the container —— **erase** 删除
> - Query if an element is in the container —— **find** 查询是否存在
>   - 如适用，还要能统计某元素在容器中出现了几份
> - Iterate (step through) the elements in a container —— **begin, end** 遍历

> [!important] 容器整体操作与 C++ 类的对应
> 对照上一学期学过的 C++ 类，会发现"对容器整体的操作"其实就是那几个特殊成员函数：
> - Create a new container → **构造函数 constructor**
> - Copy an existing container → **拷贝构造函数 copy constructor**
> - Destroy → **析构函数 destructor**
> - Empty a container → **clear()**
> - How many elements → **size()**
>
> 换句话说：**你写过的每一个类，都可以看成一个容器。**

> [!warning] size 与 capacity 千万别混
> - **size / length**：当前**实际装了几个**元素。
> - **capacity**：最多**能装几个**。
> 顺序表里两者是不同的私有成员（`int length; int capacity;`，见 [[C2.4 顺序表实现]]），插入时要同时判两件事：下标合法（对 length）、没有装满（对 capacity）。STL 的 `vector::size()` 与 `vector::capacity()` 就是这一对。
>
> **一个具体例子**：申请一个能装 11 个元素的数组，但只往里放了 2 个值 —— 此时 **capacity = 11，size = 2**。

> [!note] 这份清单就是第 2 章类定义的来源
> 把上面两张清单合起来，几乎逐字就是 `SqList` 的接口：构造、析构、empty、get、getLength、getCapacity、find、insert、erase。**先有 ADT 清单，后有类定义**——这套接口不是随手写出来的。

## 本节自测 Self-Test

> [!question] Q1：ADT 三元组 (D, R, O) 各是什么？和"数据结构"差在哪？
> **A**：D 数据对象、R 关系、O 操作。数据结构只有 (D, R)，ADT 多了操作集合 O。

> [!question] Q2："减少操作反而更好"怎么理解？举一例。
> **A**：限制操作能换来更强的实现假设。例如栈只允许一端进出，因此插入删除都是 $O(1)$；有序数组放弃任意插入，换来二分查找 $O(\log n)$。

> [!question] Q3：`size` 和 `capacity` 的区别？哪个在插入时用来判"满"？
> **A**：size 是当前元素个数，capacity 是最大容量；判满用 `length == capacity`。

> [!question] Q4：设计一个"通讯录"容器，按六问写出它的 ADT 草稿。（拓展）
> **A**：D = 联系人记录集合；R = 按姓名字典序的线性序（或无序）；O = 增、删、按姓名查、按号码查、遍历、求人数。查询关系的操作：某人是否排在另一人之前。

> [!question] Q5：12306 春运瘫痪和微博宕机，在 ADT 设计上说明了什么原则？
> **A**：设计时必须同时考虑**当前需求和未来（含极端峰值）需求**；只按平时的数据量设计，遇到突发规模就会崩溃。

> [!question] Q6：容器的"整体操作"在 C++ 类里对应哪些成员函数？
> **A**：构造函数、拷贝构造函数、析构函数、clear()、size()——任何一个类都可以看成一个容器。
