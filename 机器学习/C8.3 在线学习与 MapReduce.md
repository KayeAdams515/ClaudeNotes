# C8.3 在线学习与 MapReduce

> [!abstract] 本讲任务
> 大规模机器学习的最后两个工具。一个对付**源源不断的数据流**：来一个样本学一次，学完就扔——在线学习。另一个对付**一台机器算不完**：把计算拆给很多台机器同时算——MapReduce。前者要讲清楚它和 SGD 是什么关系、有什么额外好处；后者要讲清楚什么样的算法能这样拆。

---

## 1. 在线学习

### 1.1 一个快递网站

设想你经营一个快递网站。用户来了，输入起点和终点；你报一个价；用户要么接受、用你的服务（$y=1$），要么嫌贵走掉（$y=0$）。

你想知道的是：**在这个价格下，这个用户接受的概率有多大？** 记作 $p(y=1\mid x;\theta)$。特征 $x$ 包括用户的属性、起点和终点的属性，以及**你报的价格**。这是一个标准的逻辑回归问题（[[C2.5 逻辑回归]]），学到这个概率之后，就可以用它来**优化报价**。

特别之处在于数据的来法：用户是**一个一个来的，源源不断**。没有一个“收集完毕的训练集”，数据流永远不会停。

### 1.2 算法

对这种场景，算法写出来非常简单：

$$
\begin{aligned}
&\textbf{永远重复}\ \{\\
&\qquad\text{拿到当前这个用户对应的 } (x,y)\\
&\qquad\text{用这一个样本更新 } \theta:\quad\theta_j:=\theta_j-\alpha\left(h_\theta(x)-y\right)x_j\qquad(j=0,\ldots,n)\\
&\}
\end{aligned}
$$

其中 $h_\theta(x)=\frac{1}{1+e^{-\theta^Tx}}$。

![[C8.3-板书-在线学习快递定价.png]]

这个更新式和 [[C8.1 大数据集与随机梯度下降]] 的 SGD 一模一样（逻辑回归的梯度和线性回归形式相同）。区别只在于**数据从哪来**：

| | 随机梯度下降 | 在线学习 |
|---|---|---|
| 数据 | 一个**固定的**训练集，$m$ 个样本 | **源源不断的数据流** |
| 循环 | for $i=1..m$，外面再套几遍 | 永远重复 |
| 样本编号 | $(x^{(i)},y^{(i)})$ | $(x,y)$，没有编号 |
| 用完之后 | 留着，下一遍还会再用 | **扔掉，不再使用** |

注意在线学习里写的是 $(x,y)$，而不是 $(x^{(i)},y^{(i)})$。因为这里**没有“第 $i$ 个样本”这个概念**：样本不存储、不编号、不重复使用。用户来了，学一下，就过去了。这就是“在线”的意思。

什么时候适合这么做？**数据流足够大的时候**。一个大网站每天有成千上万的用户，新数据永远比旧数据多，根本不需要回头重复使用旧样本。如果一天只来几个用户，那还不如把数据存下来，用普通方法训练。

### 1.3 一个意外的好处：跟得上变化

在线学习还有一个固定数据集训练做不到的优点：**它能适应用户偏好的变化。**

用户偏好是会变的。经济好的时候人们对价格不敏感，经济差的时候就很敏感；竞争对手降了价，你的报价就显得贵了；节假日前大家更愿意为加急付钱……在线学习**一直在用最新的数据更新 $\theta$**，旧数据的影响会被新数据逐渐冲淡，所以 $\theta$ 会自动跟着偏好漂移。一个用去年数据训练好、之后就不再更新的模型，做不到这一点。

> [!tip] 学到了概率，怎么用来定价？（拓展）
> 设运一单的成本是 $c$，报价为 price，那么期望利润是
> $$\mathbb{E}[\text{利润}]=p(y=1\mid x,\text{price};\theta)\times(\text{price}-c)$$
> 价格定高了，每单赚得多但用户接受的概率低；定低了反之。对每个来访用户，试几个候选价格，报出期望利润最大的那个——这就是“优化报价”。

### 1.4 另一个例子：商品搜索

一个电商网站，用户搜索 “Android phone 1080p camera”。店里有 100 款手机，页面上只能展示 10 个结果。**展示哪 10 个？**

对每一款手机，构造特征 $x$：手机本身的属性、搜索词里有几个词和手机名称匹配、有几个词和手机描述匹配，等等。标签 $y$ 是用户**有没有点击**这个结果。学习 $p(y=1\mid x;\theta)$——这个量叫**预测点击率 predicted CTR**（click-through rate）。然后把点击率最高的 10 款展示出来。

![[C8.3-板书-在线学习商品搜索.png]]

在线学习在这里是这样发生的：每次展示 10 个结果，用户点了其中几个、没点另外几个——**一次搜索就产生了 10 个 $(x,y)$ 样本**。每个都拿来更新一次 $\theta$，然后扔掉。

同样的思路还能用在：挑选给用户展示哪些特惠活动、为用户挑选新闻文章、商品推荐——后者正是 [[C7.1 推荐问题与基于内容的推荐]] 的场景，推荐系统天然适合在线学习。

## 2. MapReduce 与数据并行

### 2.1 把求和拆开

回到批量梯度下降。为了好算，假设只有 $m=400$ 个样本（真实场景可能是 4 亿）：

$$\theta_j:=\theta_j-\alpha\,\frac{1}{400}\sum_{i=1}^{400}\left(h_\theta(x^{(i)})-y^{(i)}\right)x_j^{(i)}$$

最耗时的是那个 400 项的求和。一个很自然的想法：**把它拆成 4 份，交给 4 台机器同时算。**

| 机器 | 负责哪些样本 | 计算 |
|---|---|---|
| 机器 1 | 第 1 到 100 个 | $\text{temp}_j^{(1)}=\sum_{i=1}^{100}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$ |
| 机器 2 | 第 101 到 200 个 | $\text{temp}_j^{(2)}=\sum_{i=101}^{200}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$ |
| 机器 3 | 第 201 到 300 个 | $\text{temp}_j^{(3)}=\sum_{i=201}^{300}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$ |
| 机器 4 | 第 301 到 400 个 | $\text{temp}_j^{(4)}=\sum_{i=301}^{400}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$ |

四台机器算完，把结果送到一台中心服务器上**合并**：

$$\theta_j:=\theta_j-\alpha\,\frac{1}{400}\left(\text{temp}_j^{(1)}+\text{temp}_j^{(2)}+\text{temp}_j^{(3)}+\text{temp}_j^{(4)}\right)\qquad(j=0,\ldots,n)$$

![[C8.3-板书-MapReduce拆分求和.png]]

为什么这样做是对的？因为

$$\sum_{i=1}^{400}=\sum_{i=1}^{100}+\sum_{i=101}^{200}+\sum_{i=201}^{300}+\sum_{i=301}^{400}$$

求和可以任意拆开、分别算、最后相加。合并后的结果和一台机器算的**完全相同**——不是近似，是精确相等。理想情况下，4 台机器能把计算提速接近 4 倍；实际会少一些，因为要把数据分发出去、把结果收回来，有网络通信的开销。

### 2.2 名字的来历

这个模式分两步：

- **Map**：把任务分发到各台机器，每台对自己那一份数据做同样的计算（算出自己的 $\text{temp}_j$）；
- **Reduce**：把各台的结果汇总成一个（把四个 $\text{temp}_j$ 加起来）。

所以叫 **MapReduce**。它出自 Google 的 Jeffrey Dean 和 Sanjay Ghemawat（2004），最有名的开源实现是 Hadoop。（拓展）

![[C8.3-板书-MapReduce示意.png]]

### 2.3 什么样的算法能这样拆

判断标准只有一条：**算法里最耗时的那部分，是不是一个“对训练集求和”？** 是，就可以用 MapReduce；不是，就不行，或者不容易。

事实上，很多学习算法都能写成“在训练集上对某些函数求和”。比如用高级优化算法（[[C2.6 高级优化算法与多分类]] 里的 fminunc、L-BFGS 等）训练逻辑回归时，每一步要向优化器提供两样东西——代价和梯度：

$$J_{train}(\theta)=-\frac1m\sum_{i=1}^{m}\left[y^{(i)}\log h_\theta(x^{(i)})+(1-y^{(i)})\log\left(1-h_\theta(x^{(i)})\right)\right]$$

$$\frac{\partial}{\partial\theta_j}J_{train}(\theta)=\frac1m\sum_{i=1}^{m}\left(h_\theta(x^{(i)})-y^{(i)}\right)x_j^{(i)}$$

**两个都是对训练集的求和。** 所以每台机器可以各算一份部分和——代价的部分和 $\text{temp}^{(k)}$、梯度的部分和 $\text{temp}_j^{(k)}$——汇总之后交给优化器。

![[C8.3-板书-求和形式的算法.png]]

> [!warning] 课件笔误
> 课件这一页的代价函数印成了 $-\frac1m\sum y^{(i)}\log h_\theta(x^{(i)})\,-\,(1-y^{(i)})\log(1-h_\theta(x^{(i)}))$：中间是减号，而且少了方括号，第二项的符号就反了。正确的对数损失（[[C2.5 逻辑回归]]）是上面写的那个——**中间是加号，外面有方括号**。考试按正确的写。

那 SGD 为什么不太适合 MapReduce？因为 SGD 每一步只用一个样本，**根本没有求和可以拆**；而且每一步都依赖上一步的 $\theta$，天然是串行的。所以大规模场景下常见两条路：单机跑 SGD 或小批量（每步便宜，步数多），或者多机用 MapReduce 跑批量法（每步贵，但可以并行）。（拓展）

### 2.4 一台机器上的多核

同样的思路不一定需要多台机器。今天一台普通电脑就有 4 到 16 个 CPU 核，把训练集拆给几个核并行计算，道理完全一样。

![[C8.3-多核并行.png]]

多核比多机还多一个好处：**没有网络通信开销**——各个核共享内存，数据不用在机器之间传来传去，所以实际加速比更接近理想值。更进一步，很多线性代数库在做向量化运算时**已经自动用上了多核**。只要你把代码写成向量化形式（[[C8.2 小批量梯度下降与 SGD 的收敛]] 讲过），并行就自动发生了，连 MapReduce 都不用自己写。（拓展）

## 3. 小结

第 8 章是一张“数据太大怎么办”的工具箱：

| 方法 | 每步用多少数据 | 能否并行 | 适合 |
|---|---|---|---|
| 批量梯度下降 | 全部 $m$ 个 | 能（MapReduce） | 数据不太大，或有集群 |
| 随机梯度下降 | 1 个 | 基本不能 | 单机、数据极大 |
| 小批量梯度下降 | $b$ 个 | 批内可向量化 / 多核 | 最常用的折中 |
| 在线学习 | 来一个用一个 | — | 数据流、偏好会变 |

用之前，别忘了 [[C8.1 大数据集与随机梯度下降]] 的第一步：先画学习曲线，确认加数据真的有用。

> [!important] 这一讲的三句话
> 1. **在线学习**：数据源源不断时，永远重复 { 取当前用户的 $(x,y)$；$\theta_j:=\theta_j-\alpha(h_\theta(x)-y)x_j$ }。更新式与 SGD 相同，但没有固定训练集、样本不编号、用完即扔，并且**能适应用户偏好的变化**。例：快递网站学 $p(y=1\mid x;\theta)$（$x$ 含报价）来优化定价；商品搜索学预测点击率，决定展示哪 10 款手机；还可用于特惠选择、新闻推荐、商品推荐。
> 2. **MapReduce**：把批量梯度下降里的求和拆给多台机器——$m=400$、4 台机器时，各算 $\text{temp}_j^{(k)}=\sum_{i\in\text{第}k\text{份}}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$，再合并 $\theta_j:=\theta_j-\alpha\frac1{400}(\text{temp}_j^{(1)}+\cdots+\text{temp}_j^{(4)})$。结果与单机精确相等，理想提速接近机器数，实际受通信开销影响。
> 3. **能不能用 MapReduce，看最耗时的部分是不是对训练集求和**：用高级优化器训练逻辑回归时，代价和梯度都是求和，都能拆。同样的思路可以用在单机多核上，没有网络开销。

### 速查表

| 名称 | 公式 / 内容 |
|---|---|
| 在线学习 | 永远重复 { 取 $(x,y)$；$\theta_j:=\theta_j-\alpha(h_\theta(x)-y)x_j$ } |
| 与 SGD 的区别 | 数据流、无编号、用完即扔、没有“遍数” |
| 在线学习的好处 | 适应用户偏好的变化 |
| 快递例 | $y=1$ 接受报价；$x$ 含用户、起终点、价格；学 $p(y=1\mid x;\theta)$ |
| 商品搜索例 | 100 款手机选 10 个展示；$y=1$ 为点击；学预测点击率 CTR |
| MapReduce 拆分 | $\text{temp}_j^{(k)}=\sum_{i\in\text{第}k\text{份}}(h_\theta(x^{(i)})-y^{(i)})x_j^{(i)}$ |
| MapReduce 合并 | $\theta_j:=\theta_j-\alpha\frac1m\sum_k\text{temp}_j^{(k)}$ |
| 为什么精确 | 求和可以任意拆开再相加 |
| 适用判据 | 主要计算是否为对训练集求和 |
| 逻辑回归代价 | $-\frac1m\sum[y\log h+(1-y)\log(1-h)]$（课件此页中间误为减号） |
| 多核 | 同样的数据并行，无网络开销 |
