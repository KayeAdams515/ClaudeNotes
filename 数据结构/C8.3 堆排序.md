# C8.3 堆排序

> [!abstract] 这一讲的任务
> 第七章的堆能在 $O(\lg n)$ 里反复交出最值，于是"排序"有了一个几乎不用想的答案：全都塞进堆，再一个一个取出来。这一讲把它做成算法，中间只转两个弯——**改用 max-heap**，以及**把取出的最大值直接写回数组尾部空出的那一格**。转过之后，整个过程只用 $\Theta(1)$ 的额外空间。
> 另一件事更值钱：把乱序数组**原地**变成堆只要 $\Theta(n)$，不是"插 $n$ 次"的 $\Theta(n\lg n)$。这个反直觉的结论靠一次按层求和，也是堆排序便宜的全部原因。

## 把第七章的堆用满

这一讲不是在发明新算法，而是把已经有的结构用满。第七章建好的堆，一直在做一件事：**$O(\lg n)$ 交出当前最值**。那"排序"呢？把所有元素塞进去，再一个一个取出来——取出来的顺序天然就是有序的。

整节要走的四步，第一页就列清楚了：先定策略（进堆、出堆），算它的代价，再解决一个工程问题（**能不能原地**），最后看例子。原页还标了一句 `Bonus: may be performed in place`——这一句是整节课的落点，也是堆排序能在 $\Theta(n\lg n)$ 三兄弟里站住脚的唯一理由。

### 代价：$\ln(n!)$ 是怎么冒出来的

设堆里有 $k$ 个元素，取走堆顶要 $O(\lg k)$——下滤最多走树高那么多层。取 $n$ 次，总代价是

$$\sum_{k=1}^{n}\ln k=\ln(1\cdot 2\cdots n)=\ln(n!).$$

中间这一步只用到 $\ln a+\ln b=\ln(ab)$：$n$ 个对数的和并成一个对数，里面正好是阶乘。

所以问题变成一个纯数学问题：**$\ln(n!)$ 长得多快？**

工具算一遍最省事：

> [!quote] 原稿
> `> asympt( ln( n! ), n );`
> The leading term is $(\ln n-1)n$ … Therefore, the run time is $O(n\ln n)$

展开式是

$$\ln(n!)=\bigl(\ln n-1\bigr)n+\ln\sqrt{2\pi}+\frac{1}{2}\ln n+\frac{1}{12n}-\frac{1}{360n^{3}}+O\!\left(\frac{1}{n^{5}}\right).$$

**只有第一项 $(\ln n-1)n$ 决定阶**：它等于 $n\ln n-n$，与 $n\ln n$ 同阶；后面的 $\frac12\ln n$、$\frac1{12n}$ 相对它都趋于零。于是总代价 $\Theta(n\ln n)$。

这一步真正要带走的是下面这个直觉，而不是展开式：

> [!tip] 为什么是 $n\ln n$ 而不是 $n^2$
> $\ln(n!)=\sum_{k=1}^{n}\ln k$ 是把 $n$ 个数加起来。被加项从 $0$ 一路涨到 $\ln n$，平均下来大约 $\frac{\ln n}{2}$；乘上 $n$ 项，总量约 $\frac{n\ln n}{2}$。
> **平均值只有 $\ln n$ 的一半**，所以是 $n\ln n$——系数是 $1$ 还是 $\frac12$ 不影响阶。

![[C8-堆排序-阶乘对数与nlnn曲线.png]]

两条曲线不重合，但形状一致：差的就是那个 $-n$。$n=1000$ 时 $\ln(1000!)\approx 5912$，$1000\ln 1000\approx 6908$，差 996，比值 $0.856$。差值本身随 $n$ 线性增长，**比值才缓慢趋近 1**（大约 $1-\frac{1}{\ln n}$）。判断阶看比值，不看差值。

### 麻烦来了：这不原地

上面那套做法要**另开一个大小为 $n$ 的 min-heap**，额外内存 $\Theta(n)$。按第一章立的口径，这就不算原地，也就不算好算法。

于是这一页提出真正的问题：能不能只用 $\Theta(1)$ 的额外空间（几个临时变量）？注意这不是"优化一下"，而是**换一个方向**：

> [!important] 为什么必须换成 max-heap
> 用 min-heap，先取出的是**最小值**，而最小值该待的位置是数组**开头**——开头已经被占着，你只能另开一块输出区，或者每次把整个数组往后挪一格。
> 用 max-heap，先取出的是**最大值**，而最大值该待的位置是数组**末尾**——堆每缩小一次，末尾正好空出一格。
>
> **堆给出的顺序，和数组空位长出来的顺序，方向相反才对得上。** 这一句话就是整个原地方案。

有人会问：min-heap 取出的最小值，能不能也放到数组末尾？能，但那是从后往前放降序，最后整段是降序，还得再翻一遍。要让"取出的顺序"和"空位的顺序"一致，就只能让堆先交最大值。

![[C8-堆排序-乱序数组按层存进数组.png]]

![[C8-堆排序-乱序数组对应的完全树.png]]

这两张是同一件事的两种画法：数组 `46 52 28 17 3 63 34 81 70 95`，按层塞进一棵完全二叉树。几个具体的对应：

- 根 46 在下标 0，孩子 52、28 在下标 1、2；
- 下标 3 的 17 有两个孩子 81、70（下标 7、8）；
- 下标 4 的 **3 只有一个孩子 95**（下标 9）——$n=10$，最后一个结点在下标 9。

这棵树既不是 min-heap，也不是 max-heap，更不是 BST；它只是一串数按层摆好。堆化要做的，是**不改变形状，只重排值**。

#### 0 起编号：父子公式全部平移一位

第七章用的是 1 起编号：孩子 $2k$、$2k+1$，父 $\lfloor k/2\rfloor$。C++ 数组从 0 开始，全部要平移：

![[C8-堆排序-零起下标的父子公式.png]]

$$\text{Children}: 2k+1,\;2k+2 \qquad\qquad \text{Parent}: \left\lfloor\frac{k-1}{2}\right\rfloor$$

| 名称 | 1 起编号（第七章） | 0 起编号（本讲） |
| --- | --- | --- |
| 根 | 下标 1 | 下标 0 |
| $k$ 的孩子 | $2k$、$2k+1$ | $2k+1$、$2k+2$ |
| $k$ 的父 | $\lfloor k/2\rfloor$ | $\lfloor (k-1)/2\rfloor$ |
| 最后一个非叶结点 | $\lfloor n/2\rfloor$ | $\lfloor n/2\rfloor-1$ |
| 有没有左孩子 | $2k\le n$ | $2k+1<n$ |

最后一行是最容易写出死循环的地方：**判断孩子是否存在，必须和"孩子下标"用同一套编号**。

> [!warning] 原页的父公式缺一个取整
> 材料上印的是 `Parent = (k + 1)/2 - 1`。$k=2$ 时 $(2+1)/2=1.5$，减 1 得 $0.5$——不是下标。它只在整除时成立。
> 正确写法是 $\lfloor(k+1)/2\rfloor-1$，对非负整数与 $\lfloor(k-1)/2\rfloor$ 完全等价（$k=2\to0$、$k=3\to1$、$k=0\to-1$ 表示没有父）。**直接记 $\lfloor(k-1)/2\rfloor$**，不用再补一句"什么时候整除"。

### 原地堆化：从叶子往回修

现在手上的问题是：给定这棵乱序的完全树，**能不能就在原地把它修成 max-heap**？

页面上给了两条路，并且立刻要你选：

| 策略 | 做法 | 代价 |
| --- | --- | --- |
| 自顶向下（插入式） | 把 46 当成一个堆，其余元素逐个"插入"并上滤 | $n$ 次上滤，每次 $O(\lg n)$ → 最坏 $\Theta(n\lg n)$ |
| **自底向上（修正式）** | 叶子天生是堆；从最后一个非叶结点往回，逐个向下渗 | 见下文：$\Theta(n)$ |

两条路都对，第二条便宜。**便宜在哪**，先记住一句话，下一小节会把它算实：**要渗得深的结点（靠近根）数量少，数量多的结点（底层）只需渗一点点**。自底向上正好把便宜的活干在数量多的那一头。

> [!important] 下渗 percolating down
> 对以 $k$ 为根的子树，若它的左右子树都已经是堆，只要 $a_k$ 比某个孩子小，就把 $a_k$ 与**较大的那个孩子**交换，然后对新位置继续做同一件事，直到 $a_k$ 不小于两个孩子，或者走到叶子。

两个细节缺一不可：

- **必须换"较大的那个孩子"**。换小的那个，大的仍压在头上，还是违反堆性质。
- **必须继续往下渗**。一次交换只解决当前这一层；换下去之后可能还比自己新的孩子小——下面 24 就连渗了两层。

#### 堆化为什么是 $\Theta(n)$

设树高 $h$（根在第 0 层，叶子在第 $h$ 层）。第 $k$ 层有 $2^k$ 个结点，每个最坏要渗 $h-k$ 层，于是总交换次数不超过

$$\sum_{k=0}^{h}2^{k}(h-k).$$

原页给的说法是从最底层往上数：倒数第二层最多换 1 次，再上一层最多 2 次……和这个和式是同一件事。

这个和有一个干净的闭式：

$$\sum_{k=0}^{h}2^{k}(h-k)=\bigl(2^{h+1}-1\bigr)-(h+1).$$

> [!tip] 闭式怎么来
> 令 $j=h-k$，和式变成 $\sum_{j=0}^{h}2^{h-j}j=2^{h}\sum_{j=0}^{h}\frac{j}{2^{j}}$。而 $\sum_{j\ge0}\frac{j}{2^j}=2$，截到 $h$ 项少掉的尾巴是 $\frac{h+2}{2^{h}}$，代回去正好是 $2^{h+1}-(h+2)$。
> 手算几个值核对：$h=0\to0$，$1\to1$，$2\to4$，$3\to11$，$4\to26$，与 $2^{h+1}-1-(h+1)$ 逐项相等。

完美树有 $n=2^{h+1}-1$ 个结点，$h+1=\lg(n+1)$，代入：

$$\text{总交换次数}\le n-\lg(n+1).$$

每次交换要 **2 次比较**（先比出哪个孩子大，再和孩子比是否要换），所以比较次数不超过 $2n-2\lg(n+1)$——**是 $\Theta(n)$，不是 $\Theta(n\lg n)$**。

> [!important] 一句话解释这个结果
> 完全树里**一半以上是叶子**，一层都不用渗；剩下的一半里绝大多数在倒数第二层，最多渗 1 层。真正要渗很多层的只有根附近那少数几个。
> **"要渗得深"和"结点多"在数量上正好错开**，所以总和是线性的。
> 反过来，自顶向下"插入 + 上滤"时，最底层那 $n/2$ 个结点每个都要上滤 $\lg n$ 层——同一种树，反过来做，差一个 $\lg n$。

原页把上界说成"最多 $2n$ 次比较"。严格算是 $2n-2\lg(n+1)$，比 $2n$ 小一点；作为上界没错，只是不够紧。

这一节是整讲唯一需要动笔的推导。考法通常就一句："证明建堆是 $\Theta(n)$"——要写出按层求和、用 $n=2^{h+1}-1$ 化简、再说明为什么不是 $n\lg n$。最常见的错是**默认每个结点都渗满 $h$ 层**，那样算出来就是 $\Theta(n\lg n)$，正好把结论算反。

#### 课上的实现

课上记下来的实现。建堆和排序各一个函数，渗下抽成了 `pd`：

```C++
// 建堆：从最后一个非叶结点往前，逐个向下渗
void heap(int* arr, int size) {
    for (int i = size / 2 - 1; i >= 0; --i)
        pd(arr, size, i);
}

// 排序：堆顶换到尾部，堆区缩小，再把新堆顶渗下去
void heap_sort(int* arr, int size) {
    heap(arr, size);
    for (int i = size - 1; i > 0; --i) {
        swap(arr[0], arr[i]);
        pd(arr, i, 0);
    }
}
```

> [!warning] 手记里的三处笔误与两个约定
> 记录原样是 `for (int i = size-1, i>0, i--)`——三处都是逗号，照抄编译不过。函数名 `pd` 是 percolate down 的缩写，签名 `pd(数组, 堆的大小, 起点)`，就是第七章的向下渗。
> **`i > 0` 而不是 `i >= 0`**：最后一轮 `i = 1` 时堆里只剩两个元素，换完就结束，不需要再渗——这正是上面表格最后一行。
> 建堆用 `size/2 - 1`，是 0 起编号的公式，和原稿文字里的 `10/2 = 5` 差一位，以代码为准。

这段代码把整节课的三个要点一次串完：**起点 `size/2-1`**（0 起编号）、**原地**（没有新数组，只有 `swap`）、**少一次弹出**（`i > 0`）。手算时容易漏的，代码里都写在循环边界上。

### 黑板题：12 个数

用堆排序排这 12 个：

$$34,\;15,\;65,\;59,\;79,\;42,\;40,\;80,\;50,\;61,\;23,\;46$$

> [!example] 解答
> **建堆。** 最后非叶结点是 $\lfloor12/2\rfloor-1=5$（值 42）。依次对 5、4、3、2、1、0 下渗，共 **7 次交换**：5↔11、3↔7、1↔3、3↔7、0↔1、1↔4、4↔9。
> 建堆结果：$80\;79\;65\;59\;61\;46\;40\;15\;50\;34\;23\;42$。
> **弹出 11 次。** 每次堆顶换到末尾、末尾搬到根、再渗下：
> $$15\;23\;34\;40\;42\;46\;50\;59\;61\;65\;79\;80.$$

> [!warning] 手算三个最常见的错
> 1. **起点错**：$n=12$ 从下标 5 开始；不是 6，也不是 $12/2=6$。
> 2. **换错孩子**：永远换**较大的那个**孩子，不是左边那个。
> 3. **漏了继续渗**：换下去之后要再问一句"还比孩子小吗"，像 24 和 13 那样可能连走好几层。

### 总账、最好情况，以及它的短板

| 阶段 | 代价 | 为什么 |
| --- | --- | --- |
| 堆化 | $\Theta(n)$ | 上面的按层求和 |
| 弹出 $n-1$ 次 | $\Theta(n\lg n)$ | 每次渗下最多 $\lg n$ 层、每层 2 次比较 |
| **合计** | $\Theta(n\lg n)$ | 低阶项被吸收 |
| 额外空间 | $\Theta(1)$ | 只有几个下标变量和一次 `swap` |

"弹出 n 个对象"这一页特意强调了一句：**整个过程只多了一次赋值**——把堆顶写回末尾那格。除此之外没有任何额外的堆、数组或链表。这就是 `Bonus: may be performed in place` 兑现的地方。

#### "没有最坏情况"是什么意思

材料上写 `There are no worst-case scenarios for heap sort`。这句容易被读歪，准确的意思是：

- **出堆的代价与数据分布无关**：不管堆里是什么数，每次都是从根渗到叶，最坏走满树高。所以最坏 = 平均 = $\Theta(n\lg n)$。
- **不存在某种输入让它退化成 $\Theta(n^2)$**——这正是它比快速排序稳的地方。
- 但**有**一个最好情况：**所有元素相同**（或绝大多数相同）时，每次比较都不需要换，渗下立刻停，整个算法退化成 $\Theta(n)$。

还有一句容易被略过的：**初始顺序可以加速堆化，但堆化只占总代价的 $\Theta(n)$**，所以再怎么加速也动不了总阶。

| 情况 | 运行时间 | 说明 |
| --- | --- | --- |
| 最坏 | $\Theta(n\lg n)$ | 无退化情形 |
| 平均 | $\Theta(n\lg n)$ | |
| 最好 | $\Theta(n)$ | 所有（或绝大多数）元素相同 |

#### 它的短板（补充）

> [!note] 为什么工程上更爱用快排
> 堆排序渐近最优、原地，但实际速度通常不如快排和归并：
> 1. **访问模式跳**。下渗是"下标 $k\to2k+1$"，一步跨过整段内存，缓存命中率低；归并、快排访问的都是连续区间。
> 2. **比较次数多**。每次交换要 2 次比较（先选孩子、再和孩子比），而快排划分一次比较只做一次判断。
> 3. **分支不可预测**。往哪边渗取决于孩子大小，分支预测失败率高。
>
> 工业界的用法：**用堆排序保最坏情况**（`std::partial_sort`、实时系统兜底），一般情形用快排。C++ 的 `std::make_heap` / `std::sort_heap` 就是把这一节的两步拆成两个函数。

> [!note] 堆排序不稳定
> `[3, 2₁, 2₂]`：建堆后仍是 `3 2₁ 2₂`。弹出 3 时把末尾的 2₂ 换到根，得到 `2₂ 2₁ | 3`；2₂ 不小于孩子，不换。结果 **2₂ 跑到了 2₁ 前面**，原序被破坏。
> 原因还是"远距离交换"：堆顶与数组末尾一换，一个元素就甩过整段。

最后，这一页还把三个 $\Theta(n\lg n)$ 算法的内存摆在一起，给后面两讲埋了引子：**堆排序 $\Theta(1)$、归并排序 $\Theta(n)$、快速排序 $\Theta(\lg n)$（最坏 $\Theta(n)$）**。堆排序是唯一真正原地的。

| 要问的 | 0 起编号下的答案 |
| --- | --- |
| $k$ 的左/右孩子 | $2k+1$ / $2k+2$ |
