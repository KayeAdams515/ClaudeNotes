## 一、要分析的四类成分（Let's Go to Real Code）

> [!important] Basic elements or operations of a program
> - **Operators** 运算符：`+, -, =, +=, ++`, etc.
> - **Control statements** 控制语句：`if, for, while, do-while, switch`
> - **Functions** 函数
> - **Recursive functions** 递归函数
>
> **算法分析的目标**：determine the **asymptotic run time** or **asymptotic memory requirements**（确定渐进运行时间或渐进内存需求）。

> [!important] 分析的产出长什么样
> 做算法分析**不需要**把"这个算法在这个问题下总共执行了多少条指令"精确地算出来。我们要的只是一个形如
> $$\text{选择排序需要 } \Theta(n^2) \text{ 时间}$$
> 这样的结论就够了——能用 $\Theta$ 表示就用 $\Theta$，表示不了就退而用 $O$。**下面这张表就是这类结论的样板**，具体算法会在后续章节学到，现在不必记。

课件顺带给出的结论（要记住）：

| 算法 | 时间 | 额外内存 |
| --- | --- | --- |
| Selection sort 选择排序 | $\Theta(n^2)$ | — |
| Merge / quick / heap sort | $\Theta(n\ln n)$ | Merge $\Theta(n)$；Quick $\Theta(\ln n)$；Heap $\Theta(1)$ |

> [!important] 空间复杂度分析的是「额外空间 additional memory」
> 这是极易忽略的一条约定：**数据本身占用的空间不计入空间复杂度。**
> 处理一个规模为 $n$ 的数组，这 $n$ 个存储单元本身是无论用什么算法都必须占用的——**对所有算法都一样，所以不算**。
> 空间复杂度问的是：**除了问题数据本身的规模之外，你这个算法还额外需要多大空间？**
> 这就是为什么归并排序是 $\Theta(n)$（要开等长辅助数组）、堆排序是 $\Theta(1)$（完全原地）。

> [!note] 为什么快排的额外空间是 $\Theta(\ln n)$（拓展）
> 快排本身原地划分不需要辅助数组，但**递归调用要占栈空间**，栈深度平均是 $\ln n$（最坏 $n$）。归并排序需要一个与原数组等长的辅助数组，所以是 $\Theta(n)$。堆排完全原地，$\Theta(1)$。**"额外空间"要把递归栈算进去**——这是很多人漏掉的一分。

## 二、运算符 Operators

> [!important] 基本假设
> 先跳过机器指令和汇编（"because you all have not learned ☹"，因为还没学底层知识），**假定每个操作都花费固定的一个"时钟周期" (clock cycle)** ——即都是一个常数。
>
> 以下操作的时间都是 $\Theta(1)$：
> - 从内存取/存变量 (Retrieving/storing variables from memory)
> - 变量赋值 `=`
> - 整数运算 `+ - * / % ++ --`
> - 逻辑运算 `&& || !`
> - 位运算 `& | ^ ~`
> - 关系运算 `== != < <= => >`
> - **内存分配与释放 `new delete`**（课件标红）

> [!important] 常数条语句仍是 $\Theta(1)$
> Since each operation runs in $O(1)$, any **fixed number** of operations also runs in $O(1)$：
> $$O(c)=O(1)$$
>
> 直白地说：**跑 5 条语句和跑 10 条语句，在这个等价类里是一样的**，因为 $O(5)=O(1)$。

> [!note] 记号上的一个小提醒
> 严格说，"固定条数的操作"用 $\Theta(1)$ 描述更准确（每次都恰好执行那么多条）；写成 $O(1)$ 虽然常见、也不算错，但**不够精确**。课件与讲义中两者会混用，理解时按上一节 $\Theta$ 与 $O$ 的区别去分辨即可。
> 课件对照的两段代码：交换三行的版本，和中间插入很多行（但**行数与 $n$ 无关**）的版本——**两者都是 $\Theta(1)$**。

```cpp
int tmp = a;        int tmp = a;
a = b;              a = b;
b = tmp;            …  …  …
                    b = tmp;
```

> [!warning] 标红的 `new delete` 值得单独说（后半为拓展）
> 课件把内存分配标红，是因为它**理论上算 $\Theta(1)$，实际上远比一次加法贵**：要向操作系统/分配器要内存，可能触发系统调用、堆整理甚至缺页。
> 这解释了 [[C2.5 单链表实现]] 中"链表插入是 $O(1)$"为什么在实测里往往打不过数组：**数组的 $O(n)$ 次搬移是缓存友好的连续拷贝，链表的 $O(1)$ 插入却带一次 `new`**。理论复杂度相同不代表实际速度相同。

## 三、控制语句 Control Statements

> [!important] 四类控制语句 + 核心原则
> - **Conditional statements 条件语句**：`if, switch`
> - **Condition-controlled loops 条件控制循环**：`for, while, do-while`
> - **Count-controlled loops 计数控制循环**：`for i from 1 to 10 do ... end do;`（Maple）
> - **Collection-controlled loops 集合控制循环**：`foreach ( int i in array ) { ... }`（C#）
>
> **Principle: inside out（由内向外）** —— 先算最内层，再往外乘/加。
>
> 具体到条件语句：**先分析花括号里的语句体，再回头分析条件本身**。

### 3.1 条件语句

```cpp
if ( condition ) {
    // true body
} else {
    // false body
}
```

> [!important] 条件语句的运行时间
> = **条件判断的时间** + **实际执行的那个分支的时间**。
> 大多数情况下条件判断本身是 $\Theta(1)$。
>
> 什么时候不是？——**如果条件里写的是一次函数调用**（例如 `if (search(a, n) > 0)`），那就必须把这个函数的复杂度也分析进去。像 `if (a > b)`、`if (b == 7)` 这种才是 $\Theta(1)$。

**嵌套条件的例子（课件给出，结论是 $\mathbf{O}(n)$）**：

```cpp
switch( i ) {
    case 1:  /* do stuff */ break;
    case 2:  /* do other stuff */ break;
    case 3:  /* do even more stuff */ break;
    case 4:  /* well, do stuff */ break;
    case 5:  /* tired yet? */ break;
    default: /* do default stuff */
}

if ( i == 1 ) { /* do stuff */ }
else if ( i == 2 ) { /* do other stuff */ }
else if ( i == 3 ) { /* do even more stuff */ }
else if ( i == 4 ) { /* well, do stuff */ }
else if ( i == 5 ) { /* tired yet? */ }
else { /* do default stuff */ }
```

> [!warning] 为什么标 $O(n)$？—— 这里的 $n$ 不是"5 个 case"
> 课件上明明只画了 5 个 case（加上 default 是 6 个），是个固定数字，为什么写 $O(n)$ 而不是 $\Theta(1)$？
> **因为这里的 $n$ 指的是"case 的数量"**：这一页想表达的是——**如果分支数量与问题规模 $n$ 相关，那就是 $O(n)$**。
> 反过来：**如果不管问题规模多大，分支永远就是那 5 个，那它就是 $O(1)$。**
> 一句话：**分支数固定 → $\Theta(1)$；分支数随 $n$ 增长 → $O(n)$。**

> [!note] 补充：switch 与 else-if 链并不等价（拓展）
> 编译器常把 `switch` 编译成**跳转表 (jump table)**，做到 $\Theta(1)$；而 `else if` 链只能顺序判断。这两段代码在语义上等价，在复杂度上却可能不同——这正是课件把它们并排放的用意。

### 3.2 函数与"取决于数据"

```cpp
int factorial ( int n ) {          // Deterministic 确定性的
    if ( n == 0 ) { return 1; }
    else { return n * factorial ( n – 1 ); }
}

int find_max( int *array, int n ) {   // Depends on array 取决于数组内容
    max = array[0];
    for ( int i = 1; i < n; ++i ) {
        if ( array[i] > max ) { max = array[i]; }   // 这一行执行几次？
    }
    return max;
}
```

> [!warning] 这一页的标注要小心：`find_max` 整体是确定性的
> 课件在 `find_max` 旁标了 "Depends on array"，容易误读。准确的说法是：
> - **整个算法的复杂度是确定的 $\Theta(n)$** —— 要找数组里的最大值，**必须把每个元素都检查一遍**，一次不多一次不少。
> - **只有 `max = array[i];` 这一行**是 "depends on the array" —— 它有可能被执行、也可能不被执行，取决于数据分布（随机数组下期望约 $\ln n$ 次）。
>
> 也就是说：**"取决于数据"的部分被包在一个 $\Theta(1)$ 的判断里，不影响总量。** 与之对照，`factorial` 的执行路径**完全由 n 决定**（deterministic）：$n \to n-1 \to n-2 \to \dots \to 0$。
> 这一页是"最好 / 最坏 / 平均情况"分析的入口。

### 3.3 条件控制循环

> [!important] 规则一：循环体与循环变量无关
> 初始化、条件判断、自增语句通常都是 $\Theta(1)$。
> ```cpp
> for ( int i = 0; i < n; ++i ) {
>     // code which is Theta(f(n))
> }
> ```
> 运行时间为 $\Theta(n\,f(n))$。
>
> 最简例子：
> ```cpp
> int sum = 0;
> for ( int i = 0; i < n; ++i ) {
>     sum += 1;      // Theta(1)
> }
> ```
> 运行时间 $\Theta(n\cdot 1)=\Theta(n)$。

> [!warning] 课件的一个细节：为什么写 $\Omega(n)$
> 课件说："Assuming there are **no break or return statements** in the loop, the run time is $\Omega(n)$."
> 用 $\Omega$（下界）而不是 $\Theta$，是因为**循环体内部可能还有更贵的东西**，所以只能保证"至少" $n$ 次。一旦提前 `break`，连这个下界都不成立。**有 break 的循环只能给上界 $O$。**

> [!important] 规则二：循环体依赖循环变量
> ```cpp
> for ( int i = 0; i < n; ++i ) {
>     // code which is Theta(f(i,n))
> }
> ```
> 运行时间为
> $$\Theta\!\left(1+\sum_{i=0}^{n-1}\bigl(1+f(i,n)\bigr)\right)$$

> [!note] 式子里那两个 "1" 是什么
> 这个式子给出的是**准确**的指令条数，不是估计值——它一定会执行这么多条。两个 1 的来源：
> - 括号外的 $1$：循环的**初始化**（`int i = 0`）以及即使循环一次都不执行也要花的常数时间（防止 $n=0$ 时算出 $\Theta(0)$ 这种无意义结果）。
> - 求和号内的 $1$：每一轮都要做的**条件判断 + 自增**开销；$f(i,n)$ 是循环体本身。
>
> **写复杂度时永远不要出现 $\Theta(0)$**——这就是加 1 的意义。

> [!important] 嵌套循环（不依赖内层变量）
> ```cpp
> int sum = 0;
> for ( int i = 0; i < n; ++i ) {
>     for ( int j = 0; j < m; ++j ) {
>         sum += 1;        // Theta(1)
>     }
> }
> ```
> 内层是 $\Theta(m)$，外层执行 $n$ 次，总计 $\Theta(n\cdot m)$。

> [!important] 嵌套循环（内层上界依赖外层变量）—— 本节最重要的推导
> ```cpp
> int sum = 0;
> for ( int i = 0; i < n; ++i ) {
>     for ( int j = 0; j < i; ++j ) {     // 注意是 j < i
>         sum += i + j;
>     }
> }
> ```
> 内层是 $\Theta(1+i(1+1))=\Theta(i)$，故外层为
> $$\Theta\!\left(1+\sum_{i=0}^{n-1}(1+i)\right)=\Theta\!\left(1+n+\sum_{i=0}^{n-1} i\right)=\Theta\!\left(1+n+\frac{n(n-1)}{2}\right)=\Theta(n^2)$$

> [!important] 这个双重循环在做什么
> 它做的是一个**"三角形的加法"**：内层依次执行 0 个、1 个、2 个……元素的累加，数量不断递增，再把这些数全部加起来。
> **看到"三角形循环"就该条件反射：$\Theta(n^2)$。**

> [!note] 中间那一步的来源
> $\displaystyle\sum_{i=0}^{n-1} i = 0+1+\dots+(n-1)=\frac{(n-1)n}{2}$，即高斯求和。
> 这个 $\frac{n(n-1)}{2}$ 会在整门课里反复出现：冒泡/选择排序的比较次数、顺序表删除的平均移动次数（[[C2.4 顺序表实现]] 的 $\frac{n-1}{2}$）、邻接矩阵的上三角元素个数。**看到"三角形循环"就该条件反射写出 $n^2/2$。**
> 也要注意：$\Theta(n^2/2)=\Theta(n^2)$，系数 $1/2$ 在渐进意义下被丢掉——但在实测中它意味着**快一倍**。

### 3.4 串行语句：把各段相加

课件给的完整例子（数组扩容函数）：

```cpp
template <typename T>
void update_capacity( int delta ) {
    T *array_old = array;                 // ┐
    int capacity_old = array_capacity;    // │ Θ(1)
    array_capacity += delta;              // │
    array = new T[array_capacity];        // ┘

    for ( int i = 0; i < capacity_old; ++i ) {
        array[i] = array_old[i];          // Θ(n)
    }

    delete[] array_old;                   // Θ(1) or O(n)
}
```

总运行时间：
$$\Theta(1+n+1)=\Theta(n)$$

> [!important] 串行语句的规则
> 若程序由若干互不相同的代码块顺序组成，就**分别分析每一块，再把结果加起来**。总复杂度 = 各段之和，而和的阶 = **最大的那一段的阶**。

> [!note] `delete[]` 为什么标注 "$\Theta(1)$ **or** $O(n)$"（拓展）
> 因为 `delete[]` 要**逐个调用 $n$ 个元素的析构函数**：若 T 是 `int` 这类平凡类型，编译器可以直接释放整块，$\Theta(1)$；若 T 是带析构函数的类（比如里面有指针），就必须逐个析构，$O(n)$。
> 这就是"这段代码里藏着的第二个 $n$"，也是课件用 "or" 的原因。顺带说明：本节的分析**必须结合类型和实现**，不能只看语句形状。
> 这段代码正是 [[C1.4 物理结构与存储分配]] 说的"数组扩容只能重新申请再拷贝"的具体实现。

## 四、$\Theta$ 与 $O$ 的混合运算（Interesting or Confusing）

> [!important] 课件的两个问题
> 1. 在规模为 $n$ 的随机表中找**最大值** —— 必须检查每个元素，因此运行时间是 $\Theta(n)$。
> 2. 在规模为 $n$ 的随机表中找**某个特定元素** —— 可能提前结束（第一个就命中），因此是 $\mathbf{O}(n)$。

> [!important] 混合运算法则
> - 若**最高次项是 big-$\Theta$**，结果必须是 big-$\Theta$；
> - 若最高次项是 big-$O$，只能说结果是 big-$O$。
>
> $$O(n)+O(n^2)+O(n^4) = O(n^4)$$
> $$O(n)+\Theta(n^2) = \Theta(n^2)$$
> $$O(n^2)+\Theta(n) = O(n^2)$$
> $$O(n^2)+\Theta(n^2) = \Theta(n^2)$$

> [!note] 第三条为什么退化成 $O$（最容易错的一条）
> $O(n^2)+\Theta(n)$ 中，$O(n^2)$ 只保证"不超过 $n^2$"，它实际可能只有 $\Theta(1)$。这时总和就是 $\Theta(n)$；但若它真是 $n^2$，总和就是 $\Theta(n^2)$。**下界不确定，所以只能给上界 $O(n^2)$。**
> 记忆口诀：**Θ 是"知道确切阶"，O 是"只知道不超过"。两者相加时，谁的阶高听谁的；如果高阶的那个只是 O，整体就只能是 O。**

> [!warning] 第四条 $O(n^2)+\Theta(n^2)=\Theta(n^2)$：想深了反而会困惑
> 只按两条法则读，答案显然是 $\Theta(n^2)$。但每年成绩最好的几位同学都会在这里卡住并来讨论很久：$O(n^2)$ 的下界不确定，为什么加上去还能保住 $\Theta$？
> **用定义就能解释**。$\Theta(n^2)$ 的定义是存在 $c_1,c_2>0$ 使得 $n>N$ 时
> $$c_1 n^2 < f(n) < c_2 n^2$$
> 而 $O(n^2)$ 的这一项，**最好情况可以是 0，最坏情况是 $n^2$ 量级**。于是把它加进来：
> - 下界一侧最多加 $0$ → 仍是 $c_1 n^2$；
> - 上界一侧最多加一个 $n^2$ 量级的量 → 变成 $(c_2+1)n^2$。
>
> 也就是说，**只需要把 $c_1$、$c_2$ 换一组新的常数，不等式依然成立** ——因此结果仍然满足 $\Theta(n^2)$ 的定义。
> 记住这个技巧：**遇到 $\Theta$ 与 $O$ 混合运算想不通时，回到 $c_1,c_2$ 的定义去夹一夹。**

> [!important] My Own Experience：$\Theta$ 与 $O$ 到底该报哪个
> - 谈算法复杂度时，我们真正想知道的是 **$\Theta$** ——因为现实中我们对问题规模有直观判断，需要的是确切的阶。
> - 但如果你的算法是 $\Theta(n^2)$，你愿意对外说它是 $O(n^3)$ 吗？**不愿意**——那虽然"正确"却毫无信息量，等于自贬（就像说"我身高不超过 3 米"）。
> - 那说成 $O(n^2)$ 呢？**愿意**。$O$ 描述的是**最坏情况**，说 $O(n^2)$ 会给人"最坏才这么久、平常可能更快"的印象，而事实上你每次都跑满 $n^2$。
>
> 结论：**学术与工程习惯上写 $O$，但心里要清楚真实的阶是 $\Theta$。** 详见 [[C1.5 算法与渐进分析]] 中"大 $O$ 的实践含义"。

## 五、函数调用 Functions

> [!important] 函数调用的开销
> 调用一个子程序需要：准备环境 → 处理参数 → 跳转 → 执行 → 处理返回值 → 清理。
> 幸运的是现代处理器都有专门指令一次完成大部分步骤，因此我们**假定一次函数调用与返回的开销是 $\Theta(1)$**。

> [!note] 这个假设的边界（拓展）
> $\Theta(1)$ 指的是**调用机制本身**（压栈、跳转），不含函数体的执行时间。真实开销包括压参、保存返回地址、建立栈帧——这也是为什么编译器要做**内联 (inline)** 优化，以及为什么递归比循环慢。

## 六、递归函数 Recursive Functions

### 6.1 阶乘：$T(n)=T(n-1)+1$

```cpp
int factorial( int n ) {
    return (n <= 1) ? 1 : n * factorial( n – 1 );
}
```

设运行时间为 $T(n)$，则
$$T(n)=T(n-1)+1,\qquad T(1)=1$$
可推出 $T(n)=\Theta(n)$。

> [!note] 课件省略的展开（自己补）
> $T(n)=T(n-1)+1=T(n-2)+2=\dots=T(1)+(n-1)=n$。
> **递推式的写法**：`T(规模缩小后的规模) + 本层非递归部分的代价`。这里本层只做一次乘法和一次比较，是 $\Theta(1)$，写作 1。
> 直观理解也很容易：每次只把规模减 1，一直减到 1 就结束，所以总共调用 $n$ 层，**$O(n)$**。

### 6.2 二分查找：$T(n)=T\!\left(\frac{n-1}{2}\right)+\Theta(1)$

> [!important] 递推式是怎么列出来的
> 回想二分查找的过程：**每次把搜索范围砍掉一半**，也就是规模变成原来的一半（准确地说，去掉中间那一个之后再对半分，即 $(n-1)/2$）。
> 除递归调用之外的那部分代码（算中点、比较、决定走哪半边）**都是 $\Theta(1)$**。
> 把这两件事拼起来，就得到
> $$T(n)=T\!\left(\frac{n-1}{2}\right)+\Theta(1)$$
> 最终解出 $T(n)=\Theta(\log n)$。

> [!important] 问题设定
> 对有序表做二分查找：检查中间元素；若未找到，则视情况检查左半或右半。因此
> $$T(n)=T\!\left(\frac{n-1}{2}\right)+\Theta(1)$$
> 推导后得到 $\Theta(\ln n)$。

**完整求解过程（课件逐页给出，这里补全每一步的理由）**：

$$T(n)=\begin{cases} 1 & n=1 \\[4pt] T\!\left(\dfrac{n-1}{2}\right)+1 & n>1 \end{cases}$$

一般情况下这类递推式很难解，因此**只考虑特殊的 $n$**：

> [!important] 关键技巧：假设 $n=2^k-1$
> 令 $n=2^k-1$（$k$ 为整数），则
> $$\frac{n-1}{2}=\frac{2^k-1-1}{2}=\frac{2^k-2}{2}=2^{k-1}-1$$
> **形式保持不变**——规模仍然是"$2$ 的幂减 1"的形状，于是可以一层层套下去。

课件的具体例子：查找长度为 **31** 的表，先查中间；若未找到，要查两半之一，每半长 **15**。而
$$31=2^5-1,\qquad 15=2^4-1$$

展开：
$$\begin{aligned}
T(n)&=T(2^k-1)\\
&=T\!\left(\frac{2^k-1-1}{2}\right)+1 = T(2^{k-1}-1)+1\\
&=T\!\left(\frac{2^{k-1}-1-1}{2}\right)+1+1 = T(2^{k-2}-1)+2\\
&\;\;\vdots\\
&=T(2^{k-3}-1)+3
\end{aligned}$$

于是一般地，经过 $k-1$ 步后：
$$T(n)=T(2^k-1)=T\bigl(2^{k-(k-1)}-1\bigr)+k-1=T(1)+k-1=k$$
因为 $T(1)=1$。

> [!important] 最后一步：把 $k$ 换回 $n$
> 由 $n=2^k-1$ 得 $2^k=n+1$，故
> $$k=\lg(n+1)$$
> 再用 $\Theta$ 的极限定义验证 $\lg(n+1)$ 与 $\ln n$ 同阶（课件用洛必达法则）：
> $$\lim_{n\to\infty}\frac{\lg(n+1)}{\ln(n)}=\lim_{n\to\infty}\frac{\dfrac{1}{(n+1)\ln 2}}{\dfrac{1}{n}}=\lim_{n\to\infty}\frac{n}{(n+1)\ln 2}=\frac{1}{\ln 2}$$
> 极限是有限正数，因此
> $$T(n)=\Theta(\lg(n+1))=\Theta(\ln n)$$

> [!note] 这段推导里三个必须懂的点
> 1. **为什么要假设 $n=2^k-1$**：为了让 $(n-1)/2$ 保持同样的形状，递推能干净地套下去。这不是耍赖——因为 $T(n)$ 单调，任意 $n$ 都被夹在两个 $2^k-1$ 之间，结论对一般 $n$ 同样成立（课件没说，但这是严格性的关键补丁）。
> 2. **为什么最后还要算个极限**：因为答案 $\lg(n+1)$ 里既有"+1"又有底数 2，必须验证它与 $\ln n$ 同阶才能写成 $\Theta(\ln n)$。**结论层面不必纠结对数的底**——以 2、以 e、以 10 为底写出来都对，因为所有对数函数都落在**同一个 $\Theta$ 等价类**里（换底只差一个常数因子）。这正是 [[C1.5 算法与渐进分析]] 里 $\Theta$ 极限定义的直接应用——**先解出精确解，再用 $\Theta$ 化简**。
> 3. **求导那一步**：$\dfrac{d}{dn}\lg(n+1)=\dfrac{1}{(n+1)\ln 2}$（因为 $\lg x=\ln x/\ln 2$），$\dfrac{d}{dn}\ln n=\dfrac 1n$。这是洛必达法则（$\infty/\infty$ 型）。

### 6.3 解递推式的通用套路（补充：主定理）

> [!note] Master Theorem 主定理（拓展）
> 对 $T(n)=aT(n/b)+f(n)$：
> - 二分查找：$a=1,b=2,f=\Theta(1)$ → $T(n)=\Theta(\log n)$
> - 归并排序：$a=2,b=2,f=\Theta(n)$ → $T(n)=\Theta(n\log n)$
> - 二叉树遍历：$a=2,b=2,f=\Theta(1)$ → $T(n)=\Theta(n)$
>
> 后面讲树和排序时会不断用到，现在先建立"**列递推式 → 展开 → 代入边界 → 化简为 $\Theta$**"这个四步流程。

## 七、Take Home Message（三句总结）

> [!important] 课件原文
> 1. Use your intelligence to calculate **how many $O(1)$ codes are executed**.（动脑数一数有多少段 $O(1)$ 的代码被执行了。）
> 2. Do **not care much about the constant theoretically**, care it **practically**.（理论上别太在意常数，实践中要在意。）
> 3. **Remember the complexities of some well-known codes and algorithms.**（记住常见代码和算法的复杂度。）

> [!note] 第二句是全节的精髓
> 理论上 $\Theta(n)$ 和 $\Theta(100n)$ 同阶；实践中差 100 倍。**做真实系统时必须考虑常数。**
> 给一个判断标准：**如果某个算法的常数系数是 100 万，而你现实中面对的问题规模只有 10 万，那这个常数比问题规模本身还大，你当然必须考虑它。**
> 第三句"记住经典算法的复杂度"同理：后面会学很多经典结构与算法，**把它们的复杂度结论直接记住**，用的时候不必每次都重新分析一遍。
> **【拓展】** 做 AI 尤其明显：算子融合、混合精度、内存布局优化，全都是在优化常数，因为算法的阶已经压不下去了。

## 本节自测 Self-Test

> [!question] Q1：`for(i=0;i<n;i++) for(j=0;j<i;j++) sum++;` 的复杂度？给出求和过程。
> **A**：$\sum_{i=0}^{n-1} i=\frac{n(n-1)}{2}=\Theta(n^2)$。

> [!question] Q2：$O(n^2)+\Theta(n)$ 等于什么？为什么不是 $\Theta(n^2)$？
> **A**：$O(n^2)$。因为 $O(n^2)$ 那一项的真实阶未知（可能远小于 $n^2$），下界无法确定，只能给上界。

> [!question] Q3：为什么解 $T(n)=T((n-1)/2)+1$ 时要假设 $n=2^k-1$？
> **A**：这样 $(n-1)/2=2^{k-1}-1$，形状保持不变，递推可以逐层套用；且由单调性可推广到一般 $n$。

> [!question] Q4：串行代码段的复杂度怎么算？举例说明。
> **A**：各段相加，结果取最高阶。如 `update_capacity` 是 $\Theta(1)+\Theta(n)+\Theta(1)=\Theta(n)$。

> [!question] Q5：为什么 `delete[] array_old` 被标为 "Θ(1) or O(n)"？
> **A**：若元素类型有非平凡析构函数，需逐个析构，$O(n)$；平凡类型可整块释放，$\Theta(1)$。

> [!question] Q6：写一个循环里带 `break` 的查找，其复杂度应该用 Θ 还是 O？
> **A**：用 $O(n)$。因为可能提前退出，下界不确定。

> [!question] Q7：课件里 switch 有 5 个固定分支，为什么标 $O(n)$？
> **A**：那里的 $n$ 指 case 的数量。若分支数随问题规模增长才是 $O(n)$；固定 5 个分支就是 $O(1)$。

> [!question] Q8：空间复杂度为什么不把数据本身占的 $n$ 算进去？
> **A**：因为处理规模为 $n$ 的数据，任何算法都必须占用这 $n$ 个单元，对所有算法都一样；空间复杂度比较的是**额外空间**。

> [!question] Q9：$O(n^2)+\Theta(n^2)$ 为什么仍是 $\Theta(n^2)$？用定义说明。
> **A**：$O(n^2)$ 那一项最小为 0、最大为 $n^2$ 量级，加入后只需把 $\Theta$ 定义中的 $c_1,c_2$ 换一组常数，夹逼不等式依然成立。

> [!question] Q10：`find_max` 到底是不是"取决于数据"？
> **A**：整体是确定性的 $\Theta(n)$（每个元素都必须检查）；只有 `max = array[i];` 那一行的执行次数取决于数据。
