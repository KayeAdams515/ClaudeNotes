# 数据结构训练营 · 训练手册

> [!info] 这个文件夹是什么
> [[数据结构 MOC|数据结构]] 那个文件夹是**讲义轨道**：用来读、用来查、用来复习。
> 这个文件夹是**训练轨道**：用来写、用来跑、用来报错。
>
> 两条轨道绑在一起用，但绝不混用：
> **看讲义 → 来这里写代码；卡住了 → 回讲义查口径；写完了 → 回讲义核对。**

> [!important] 一句话说明它为什么存在
> 你上课能听懂、讲义看得懂，但合上就写不出来。这不是理解问题，是**没有亲手写过**。
> 这个训练营只解决一件事：**让你每天都有 30–45 分钟在写代码，并且立刻知道自己写得对不对。**

## 一、核心规则（先看这一节，其他都可以后看）

### 规则 1：只准看 A 档和 B 档，C 档是最后才允许碰的

每个模块里都有三层：

| 档位 | 是什么 | 什么时候用 |
| --- | --- | --- |
| **A–脚手架** | 函数签名 + 提示注释，函数体空着 | **主战场。** 从 A 档开始写 |
| **B–参考** | 完整可编译的正确实现 | **只在卡住超过 20 分钟、或想核对写法时看** |
| **测试** | 自动判定对错 | 每写完一个函数就立刻跑 |

> [!warning] 最重要的一条
> **不要抄参考实现。** 抄一遍等于没写，还会给你"我懂了"的错觉。
> 正确用法是：写完 → 跑测试 → 红了 → 自己查 → **再看参考** → 关掉参考 → **默写一遍**。

### 规则 2：每个函数写完立刻跑测试，不要攒着

```bash
cd 数据结构训练营/M1-线性表
make test       # 跑全部关卡
make test-1     # 只跑第 1 关
```

看到 `全部通过` 才算过关。红了就是错了，**不是环境问题，是你的代码问题**——这正是训练营的价值。

### 规则 3：每关都要过"裸写"验收，才算真的过关

测试跑绿只说明"这次写对了"。真正的验收是：

> **合上所有文件、关掉参考实现，在白纸或空文件里从零默写这个数据结构，编译通过。**

默写不过关就**重来一遍，不要推进**。进度宁可慢，不能虚。

### 规则 4：把编译器当老师，不要怕红字

第一次一定会遇到一堆报错和段错误。这不是你笨，这是所有人的必经路径。
最常见的三种，先有个心理准备：

| 症状 | 几乎一定是 |
| --- | --- |
| `Segmentation fault` | 访问了野指针 / NULL，或者越过链表尾部 |
| `undefined reference` | 函数声明了没实现，或者模板实现写进了 `.cpp` |
| 结果全错但不崩溃 | 循环边界差一（`<` 写成 `<=`） |

## 二、每周节奏（每天 30–45 分钟）

| 时间 | 做什么 | 用时 |
| --- | --- | --- |
| 周一 | 读对应讲义，**在纸上画图**（把指标、指针画出来） | 30 min |
| 周二–周五 | 每天推进 1–2 个小函数：写 → 跑测试 → 改 | 30–45 min |
| 周六 | 把本周的类**从头默写一遍**，不看任何东西 | 45 min |
| 周日 | 补齐这周没懂的地方，回讲义核对，更新自己的错题本 | 30 min |

> [!tip] 卡住的标准动作
> 1. 先看报错原文（**不要跳过，逐字读**）
> 2. 在纸上画一遍指针/下标的走向
> 3. 打印中间变量看一眼
> 4. 还不行才看参考实现，**并且看完立刻关掉重写**

> [!note] 顺序为什么这么排

> 第三阶段的内容对应你 `pdfs/` 里那批还没做成讲义的课件，等讲义补齐再建模块。

## 四、开始之前：环境自检

在终端里跑一次这个，三条都要有输出：

```bash
cd 数据结构训练营/M1-线性表
make test-ref
```

正常应该看到最后一行是 **`全部通过`**。
这条命令跑的是**参考答案**——如果你连它都跑不过，说明环境有问题，不是你的代码问题。

> [!warning] 如果 `make test-ref` 失败了
> 说明编译器或路径有问题，先解决这个再开始，否则你分不清"是我错了"还是"环境错了"。

### 现在就可以做的第一件事

```bash
cd 数据结构训练营/M1-线性表
make test          # 会看到满屏的红——这是【正常】的起点，不是坏事
```

然后打开 [[关卡说明]] 的「S1 · 构造、析构、简单函数」，
对照着改 `sqlist.h` 里的 `TODO 1`，改完跑 `make test-1`。

> [!tip] 满屏的红不是打击，是路线图
> 每一行红字都是一句精确的"你这里还不对"。
> 绿灯一盏盏亮起来的过程，就是你的代码能力长出来的过程。

## 五、目录结构说明

```
数据结构训练营/
├── 00 训练手册.md          ← 你正在看
├── testkit/testkit.h       ← 极简测试框架（不用管它）
└── M1-线性表/
    ├── 关卡说明.md          ← 每一关要你实现什么、考点是什么
    ├── makefile
    ├── sqlist.h            ← 【你要写的文件】顺序表
    ├── ll.h                ← 【你要写的文件】单链表
    ├── sqlist_ref.h        ← 参考答案，卡住了才看
    ├── ll_ref.h            ← 参考答案，卡住了才看
    ├── test_sqlist.cpp     ← 测试题，不用改
    └── test_ll.cpp         ← 测试题，不用改
```

> [!important] 你唯一要修改的文件
> `sqlist.h` 和 `ll.h` 这两个**脚手架头文件**。其他文件都是给你用的工具，不要改。
> 测试文件里的断言就是"题目要求"，**读测试文件本身就是读题**。
>
> 测试文件通过两个**只读访问器** `headNode()` / `tailNode()` 来核对
> "尾巴有没有接对"。这俩已经给你实现好了，不用动——
> 真实的工程里也不会把 `head` 直接暴露出去（否则外面能随意改内部指针）。
