> [!info] 这个模块有两组关卡，共 9 关

# 顺序表 SqList

对应讲义：[[C2.4 顺序表实现]]（接口总览见 [[C2.3 线性表 ADT]]）

## S1 · 构造、析构、简单函数

**要写的**：`SqList(int capacity)`、`~SqList()`、`empty()`、`getLength()`、`getCapacity()`、`clear()`

**核心考点**
- 构造函数三件事：开数组、记容量、**长度置 0**（不是置 capacity）
- 析构用 `delete[]` 而不是 `delete`
- `clear()` **不释放内存**、容量不变，只是把长度归零

**跑**：`make test-1`

**过关自问**：为什么新构造的表 `length` 是 0 而不是 capacity？
<details><summary>答案</summary>capacity 是"预定的座位数"，length 是"实际坐了几个人"。刚开的店一个客人都没有。</details>

## S2 · 取值与查找

**要写的**：`get(int index)`、`find(T x)`

**核心考点**
- `get` 的合法下标是 $[0,\ \text{length}-1]$，**不是** $[0,\ \text{capacity}-1]$
  （已分配但没装数据的格子读出来是垃圾值）
- `find` 找不到返回 **-1**，这是"哨兵值"的用法
- 这两个是互逆操作：Retrieve 给下标要元素，Find 给元素要下标

**跑**：`make test-2`

**过关自问**：为什么 `get` 是 $O(1)$，`find` 是 $O(n)$？
<details><summary>答案</summary>get 靠地址公式直接算位置；find 必须逐个比，运气好第一个命中，运气差要走完全程。</details>

## S3 · 插入与删除

**要写的**：`insert(T x, int index)`、`erase(int index)`

**核心考点（本模块最容易错的一关）**

| | insert | erase |
| --- | --- | --- |
| 合法下标 | $[0,\ \text{length}]$ ← 可以等于 length | $[0,\ \text{length}-1]$ |
| 搬移方向 | **从后往前**（右移） | **从前往后**（左移） |
| 长度 | `length++` | `length--` |

- 插入时 `index == length` 表示**追加到末尾**，是合法的——这个"差一"就是考点
- 搬移方向写反的后果：插入会把一个值复制满整个数组；删除会把元素复制反
- 别忘了 `length++` / `length--`

**跑**：`make test-3`

**过关自问**：插入的平均移动次数是 $n/2$，删除是 $(n-1)/2$，为什么分母不一样？
<details><summary>答案</summary>插入有 $n+1$ 个空隙可选（含末尾之后），删除只能从 $n$ 个已存在元素里挑。</details>

## S4 · 进阶：扩容

**要写的**：不是改类，而是**用测试里的代码手动模拟扩容**

**核心考点**
- 扩容的套路：开一个更大的数组 → 把旧数组的**前 length 个**元素搬过去
- **最容易犯的错**：搬了 capacity 个，把没装数据的垃圾值也搬了过去

**跑**：`make test-4`（同时会跑 LL 的 L4）

**选做**：如果你想让类自己会扩容，给 `SqList` 加一个 `void grow()`，
在 `insert` 判满时调用它（容量翻倍）。这样 `insert` 在满表时就不再返回 false 了。
讲义 [[C2.4 顺序表实现]] 六节的原话是：课件写法直接 `return false`，
工业实现（如 `vector`）会在这里触发扩容，代价 $\Theta(n)$。

# 单链表 LL

对应讲义：[[C2.5 单链表实现]]

> [!warning] 三个课程约定，写之前必须记住
> 1. **不带头结点**：`head` 直接指向首元结点，空表就是 `head == NULL`。
>    代价是"在表头增删"必须特判，因为要改的是 `head` 这个变量本身。
> 2. **有尾指针 tail**：尾插从 $O(n)$ 降到 $O(1)$。
>    代价是每个动到表尾的操作都要同步 `tail`——**这是本模块最大的失分点**。
> 3. **先连后断**：插入时先让新结点抓住后面的链，再让前驱改口。

## L1 · 骨架、遍历、查找

**要写的**：`LL()`、`~LL()`、`empty()`、`getLength()`、`find(T x)`、`clear()`

**核心考点**
- 构造：三个成员都要初始化，**`head` 和 `tail` 都必须是 NULL**
- 析构：**必须"留住后路"**——先存下一结点地址，再删当前结点
  ```cpp
  Node* temp = cur;   // 先留住后路
  cur = cur->next;
  delete temp;
  ```
  写成 `delete head; head = head->next;` 就是访问已释放内存
- `find` 的循环条件是 `while (ptr != NULL)`——**忘判 NULL 就是段错误**，这是遍历链表的标准写法
- `clear()` 和顺序表的完全不同：**必须真的 delete 每个结点**，否则内存泄漏

**跑**：`make test-1`（同时会跑 SqList 的 S1）

**过关自问**：为什么析构里不能先 `delete` 再取 `next`？
<details><summary>答案</summary>delete 之后那块内存已经还给系统了，再读它的 next 就是读已释放内存（悬垂指针），未定义行为。</details>

## L2 · 按下标取值

**要写的**：`get(int index)`

**核心考点**
- 合法下标 $[0,\ \text{length}-1]$，越界 `exit(EXIT_FAILURE)`
- 从 head 出发走 **index 步**（head 自己就是下标 0）
- 循环写 `i < index` 还是 `i <= index`，**差一步就走到 NULL 上**
- 这是"顺序存取"的直观体现：取最后一个元素要走 $n$ 步

**跑**：`make test-2`

## L3 · 插入（头、中、尾）

**要写的**：`insert(T x, int index)`

**核心考点（本模块最容易错的一关）**
- 合法下标 $[0,\ \text{length}]$，和 SqList 口径一致
- 三个分支，这就是"不带头结点"的代价：
  - **头插**（`index == 0`）：改的是 `head` 本身
    ★ **空表时 `tail` 也要指过来**，漏了这一步后面尾插必崩
  - **尾插**（`index == length`）：用 `tail` 直接 $O(1)$ 完成，不用遍历
    ★ 空表时 `tail` 是 NULL，`tail->next = s` 会崩
  - **中间插**：走 `index-1` 步停在前驱 `p`，然后
    ```cpp
    s->next = p->next;   // 先连
    p->next = s;         // 后断
    ```
    ★ 这两句**不能交换**，交换就丢失后半段链表

**跑**：`make test-3`

**过关自问**：为什么循环是 `index-1` 步而不是 `index` 步？
<details><summary>答案</summary>要停在【前驱】上，前驱的下标是 index-1；停在目标位置就没法改它前驱的 next 了。</details>

## L4 · 删除（头、中、尾）

**要写的**：`erase(int index)`

**核心考点**
- 合法下标 $[0,\ \text{length}-1]$，非法就什么都不做
- **删头结点**：要改 `head` 本身；★ 如果删完表空了，`tail` 也必须置 NULL
  （否则 tail 就悬垂了，下一次尾插必崩）
- **删其它结点**：
  ```cpp
  Node* ptr = p->next;   // 先记住要删的那个
  p->next = ptr->next;   // 跨过它
  delete ptr;            // 最后才删
  ```
  ★ 顺序错了就是访问已释放内存。这是"先接后删"，和插入的"先连后断"是同一条定律的两面
- ★ **删的是尾结点时，必须把 `tail` 更新成前驱 `p`**

**跑**：`make test-4`

**过关自问**：删掉尾结点后如果不更新 tail，会发生什么？
<details><summary>答案</summary>tail 指向一块已经释放的内存（悬垂指针），下一次尾插写 tail->next 就写入已释放内存，行为不可预测。</details>

## L5 · 进阶：反转链表、约瑟夫环

**要写的**：成员函数 `LL<T>::reverse()`、独立函数 `int josephus(int n, int m)`（都在 `ll.h` 中）。

`reverse()` 改变当前链表；`josephus()` 自行创建、释放模拟用的结点，不依赖已有链表，直接调用 `josephus(8, 3)`，不用先创建 `LL` 对象。独立函数在头文件中定义，保留签名前的 `inline`，避免多个源文件包含时出现重复定义。

**reverse 核心考点**
- 三指针标准写法：`prev` / `cur` / `nxt`，每轮先"留住后路"再掉头
- 循环结束后：新的 `head` 是 `prev`，新的 `tail` 是**原来的 head**
  ★ 忘更新 `tail` 是这一关最常见的错

**josephus 核心考点**
- `n <= 0` 或 `m <= 0` 时返回 `-1`；有效输入使用整数编号 `1..n`。
- 可以用局部 `Node<int>*` 自行建环并释放全部结点；若用局部 `LL<int>`，须正确维护它的结构与结点所有权，不能让普通链表析构函数遍历一个尚未断开的环，也不能重复释放结点。
- 需要**循环链表**：最后让 `tail->next = head`，首尾相接
- 数 $m$ 个出列 → 从当前起点算，起点本身算第 1 个，所以先**挪 $m-1$ 步**再删
  ★ 挪 $m$ 步是最常见的差一错误
- ★ 循环链表的终止条件**不能**用 `ptr == NULL`（永远不成立，会死循环），
  要用"还剩几个结点"来数
- 讲义给的核对值：$n=8, m=3$ → 幸存者编号 **7**（从 1 开始编号）

**跑**：`make test-5`

**选做**：约瑟夫环还有一个 $O(n)$ 的递推解法 $J(1)=1$，$J(n)=((J(n-1)+m-1)\bmod n)+1$，
不需要任何数据结构。写出来和链表解法对拍一下，看看结果是否一致
（讲义 [[C2.5 单链表实现]] 十三节有完整推导）。

## 卡住时的排查顺序

1. **逐字读那条红字**——测试的说明就是题目要求，它告诉你期望值是什么
2. **看行号**，去 `test_ll.cpp` 找到那一行，看它前面几行在准备什么数据
3. **在纸上画**：把 `head → A → B → C` 画出来，标注每根指针，然后手动执行你的代码
4. **打印中间变量**：`std::cout << "index=" << index << " p=" << p->data << std::endl;`
5. 还不行才看 `sqlist_ref.h` / `ll_ref.h`，结合注释解释变量含义和分支组织，再回自己的文件理解后改写；独立复写留到二轮

> [!tip] 段错误（Segmentation fault）的排查口诀
> 段错误几乎都是"在 NULL 上取了成员"。问自己三个问题：
> **这个指针现在可能是 NULL 吗？我判过它了吗？空表/单元素/删光了这三种情况我处理了吗？**
