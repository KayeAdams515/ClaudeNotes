# C11.5 Kruskal 算法

> [!abstract] 这一讲的任务
> 上一讲的 Prim 是"**先把树围起来，再往外找最近的**"：树只有一个，一次长一个点。
> Kruskal 换了个方向，笨得多也简单得多：**把所有边按权从小到大排好，一条条试着加，加进去会成环就跳过**。加到够 $n-1$ 条就停。
> 这个"笨"办法能成立，靠的是两件事：一是上一讲的割性质（换成"按边排序"的说法仍然成立），二是一个几乎 $O(1)$ 的判环工具——并查集。于是整条复杂度落在**排序** 上，图遍历、并查集、排序这三块知识在这里合流。

## 算法只有三句话

> [!important] Kruskal 算法
> 1. 把**所有边** 按权值从小到大**排序**；
> 2. 准备一个空图（只有 $n$ 个顶点、没有边）；
> 3. 按排序顺序逐条考察每条边：**若加入它不会形成环**，就把它加进图里；否则跳过。
> 4. 加满 $n-1$ 条边时停止。

和 Prim 摆在一起看，差别一目了然：

| | Prim | Kruskal |
| --- | --- | --- |
| 长什么 | 一棵不断长大的树 | 一开始一堆孤立点，边一条条把点连起来 |
| 选边的依据 | 跨割最小（离树最近） | **全局最小**（下一便宜的那条） |
| 判据 | 有新点可连 | 不形成环 |
| 需要的数据结构 | 优先队列（或扫描表） | **并查集** + 排序 |

两种都是贪心，但贪心的对象不同：Prim 贪"离已连部分最近的边"，Kruskal 贪"全局最便宜的边"。它们都对，因为**都满足割性质**——挑的每条边都是某个割上的最小边。

### 三个值得停一下的地方

**第 6 步：两块大树第一次相遇。** 前五步并出了 $\{B,C,E\}$ 和 $\{F,G,H,I\}$ 两块，$E{-}H$ 是它们之间最便宜的通道，加进去两块并成一块。这就是"并查集的 union"在几何上的样子。

**第 7 步：第一次跳过。** $B$ 和 $C$ 早就在 $\{B,C,E\}$ 里了——再加 $B{-}C$，它们之间就有两条通路，环成。**这正是判环的全部逻辑：不用真的去搜环，只要问一句"两端是不是已经连上了"。**

**第 17 步与第 20 步：为什么中间空了那么多步。** 第 16 步之后，$A\sim L$ 里只剩 $A$ 和 $J$ 两个孤立点。所以 17 到 20 步之间能连的只有 $J{-}K$ 和 $A{-}B$。这也解释了为什么第 18、19 步（$J{-}I$、$J{-}G$）全被跳过——$J$ 在第 17 步已经并进去了。

## 判环：从"搜一遍"到"问一句"

同一个"会不会成环"，两种做法的代价差得很远。

### 笨办法：每加一条边就 DFS 一次

想判断加入 $(u,v)$ 会不会成环，可以在已有的森林里从 $u$ 出发做一次 DFS：**若能走到 $v$，就说明 $u,v$ 已经连通，加这条边必成环**。

一次 DFS 是 $O(|V|+|E|)$，最坏对每条边都做一次，总代价 $O(|E|\cdot(|V|+|E|))=O(|E|^2)$。

排序才 $O(|E|\ln|E|)$，判环反而成了瓶颈——**主次颠倒了**。

### 好办法：并查集

上一章讲过的并查集，把"连通"这件事维护成一个划分：

- 一开始每个顶点各自一个集合；
- 每加一条边 $(u,v)$，就把这两个集合**合并**；
- 判"$u,v$ 是否已经连通"，就是 `find(u) == find(v)`。

代价是均摊 $O(\alpha(|V|))\approx O(1)$。于是整条算法变成：

```cpp
for (每条边 e = (u, v, w)，按 w 升序) {
    if (find(u) != find(v)) {   // 不在同一棵树里
        mst.add(e);             // 加入生成树
        set_union(u, v);        // 合并两个集合
        if (mst.size() == n - 1) break;
    }
}
```

判环与合并被压缩成一个 `if`。**这是"并查集为什么值得单开一章"最直接的回答。**

## 代价

| 阶段 | 代价 | 说明 |
| --- | --- | --- |
| 排序 | $O(\lvert E\rvert\ln\lvert E\rvert)$ | 用快排；若用分配排序可降到 $O(\lvert E\rvert)$ |
| 判环 + 合并 | $O(\lvert E\rvert\,\alpha(\lvert V\rvert))$ | 每条边一次 `find` 两次、`union` 至多一次 |
| 总计 | $O(\lvert E\rvert\ln\lvert E\rvert)$ | 排序占绝对主导 |

因为 $|E|\le|V|^2$，所以 $\ln|E|\le2\ln|V|$，也可以写成

$$O\bigl(|E|\ln|V|\bigr).$$

这个式子与 Prim 用二叉堆的界是一样的。两者的取舍：

- **稀疏图**：$|E|$ 小，Kruskal 的排序便宜，且实现比 Prim 短，**实践中更常用**；
- **稠密图**：$|E|\approx|V|^2$，Kruskal 要存下所有边并排序，而 Prim 用数组是 $O(|V|^2)$、不用存边——**稠密图偏向 Prim**。

> [!note] 为什么"排序"这一步躲不掉
> 有人会想：既然只要最小的 $n-1$ 条边，能不能边生成边挑、不排序？
> 不行。MST 的正确性依赖"每次取全局最便宜且不成环的边"，而这个"全局"需要一个顺序。Prim 绕开了全局排序，代价是它得反复做"取最近"（优先队列）；Kruskal 绕开了优先队列，代价是它得排序。**两条路的总代价相当，只是把成本放在了不同的地方。**

## 与 Prim 的对照

| 维度 | Prim | Kruskal |
| --- | --- | --- |
| 生长方式 | 单点长成树，始终连通 | 森林逐步合并 |
| 选边 | 跨割最小 | 全局最小 |
| 判据 | 有新点可连 | 不成环 |
| 核心结构 | 优先队列 / 扫描表 | 并查集 + 排序 |
| 代价 | $O(\lvert V\rvert^2)$ 或 $O(\lvert E\rvert\ln\lvert V\rvert)$ | $O(\lvert E\rvert\ln\lvert E\rvert)$ |
| 中途状态 | 永远是一棵**连通的树** | 一片**森林** |
| 不连通时 | 得到一个分量的树，换起点重跑 | 直接得到**生成森林**，不用改代码 |
| 适合 | 稠密图 | 稀疏图 |

表格里有一行最容易被忽略：**Kruskal 天然处理不连通图**。它跑完时如果边数不到 $n-1$，剩下的顶点就各自是一个分量——得到的正是生成森林，不需要额外判断。Prim 则必须显式地换起点重跑。

## 勘误

| 位置 | 原稿 | 更正 | 性质 |
| --- | --- | --- | --- |
| 复杂度页的排序成本 | "using quicksort, the run-time is $O(\lvert E\rvert\ln\lvert E\rvert)$" | 正确；但材料没说明 $\lvert E\rvert$ 与 $\lvert V\rvert$ 的关系，也没给出 $O(\lvert E\rvert\ln\lvert V\rvert)$ 这个等价写法 | 表述不完整 |
| 判环的"笨办法" | 只说"我们可以用 DFS 检查"，没算代价 | 每条边一次 DFS 是 $O(\lvert E\rvert^2)$，比赛排序还贵——这正是引入并查集的动机，应当写明 | 论证跳步 |
| 例子的收尾 | 第 20 步加完 $A{-}B$ 后直接终止 | 正确；但 $A{-}D$、$E{-}F$ 两条边还没考察，"加了 $n-1$ 条就停"是提前退出的依据，需要点明 | 表述不完整 |
| 页面右侧的边表 | 排序后的边表只列端点、不列权值 | 权值在图上，读表时要在图与表之间来回找；讲义已按权值补全成一张表 | 排版不便 |

## 速查

| 项目 | 内容 |
| --- | --- |
| 输入 | 连通（或不连通）带权无向图 |
| 输出 | 最小生成树（或不连通时的最小生成森林） |
| 步骤 | 排序 → 逐条判环 → 加够 $n-1$ 条停 |
| 判环 | `find(u) != find(v)` |
| 合并 | `set_union(u, v)` |
| 时间 | $O(\lvert E\rvert\ln\lvert E\rvert)$ |
| 空间 | $O(\lvert V\rvert+\lvert E\rvert)$（要存下所有边） |
| 例子 | 12 顶点、加 11 条、总权 $85$ |
| 不连通时 | 自动得到生成森林，边数 $<n-1$ |

## 下一讲

生成树回答的是"**怎么把所有点连起来最省**"。下一个问题换了一个方向：**从一个点到另一个点，怎么走最快**。

两件事看着像，其实完全不同：生成树要照顾所有顶点，最短路只关心两个端点；生成树看的是"边的总长"，最短路看的是"路径的总长"。而且一旦有向、有负权，贪心会遇到麻烦。下一讲先讲最经典的那个——Dijkstra，以及它为什么"每次取最近"是对的。
