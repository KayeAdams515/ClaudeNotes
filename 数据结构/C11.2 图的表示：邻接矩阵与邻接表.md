# C11.2 图的表示：邻接矩阵与邻接表

> [!abstract] 这一讲的任务
> 上一讲把图的词定完了，但一个抽象的 $G=(V,E)$ 在内存里长什么样，还没说。
> 这一讲给三种答案：把所有边装进一个容器（最省事、最慢）、开一张 $n\times n$ 的表（判邻最快、内存平方级）、给每个顶点挂一条邻居链（算法的默认选择）。中间夹着一块 C++ 的硬骨头：**二维数组在 C++ 里并不存在**，只有"数组的数组"，所以要写 `double**`、要 `new` 两次、`delete` 两次。最后落到真实规模上：广州所有路口当顶点，矩阵里 $99.999\%$ 的格子都存着"无穷远"——这时候要换稀疏表示。

## 同一个问题的三种答案

先确定一个用来对照的图：**6 个顶点、9 条带权边**。

![[C11-示例图-六顶点九边.png]]

| 边 | 权 | 边 | 权 | 边 | 权 |
| --- | --- | --- | --- | --- | --- |
| $\{0,1\}$ | $0.83$ | $\{1,2\}$ | $0.67$ | $\{2,3\}$ | $0.39$ |
| $\{0,3\}$ | $0.65$ | $\{1,3\}$ | $0.72$ | $\{3,4\}$ | $0.24$ |
| $\{0,5\}$ | $0.51$ | $\{1,4\}$ | $0.46$ | | |
| | | $\{1,5\}$ | $0.90$ | | |

三种表示都要能把这 9 条边一字不差地存进去，差别只在**哪一类操作快、内存要多少**。

## 邻接矩阵

> [!important] 邻接矩阵 Adjacency Matrix
> 开一个 $n\times n$ 的表 $A=(a_{ij})$。若 $v_i$ 与 $v_j$ 之间有边、权为 $w$，就令 $a_{ij}=a_{ji}=w$。

- 带权图存**权**；无向图必然**对称**（$a_{ij}=a_{ji}$）；有向图**不必对称**（$(v_i,v_j)$ 存在不影响 $(v_j,v_i)$）。
- 无权图可以把元素类型换成 `bool`：有边 `true`、无边 `false`，$O(1)$ 判邻。
- 内存 $\Theta(n^2)$——不管实际有多少条边。

这个"不管"是全部问题的根源：$n$ 个顶点的图最多只有 $n(n-1)/2$ 条边，而矩阵开了 $n^2$ 格。

### 没边的地方填什么

这是实现里第一个要决定的事，三个候选：

| 填法 | 好处 | 坏处 |
| --- | --- | --- |
| $0$ | 简单 | 与"权为 $0$ 的边"混淆 |
| $-1$ | 能区分 $0$ 权 | 权本身可能为负（Dijkstra 不能用负权，但别的算法可以） |
| $+\infty$ | **语义最顺**：两点不连通，距离就是无穷远 | 需要一个"足够大"的常数 |

第三个是材料的选择，理由值得记：**"不连通"与"距离无穷远"是同一件事**，这样 Dijkstra 里"尚未到达"就可以直接写成 `dist = INF`，不必再加一个布尔标记。

初始化时还有一个约定：**对角线置 $0$**（自己到自己的距离是 $0$）；无权的布尔矩阵则把对角线置 `true`（自己与自己"连通"）。

```cpp
for (int i = 0; i < N; ++i) {
    for (int j = 0; j < N; ++j) {
        matrix[i][j] = INF;
    }
    matrix[i][i] = 0;          // 自己到自己
}
```

> [!warning] 对角线置 $0$ 与"不允许自环"是两回事
> 上一讲定了"顶点不与自己相邻"，这里却把对角线填成"有边/距离 0"。这不是矛盾，而是两种不同的用途：
> - **邻接关系** 看的是有没有边，对角线应该是 `false` 或"无"；
> - **距离矩阵** 看的是最短距离，对角线应该是 $0$。
> 混用的时候要知道自己在用哪一种，否则"自己和自己相邻"会悄悄污染判断。

## C++ 里没有二维数组

这是本讲最容易被跳过、又最容易在实验课上绊倒的一段。

C++ 的数组只能是一维的。`matrix[3][4]` 的写法来自"**数组的数组**"：先有一个装指针的数组，每个指针再指向一行。所以要声明的类型是"指向指针的指针"：

```cpp
double **matrix;              // 指向"指针"的指针
matrix = new double *[16];    // 16 个指针，每个指向一行
for (int i = 0; i < 16; ++i) {
    matrix[i] = new double[16];   // 每行 16 个 double
}
```

下标表达式的类型是一层层剥开的：

| 表达式 | 类型 | 含义 |
| --- | --- | --- |
| `matrix` | `double**` | 指向"行指针数组"的指针 |
| `matrix[3]` | `double*` | 第 3 行的首地址 |
| `matrix[3][4]` | `double` | 第 3 行第 4 列的值 |

`matrix[3][4]` 可以读成 `(matrix[3])[4]`：先取出第 3 行的指针，再在这行里取第 4 个元素。

释放的时候必须**一一对应**：每个 `new[]` 配一个 `delete[]`，所以也是两轮：

```cpp
for (int i = 0; i < 16; ++i) {
    delete[] matrix[i];       // 先删每一行
}
delete[] matrix;              // 再删指针数组
```

只写 `delete matrix;` 会漏掉 16 行，而且 `new[]` 配 `delete`（不带方括号）是未定义行为。

### 这张矩阵在内存里长什么样

![[C11-邻接矩阵-数组的数组.png]]

上图是 6 个顶点的例子：左边那张指针数组里存着 6 个地址，每个地址指向单独分配的一行。**这 6 行在内存里可能相隔很远**——它们不是一次 `new` 出来的连续空间。

这正是"数组的数组"与"二维数组"的实质区别，而它有三个后果：

1. **不连续**：`matrix[2]` 的末尾接不上 `matrix[3]` 的开头，所以不能对整张表做一次 `memcpy`、也不能指望一次 `delete[]` 搞定；
2. **缓存不友好**：按行扫还行，按列扫（`matrix[0][j], matrix[1][j], …`）会每次跳到另一块内存，缓存命中率骤降；
3. **两次分配**：$n+1$ 次 `new`，失败时还要回滚已经分配的部分。

> [!note] 补一个更常用的写法
> 如果不需要"每行长度不同"的灵活性，**开一个长度为 $n^2$ 的一维数组**、用 `a[i*n+j]` 当下标，就同时解决上面三条：内存连续、一次 `new[]` 一次 `delete[]`、按行扫按列扫都局部。
> 代价是下标要自己乘，而且调试器里看不到"二维"的形状。工程代码（包括大多数数值库）选的是这一种。

## 稀疏：矩阵装不下的时候

$n$ 大起来，$n^2$ 就是灾难。先把代价算清楚。用"数组的数组"存 $n\times n$ 的 `double`：

$$4\ \text{(指针变量)}+4n\ \text{(行指针)}+8n^2\ \text{(数据)}=\Theta(n^2)\ \text{字节}.$$

（$4$ 与 $4n$ 是 32 位机器上指针的长度；64 位机器上把 $4$ 换成 $8$，结论不变——主项还是 $8n^2$。）

材料给了一个真实的估计：**把广州所有路口当顶点、街道当边**，每个路口平均连 4 个方向。于是

- 有边的格子数约 $4n$（每条边占两格）；
- 占全部格子的比例约 $\dfrac{4n}{n^2}=\dfrac{4}{n}$。

材料说这个比例"小于 $0.001\%$"。反推一下：$\dfrac{4}{n}<10^{-5}\Rightarrow n>4\times10^{5}$——**四十万个路口**。广州的十字路口确实不止这个数，所以这个估计是站得住的。

于是有了按"非默认值占多少"分类的习惯：

| 类别 | 非默认值的比例 | 含义 |
| --- | --- | --- |
| 稀疏 sparse | $<5\%$ | 绝大多数格子是"无穷远"或 $0$ |
| 稠密 dense | $\ge25\%$ | 大部分格子有内容 |

材料自己也说了：**这两个不是硬界限**，只是说话时的量级约定。真正的判据是"非零元个数 $\text{nnz}$ 是不是远小于 $n^2$"。

> [!note] 稀疏矩阵的两种典型实现
> - **三元组表**：把 $(i,j,w)$ 存进一个数组，只存非零元——再往下就是"稀疏矩阵转置、乘法"那一类课的内容；
> - **行链表**：每个顶点挂一条链，装它的邻居——这正是下面要讲的邻接表。
> 这一讲只做到第二种，材料说"更高效的稀疏矩阵实现留到后面"。

## 邻接表

> [!important] 邻接表 Adjacency List
> 一个长度为 $n$ 的数组，第 $i$ 项是一条链表，装着 $v_i$ 的所有邻居。每条边存两项信息：**邻居是谁**、**权是多少**。

做法上有一个很自然的设计：定义一个"顶点—权"的小结构体，让链表里装的不是裸的顶点号，而是一对值：

```cpp
class Pair {
private:
    double edge_weight;
    int    adjacent_vertex;
public:
    Pair(int, double);
    double weight() const;
    int    vertex() const;
};
```

```cpp
SingleList<Pair> *array;
array = new SingleList<Pair>[16];
```

每个顶点的邻居表就是一条 `SingleList<Pair>`。

### 无向图的一个省法：只存上半三角

无向图的边是对称的：$\{i,j\}$ 在两个顶点的表里都会出现。如果两处都存，**同一条边要存两次**。

省法很简单：**只把这条边记到下标较大的那个顶点的表里**。

```cpp
void insert(int i, int j, double w) {
    if (i < j) {
        array[j].push_front(Pair(i, w));    // 小下标 记到大下标 的表里
    } else {
        array[i].push_front(Pair(j, w));
    }
}
```

![[C11-邻接表-上半三角的链表.png]]

上图的六顶点例子正好是这个形状：0 号的表是空的（没有比它小的邻居），1 号里是 $(0,0.83)$，3 号里是 $(0,0.65),(1,0.72),(2,0.39)$……每条边只出现一次，内存正好是原来的一半。

> [!warning] 省一半内存，代价是查邻居变麻烦
> 只存上半三角之后，**"列出 $v$ 的所有邻居"要多扫一遍全部链表**：比 $v$ 小的邻居在 $v$ 自己的表里，比 $v$ 大的邻居却散在别人的表里。
> 所以这个省法适合"只关心边集、不常查邻居"的场合；如果算法要反复遍历邻居（遍历、最短路、最小生成树都要），**两边都存** 更划算——用一倍的内存换 $O(1)$ 的邻居访问。

### 代价

| 量 | 邻接表 |
| --- | --- |
| 内存 | $\Theta(\lvert V\rvert+\lvert E\rvert)$ |
| 判断 $v_i,v_j$ 相邻 | 平均 $O(\lvert E\rvert/\lvert V\rvert)$（顺着 $v_i$ 的链找） |
| 列出 $v_i$ 的全部邻居 | $\Theta(\lvert E\rvert/\lvert V\rvert)$（平均出度） |

"平均"两个字是 $\lvert E\rvert/\lvert V\rvert$ 的来源：$n$ 个顶点分摊 $2\lvert E\rvert$ 个表项，每个顶点的平均度数就是 $2|E|/n$ 的量级（严格说前向边数是 $|E|$）。

## 三种表示对比

| | 关系表（边的容器） | 邻接矩阵 | 邻接表 |
| --- | --- | --- | --- |
| 内存 | $\Theta(\lvert E\rvert)$ | $\Theta(\lvert V\rvert^2)$ | $\Theta(\lvert V\rvert+\lvert E\rvert)$ |
| 判邻 | $O(\lvert E\rvert)$ | $O(1)$ | 平均 $O(\lvert E\rvert/\lvert V\rvert)$ |
| 列邻居 | $\Theta(\lvert E\rvert)$ | $\Theta(\lvert V\rvert)$ | $\Theta(\deg v)$ |
| 适合 | 边少、只做一次扫描 | 稠密图、频繁判邻 | **算法题默认** |

怎么选，材料给了三个判据：

- **带权还是无权**：无权可以用布尔矩阵，内存省一半以上（一个 `bool` 一字节，`double` 八字节）；
- **有向还是无向**：无向矩阵可以只存上半三角；有向图不行，$(i,j)$ 与 $(j,i)$ 是两条边；
- **稠密还是稀疏**：稠密图矩阵不亏（还能享受 $O(1)$ 判邻），稀疏图用矩阵就是拿 $n^2$ 的内存换几个格子。

一句话记法：**矩阵是"用空间买时间"，邻接表是"用时间换空间"，关系表两头都不占**。

## 勘误

| 位置 | 原稿 | 更正 | 性质 |
| --- | --- | --- | --- |
| 二维数组的代码示例 | 一律用 $16\times16$（`new double*[16]`、循环 16 次） | 示例图只有 **6 个顶点**；$16$ 只是演示"指针算术"时随手取的尺寸，两种表示的实际是同一个 $6\times6$ 的表 | 前后不一致（易误读） |
| 内存公式 | $4+4n+8n^2$ 字节 | 这是 32 位机器的账（指针 4 字节）；64 位上是 $8+8n+8n^2$。主项 $8n^2$ 与 $\Theta(n^2)$ 不变 | 前提未说明 |
| 对角线的默认值 | 带权矩阵对角置 $0$、布尔矩阵对角置 `true`，理由写"顶点与自己连通" | 与"本课程不允许自环"（上一节）冲突。距离矩阵置 $0$ 是对的，邻接矩阵置 `true` 相当于做了**自反闭包**——用的时候要清楚是哪一种 | 约定混淆 |
| 链表结点的类定义 | `SingleNode( int, double SingleNode* = 0 );`；成员名 `adacent_vertex` | 构造函数少一个逗号（应为 `SingleNode(int, double, SingleNode* = 0)`），照抄编译不过；`adacent` 拼写应为 `adjacent` | **原始笔误** |
| 稀疏矩阵的阈值 | "少于 $5\%$ 非默认值为稀疏，$25\%$ 以上为稠密" | 材料自己注明 "these are not hard limits"；判据应当用 $\text{nnz}\ll n^2$ 来表述 | 表述不严 |
| 关系表的列邻居代价 | 写成 $\Theta(\lvert E\rvert)$ | 扫完整张边表是 $O(\lvert E\rvert)$；用 $\Theta$ 需要额外的下界 | 记号不严 |

## 速查

| 表示 | 内存 | 判邻 | 列邻居 | 一句话 |
| --- | --- | --- | --- | --- |
| 关系表 | $\Theta(\lvert E\rvert)$ | $O(\lvert E\rvert)$ | $\Theta(\lvert E\rvert)$ | 最省事、最慢 |
| 邻接矩阵 | $\Theta(\lvert V\rvert^2)$ | $O(1)$ | $\Theta(\lvert V\rvert)$ | 稠密图首选 |
| 邻接表 | $\Theta(\lvert V\rvert+\lvert E\rvert)$ | $O(\deg)$ | $\Theta(\deg)$ | 算法默认 |

| 量 | 结论 |
| --- | --- |
| $n\times n$ 矩阵的字节数 | $4+4n+8n^2$（32 位）；主项 $8n^2$ |
| 稀疏 / 稠密 | 非默认值 $<5\%$ / $\ge25\%$（软界限） |
| 广州路口估计 | $4/n<10^{-5}\Rightarrow n>4\times10^5$ |
| 无向图的省法 | 只存 $i<j$，内存减半，列邻居变贵 |
| C++ 二维数组 | 数组的数组；`new` 两次、`delete` 两次；行不连续 |

## 下一讲

图存好了，接下来要"走"它：从一个顶点出发，怎样不重不漏地访问到所有能到达的顶点？

两种走法——**广度优先** 用队列一层层铺开，**深度优先** 用栈（或者递归）一条路走到底再回头。别小看这两种走法：连通性、最短路（无权图）、拓扑排序、判环、生成树，全是从它们身上长出来的。下一讲的重点是**为什么必须记"访问过"**——没有这个标记，图上的走法会在环里转不出去。
