## 一、核心规则（先看这一节，其他都可以后看）

### 规则 1：先尝试，再主动学习参考实现的组织方式

每个模块里都有三层：

| 档位 | 是什么 | 什么时候用 |
| --- | --- | --- |
| **A–脚手架** | 函数签名 + 提示注释，函数体空着 | **主战场。** 从 A 档开始写 |
| **B–参考** | 带讲解注释的可编译实现 | 卡住时定位问题；通过后主动逐函数比较写法 |
| **测试** | 自动判定对错 | 每写完一个函数就立刻跑 |

> [!important] 学习参考实现的方法
> 先尝试自己的实现，再主动对照 ref 的变量含义、分支组织、边界覆盖和修改顺序。理解后可以模仿、改写，并重新跑测试；不以机械抄写替代理解，也不把 ref 当成唯一标准。
> 一轮完成后直接推进，独立复写留到二轮。

### 规则 2：每个函数写完立刻跑测试，不要攒着

```bash
cd 数据结构训练营/M1-线性表
make test       # 跑全部关卡
make test-1     # 只跑第 1 关
```

看到 `全部通过` 才算通过当前测试。失败时先看编译诊断、测试说明和代码；必要时跑参考实现区分代码与环境问题。复杂度还需要检查实现，不能仅凭测试全绿判断。

### 规则 3：一轮先练全，二轮再独立复写

一轮通关标准：自己实现、通过测试、理解主要指针或下标的含义。遇到错误先解释执行过程，再修改；正确的个人写法可以保留。

独立复写、隔次默写留到二轮复习，不作为一轮推进门槛。每关通过后即可继续下一关，不因复写未做而停住。

### 规则 4：把编译器当老师，不要怕红字

第一次一定会遇到一堆报错和段错误。这不是你笨，这是所有人的必经路径。
最常见的三种，先有个心理准备：

| 症状 | 几乎一定是 |
| --- | --- |
| `Segmentation fault` | 访问了野指针 / NULL，或者越过链表尾部 |
| `undefined reference` | 函数声明了没实现，或者模板实现写进了 `.cpp` |
| 结果全错但不崩溃 | 循环边界差一（`<` 写成 `<=`） |

---

### 规则 5：所有参考实现都要有讲解注释

今后新增或修改的 `*_ref.h` 及其他参考代码，都必须随代码提供中文讲解，现有 M1、M2 已补齐。注释重点解释“为什么这样组织”，不要逐行翻译语句：

- 结构约定、变量角色和循环开始时保持的关系。
- 分支如何覆盖空表、单结点、头尾位置与非法输入。
- 指针修改顺序、需要保留的地址、结点由谁创建与释放。
- 定位与接链各自的复杂度，以及为什么不需要重复的特殊分支。
- 参考实现的适用前提和局限；不同正确写法的指针约定不能混用。

简单访问器简短说明即可，增删、反转、扩容等关键操作要展开。批改除了修错，还要解释 ref 中值得吸收的结构；正确的个人写法可以保留，不要求强行统一。

## 二、每周节奏（每天 30–45 分钟）

| 时间 | 做什么 | 用时 |
| --- | --- | --- |
| 周一 | 读对应讲义，**在纸上画图**（把指标、指针画出来） | 30 min |
| 周二–周五 | 每天推进 1–2 个小函数：写 → 跑测试 → 改 | 30–45 min |
| 周六 | 一轮继续下一关；二轮再安排独立复写 | 30–45 min |
| 周日 | 补齐这周没懂的地方，回讲义核对，更新自己的错题本 | 30 min |

> [!tip] 卡住的标准动作
> 1. 先看报错原文（**不要跳过，逐字读**）
> 2. 在纸上画一遍指针/下标的走向
> 3. 打印中间变量看一眼
> 4. 还不行才看参考实现，**并且看完立刻关掉重写**

## 四、开始之前：环境自检

在终端里跑一次这个，三条都要有输出：

```bash
cd 数据结构训练营/M1-线性表
make test-ref
```

正常应该看到最后一行是 **`全部通过`**。
这条命令跑的是**参考答案**——如果你连它都跑不过，说明环境有问题，不是你的代码问题。

> [!warning] 如果 `make test-ref` 失败了
> 说明编译器或路径有问题，先解决这个再开始，否则你分不清"是我错了"还是"环境错了"。

### 现在就可以做的第一件事

```bash
cd 数据结构训练营/M1-线性表
make test          # 会看到满屏的红——这是【正常】的起点，不是坏事
```

然后打开 [[关卡说明]] 的「S1 · 构造、析构、简单函数」，
对照着改 `sqlist.h` 里的 `TODO 1`，改完跑 `make test-1`。

> [!tip] 满屏的红不是打击，是路线图
> 每一行红字都是一句精确的"你这里还不对"。
> 绿灯一盏盏亮起来的过程，就是你的代码能力长出来的过程。
