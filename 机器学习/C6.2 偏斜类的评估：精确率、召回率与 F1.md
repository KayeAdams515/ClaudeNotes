# C6.2 偏斜类的评估：精确率、召回率与 F1

> [!abstract] 本讲任务
> [[C6.1 系统设计的起点：垃圾邮件分类与误差分析]] 说，所有取舍都靠一个单一数值指标比大小。这一讲先给这个说法泼一盆冷水：**错误率这个最自然的指标，在某些问题上会系统性地骗人。** 然后建立一套不会被骗的指标——精确率、召回率——并解决它们带来的新问题：两个数怎么比？怎么在两者之间做取舍？
>
> 这些概念在 [[C5.2 异常检测算法与系统评估]] 里已经用过一次，这一讲是它们在监督学习里的正式出场，并补上“调阈值”这一块。

---

## 1. 一个 99% 准确的模型，可能一文不值

假设你训练了一个逻辑回归模型 $h_\theta(x)$ 来诊断癌症，$y=1$ 表示患癌，$y=0$ 表示没有。在测试集上它只错了 **1%**，也就是 99% 的诊断都是对的。听上去可以上线了。

然后你了解到一个事实：在这批病人里，**真正患癌的只有 0.5%**。

现在考虑一个“模型”，它连输入都不看：

```matlab
function y = predictCancer(x)
  y = 0;  % ignore x!
return
```

无论来的是谁，它一律回答“没得癌症”。它的错误率是多少？它只会在那 0.5% 真正患癌的人身上出错，所以**错误率只有 0.5%**——比你辛辛苦苦训练出来的逻辑回归还低一半。

这说明，在这种问题上，**错误率低不代表模型好**。更麻烦的是，它连“进步”都能伪装：假设你改了改算法，准确率从 99.2%（错误率 0.8%）涨到了 99.5%（错误率 0.5%）。这是真的变好了吗？不一定——很可能只是你的算法变得更爱回答“没病”，越来越接近那个一律说 0 的笨程序。准确率涨了，被它找出来的癌症病人反而可能变少了。

![[C6.2-板书-癌症分类与偏斜类.png]]

这种情况有一个名字：**偏斜类 skewed classes**——一类样本的数量远远少于另一类。癌症诊断、信用卡欺诈、罕见设备故障都是这样。在偏斜类上，“永远猜多数类”就能拿到极高的准确率，于是准确率失去了分辨能力，我们需要别的指标。

---

## 2. 精确率与召回率

先定一个约定：**把我们想找出来的那个稀有类记作 $y=1$**。在癌症问题里，$y=1$ 就是“患癌”。后面所有定义都围绕 $y=1$ 来写。

对每个测试样本，模型给一个预测，真实情况也有一个答案，两两组合就有四种结果。把它们排成一张 2×2 的表，列是真实类别，行是预测类别：

| | **实际 $y=1$** | **实际 $y=0$** |
|---|---|---|
| **预测 $y=1$** | 真正例 True Positive（TP） | 假正例 False Positive（FP） |
| **预测 $y=0$** | 假负例 False Negative（FN） | 真负例 True Negative（TN） |

这张表通常叫**混淆矩阵 confusion matrix**。名字这样记：后一个词（positive / negative）说的是**你预测了什么**，前一个词（true / false）说的是**你预测得对不对**。所以“假正例”就是你说有病、其实没病——**误报**；“假负例”就是你说没病、其实有病——**漏报**。

有了这张表，就能定义两个指标。

**精确率 Precision**：在所有我们**预测**为患癌的人里，有多大比例**真的**患癌？

$$P=\frac{\text{真正例}}{\text{预测为正的总数}}=\frac{TP}{TP+FP}$$

**召回率 Recall**：在所有**真正**患癌的人里，我们正确找出了多大比例？

$$R=\frac{\text{真正例}}{\text{实际为正的总数}}=\frac{TP}{TP+FN}$$

两个式子分子一样，都是真正例，只差在分母：精确率除以混淆矩阵的**第一行**（我报出来的），召回率除以**第一列**（真实存在的）。所以一个问的是“**报得准不准**”，一个问的是“**找得全不全**”。

![[C6.2-板书-混淆矩阵与精确率召回率.png]]

现在回头看那个一律回答 0 的笨程序。它从来不预测 $y=1$，所以真正例 $TP=0$，召回率

$$R=\frac{0}{0+FN}=0$$

一个病人都没找到。准确率说它 99.5% 好，召回率当场揭穿它毫无用处。

这就是为什么要同时看两个指标：一个分类器要想精确率和召回率**都高**，就必须真的把两类分开。任何偷懒的策略——一律报 0，或者一律报 1——都会让其中一个指标崩掉。

---

## 3. 两者此消彼长：调阈值

逻辑回归输出的 $h_\theta(x)$ 是一个 0 到 1 之间的数，代表“患癌的概率”。我们一直默认的规则是

$$h_\theta(x)\ge0.5\Rightarrow\text{预测 }1,\qquad h_\theta(x)<0.5\Rightarrow\text{预测 }0$$

但这个 0.5 并不是天经地义的，它是一个可以调的**阈值**。

**情形一：只在非常有把握时才告诉病人“你得了癌症”。** 误诊一个健康人，会给他带来巨大的心理压力和不必要的治疗。于是把阈值提高到 0.7，甚至 0.9。这样报出来的病人少了，但报出来的基本都是真病人——**精确率高，召回率低**。

**情形二：尽量别漏掉任何一个癌症病人。** 漏诊一个病人，他可能错过最佳治疗时机，代价比误诊大得多；宁可多报几个，让他们去做进一步检查。于是把阈值降到 0.3。这样几乎所有病人都被找出来了，但也夹带了很多健康人——**召回率高，精确率低**。

一般地，规则写成

$$h_\theta(x)\ge\text{threshold}\;\Rightarrow\;\text{预测 }1$$

threshold 由业务需求决定。把它从 0.99 一路调到 0.01，每个阈值算一对 $(R,P)$，画出来就是**精确率—召回率曲线**：阈值接近 0.99 时在左上角（精确率高、召回率低），阈值接近 0.01 时在右下角（召回率高、精确率低）。曲线具体是凸是凹，取决于模型和数据，但“此消彼长”这个总趋势不变。

![[C6.2-板书-调阈值权衡.png]]

下面是一次模拟：5000 个样本里只有 25 个正例（0.5%），用逻辑回归式的得分。左图可以清楚看到，阈值越高，精确率越高、召回率越低；右图是同一批数据画出的精确率—召回率曲线。

![[C6-阈值与精确率召回率.png]]

既然阈值可调，就面临一个选择：**选哪个阈值？** 或者更一般地，给你几个模型，各有一对 $(P,R)$，**选哪个？** 两个数没法直接比大小，得先把它们合成一个数。

---

## 4. 把两个数合成一个：$F_1$ 分数

考虑三个算法：

| | 精确率 $P$ | 召回率 $R$ |
|---|---|---|
| 算法 1 | 0.5 | 0.4 |
| 算法 2 | 0.7 | 0.1 |
| 算法 3 | 0.02 | 1.0 |

最自然的想法是取平均 $\frac{P+R}{2}$：算法 1 得 0.45，算法 2 得 0.40，**算法 3 得 0.51，最高**。

可是算法 3 是什么？召回率 1.0、精确率 0.02——它把**所有人都报成癌症**。召回率当然是满分（一个都没漏），精确率就等于人群中的患病比例。这和第 1 节那个一律报 0 的程序是同一种作弊，只是方向反过来。算术平均被它骗了，因为 $R=1.0$ 这个大数足以把 $P=0.02$ 的惨状“平均掉”。**所以算术平均不能用。**

正确的合并方式是 **$F_1$ 分数**：

$$F_1=2\,\frac{PR}{P+R}$$

它其实是 $P$ 和 $R$ 的**调和平均** $\dfrac{2}{\frac1P+\frac1R}$。用它重新算一遍：

| | $P$ | $R$ | 算术平均 | $F_1$ |
|---|---|---|---|---|
| 算法 1 | 0.5 | 0.4 | 0.45 | **0.444** |
| 算法 2 | 0.7 | 0.1 | 0.40 | 0.175 |
| 算法 3 | 0.02 | 1.0 | 0.51 | 0.039 |

以算法 1 为例：$F_1=2\times\frac{0.5\times0.4}{0.5+0.4}=2\times\frac{0.2}{0.9}\approx0.444$。现在 $F_1$ 选中的是算法 1——它的精确率和召回率都不算高，但**两个都不差**；那个作弊的算法 3 只剩 0.039。

![[C6.2-板书-F1分数.png]]

为什么 $F_1$ 不会被骗？关键在分子是**乘积** $PR$。只要 $P$ 和 $R$ 有一个是 0，乘积就是 0，$F_1$ 就是 0，另一个再大也救不回来；只有 $P$ 和 $R$ **都等于 1**，$F_1$ 才能到 1。换句话说，$F_1$ 取值在 0 到 1 之间，而且总是被 $P$、$R$ 中**较小的那个**拖住——这正好惩罚了“一个指标拉满、另一个放弃”的偷懒策略。

有了 $F_1$，选阈值就是个机械过程：在**交叉验证集**上试一串阈值（比如 0.1、0.2、……、0.9），每个都算出 $P$、$R$、$F_1$，**选 $F_1$ 最大的那个**，最后在测试集上报告性能。这和 [[C5.2 异常检测算法与系统评估]] 里用交叉验证集选 $\varepsilon$ 是同一个流程——那里的 $\varepsilon$ 就是这里的阈值。

> [!tip] $F_1$ 不是唯一选择（拓展）
> $F_1$ 默认精确率和召回率同等重要。如果漏报的代价远大于误报（比如癌症诊断），可以用 $F_\beta=\dfrac{(1+\beta^2)PR}{\beta^2P+R}$，取 $\beta>1$（常用 $\beta=2$）让它更看重召回率；反过来 $\beta<1$ 更看重精确率。$F_1$ 就是 $\beta=1$ 的特例。

## 5. 小结

这一讲的逻辑链是：错误率在偏斜类上失效 → 换成精确率和召回率这一对不会被“一律猜某一类”骗到的指标 → 两者由阈值控制此消彼长 → 用 $F_1$ 把它们合成一个数，在交叉验证集上选阈值、选模型。

> [!important] 这一讲的三句话
> 1. **偏斜类上错误率会骗人**：只有 0.5% 的人患癌时，一律预测 $y=0$ 的程序错误率只有 0.5%，比错误率 1% 的逻辑回归还“好”；准确率从 99.2% 升到 99.5% 也可能只是模型更偏向预测 0。
> 2. 把稀有类记为 $y=1$，用**精确率 $P=\frac{TP}{TP+FP}$**（报出来的有多少是真的）和**召回率 $R=\frac{TP}{TP+FN}$**（真的有多少被报出来）评估；一律报 0 的召回率为 0。二者由阈值控制：阈值调高 → 精确率高、召回率低；阈值调低 → 召回率高、精确率低。
> 3. 用 **$F_1=2\frac{PR}{P+R}$** 合成一个数，不能用算术平均：一律报 1 的算法（$P=0.02,R=1.0$）算术平均 0.51 最高，$F_1$ 只有 0.039；$F_1$ 选中的是 $P=0.5,R=0.4$ 的算法（0.444）。$P$ 或 $R$ 为 0 则 $F_1=0$，二者都为 1 时 $F_1=1$。在交叉验证集上选 $F_1$ 最大的阈值。
