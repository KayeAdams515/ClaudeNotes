> [!warning] 树这一章的几个陷阱（**考试重灾区**）
> **一、高度与深度的口径**：本课程采用的口径（及英文教材）**从 0 起算、数边**——根深度 0，单结点树高 0，空树高 −1；**国内教材从 1 起算、数结点**。换算：中文 = 英文 + 1。凡涉及高度的公式，先确认口径。详见 [[C6.1 树的概念与术语]] 第六节。
> **二、“满二叉树”的中英文不对应**：
> 
> | 英文 | 定义 | 国内译名 |
> | --- | --- | --- |
> | full binary tree | 每结点 0 或 2 个孩子，形状可不整齐 | 正则 / 严格二叉树 |
> | **perfect binary tree** | 每层填满 | **满二叉树** |
> | complete binary tree | 最后一层从左连续填 | 完全二叉树 |
>

## 课堂强调的几个判断口径

| 问题 | 口径 |
| --- | --- |
| 三个课程目标里哪个当下最不重要 | **Implement（实现）**——有大模型辅助；理解概念才是与模型沟通、调试改进的前提 |
| 数据结构定义里最关键的词 | **efficient**——随便堆也能存取，但不高效 |
| 算法四种描述方式的精确度 | 自然语言（最差，如菜谱"盐少许"）< 流程图/伪代码 < 程序设计语言（最精确） |
| 空间复杂度算什么 | 只算**额外空间 additional memory**，不算数据本身占的 $n$ |
| 大 $O$ 代表什么情况 | **最坏情况**；$\Theta$ 才是确切的阶。报告习惯写 $O$，心里要清楚是 $\Theta$ |
| 多项式 vs 指数 | 计算复杂性理论中的**可计算 / 不可计算**分界线；密码安全性正建立于此 |
| 插入排序 vs 快排图中的颜色 | **蓝线 = 快排，红线 = 插入排序**（按名字猜会看反） |
| 常数倍的算法差距 | 可以**用更快的机器买回来**（1 GHz 跑 $n^2$ ≈ 2 GHz 跑 $2n^2$）；$n^2$ 与 $n\lg n$ 的差距买不回来 |
| 实际运行时间能不能用 | 理论分析上不用；但**大数据/AI 时代实践中越来越常用**（多少 GPU、多少小时、多少钱） |

### 迭代器速查

| 写法 | 含义 | 注意 |
| --- | --- | --- |
| `begin()` / `end()` | 首元素 / **尾后**位置 | `end()` **不可解引用**；空容器时两者相等 |
| `rbegin()` / `rend()` | 末元素 / 首元素**之前** | 反向迭代器的 `++` 往前端走 |
| `*itr` | 读写当前元素（返回引用） | 越过尾后即未定义行为 |
| `itr1 != itr2` | 位置是否不同 | 循环条件用 `!=` 不用 `<`（链表迭代器不支持 `<`） |
| `at(k)` / `[k]` | 检查 / 不检查越界 | `at` 抛 `out_of_range`，`[]` 越界是 UB |

详见 [[C5.1 双端队列 Deque]] 第七至九节。

### 排序选型与代价（第 8 章）

比较平均界按互异键的均匀随机输入或明确随机枢轴模型理解；额外空间含递归栈。具体实现与边界见各篇。

| 算法 | 最好 | 平均 | 最坏 | 额外空间 | 稳定性（本次实现） |
| --- | --- | --- | --- | --- | --- |
| 选择 | Θ(n²) | Θ(n²) | Θ(n²) | Θ(1) | 否 |
| 插入 | Θ(n) | Θ(n²) | Θ(n²) | Θ(1) | 是，严格大于才移动 |
| 基本冒泡 | Θ(n²) | Θ(n²) | Θ(n²) | Θ(1) | 是 |
| 提前终止冒泡 | Θ(n) | Θ(n²) | Θ(n²) | Θ(1) | 是，不保证所有d=O(n)输入都线性 |
| 堆排 | Θ(n)，全等且提前停下滤 | Θ(n log n) | Θ(n log n) | Θ(1) | 否 |
| 常规归并 | Θ(n log n) | Θ(n log n) | Θ(n log n) | Θ(n) | 是，相等取左；原稿代码取右不稳定 |
| 二路快排 | Θ(n log n)，本次等值也推进 | Θ(n log n) | Θ(n²) | 平衡Θ(log n)，最坏Θ(n) | 否 |
| 位图/计数重建整数 | Θ(n+m) | Θ(n+m) | Θ(n+m) | m位/Θ(m)字 | 记录稳定性取决于输出方案 |
| 基数 | Θ(d(n+b)) | 同左 | 同左 | Θ(n+b) | 每位稳定才成立 |

原材料局部经验速度、取样比例与实际机器性能分开：小数组或少逆序考虑插入；严格常数空间且要最坏保证考虑堆排；要稳定考虑正确归并；整数键且位数适合可考虑桶/基数。没有对所有任务同时最优的方法。

> [!warning] 课件问题清单（逐条指到篇目）
> - **sort p.26（逆序计数）**：印 655 inversions / 885 ordered pairs；同页 56 个数枚举复算为 **646 / 894**（和都是 1540 = $\binom{56}{2}$），期望 770 正确。见 [[C8.1 排序基础与逆序数]]。
> - **sort p.4（人名拼写）**：同一批记录里 Kilji / Khilji 两种拼法，与排序逻辑无关，保留原样。
> - **sort p.84、p.86（冒泡漏端点）**：内层印 `j < i`，应为 `j <= i`；否则下标 $i$ 的元素从未参与比较却被 `array[i]=max` 覆盖，**会丢元素**（`[3,1,2]` 复算成 `[1,1,3]`）。2000–3000 组随机数组测试：印刷版失败率 91%–95%，改后 0 失败。见 [[C8.2 选择、插入与冒泡排序]]。
> - **sort p.80（图文不符）**：文字说"最后交换两项"，实际该趟一次交换都没有。见 C8.2。
> - **sort p.61（实测表不自洽）**：175/750/2700/8000 ns 前三行约合 12.5 ns 每逆序，末行只合 7.9 ns；按 12.5 ns 推算 n=64 应约 12 600 ns。趋势仍成立，只作参考。见 C8.2。
> - **sort p.125（最大孩子数值）**：文字写 "(70)"，实际换的是 **81**（同页数组可证）。见 [[C8.3 堆排序]]。
> - **sort p.123（编号口径）**："position n/2 = 5" 是 1 起编号；0 起下标的最后一个非叶结点是 **4**，材料下一帧实际处理的也是 4。见 C8.3。
> - **sort p.105（父公式）**：`(k+1)/2 - 1` 需取整，精确式 $\lfloor(k-1)/2\rfloor$。见 C8.3。
> - **sort p.143（两套数组）**：三指针首帧的两段与随后动画的两段不是同一组（并集相同、切法不同），首帧只能当示意。见 [[C8.4 归并排序]]。
> - **sort p.155、p.164–166（归并代码）**：归并比较用 `<` 时相等取右段 → **不稳定**（要稳定须 `<=`）；插入排序子区间版的 `k > first` 应为 `j > first`（死循环 + 越界），`temp` 应为 `tmp`（编译不过）。见 C8.4。
> - **sort p.157 / p.163 / p.218（表述与编号）**：`++out` 与代码里的 `++k` 不一致；p.163 的索引标成 9…33（整体 +9，不能与 0…24 的轨迹混用）；p.218 的 "heap or **quick** sort" 应为 **merge sort**。见 C8.4。
> - **sort p.226（图文不符）**：文字说"取首元素 + 表已有序"，图上却是乱序数组、用来划分的是下标 7 的 2；结论 $T(n)=\Theta(n^2)$ 不受影响。见 [[C8.5 快速排序]]。
> - **sort p.240（快排递归边界）**：右递归印 `quicksort(array, high, last)`，应为 **`low + 1`**；否则与左递归 `(first, low)` 重叠。材料自己的后续帧（15/11/21 三处）都证明是 `low + 1`。见 C8.5。
> - **sort p.288、290、298、299、324（动画标签）**：`low/high` 残留上一帧数值；`(6,14)` 应为 `(11,14)`、`(11,15)` 应为 `(11,14)`、`4−0` 应为 `20−17`。见 C8.5。
> - **sort p.352、388、392（桶与基数的图）**：`685-5762` 应为 `685-7562`；三位示例第 16 格写 `100` 应为 `010`；p.392 的红分界线偏左一格（该段 0 队列 11 项）。见 [[C8.6 桶排序与基数排序]]。
> - **sort p.364、399（界记号与位数）**：说下界时用了 $\Theta(n)$，应为 $\Omega(n)$；位数 $\lfloor\log_b m\rfloor+1$ 多算一位（值域 $0\dots m-1$，应为 $\lceil\log_b m\rceil$）。见 C8.6。
> - **sort p.396–398（基数实现）**：`size_t` 逆向循环在 `current == 0` 时下溢成死循环；`Type bit` 有符号左移溢出是 UB；`copy_back` 分支 `delete[] array` 后结果只活在按值传入的 `queue` 里，调用方拿不到。见 C8.6。
> - **hashing p.6、p.8、p.25–28（示例数据笔误）**：存 Bob 的那一格写 `Bob 555-341-1231`（Alice 的号码），而同一帧里 Bob 自己的号码是 `555-987-2314`。逐帧沿用，不影响机制。见 [[C9.1 哈希表 Hashing]]。
> - **hashing p.16（滚动哈希）**：展开式写成 $k_{N-1}\cdot37^N+\cdots+k_0$，循环实际算出的是 $k_0\cdot37^{N-1}+\cdots+k_{N-1}$（字符序反了、指数整体多 1）；同页「This is what Java Strings use」的常数实为 **31**（37 是 Weiss 教材的选择）。见 C9.1。
> - **hashing p.14–15、p.19（代码笔误）**：三元组哈希的形参写成 `Integer` 却按 `key[i]` 下标、返回值没取模；结构体哈希声明为 `int` 却缺 `return hashVal;`。见 C9.1。
> - **hashing p.46–48（表述错误）**：写「the entire block is unavailable to keys that hash to $k<7$」，但算到 $k<7$ 的键只要格子空着就直接落下，受影响的只有**算到 7** 的键。见 C9.1。
> - **hashing p.55–56（示意图不自洽）**：$T=8$ 那页把 $9$ 画在 $0$ 号格（$9\bmod8=1$）；$T=11$ 那页把 $47$ 画在 $0$ 号格（$47\bmod11=3$）、$13$ 画在 $5$ 号格（$13\bmod11=2$）而 $2$ 号格空着。两页只用于说明「某些格子不可达」，递推细节不必对上。见 C9.1。
> - **hashing p.57（口径不严）**：定理写「前 TableSize/2 个位置互不相同」，自己证明里的范围是 $0\le i<j\le$ TableSize/2，也就是 TableSize/2+1 个位置；差的那一个正是「半数装载仍能找到空格」的依据。见 C9.1。
> - **hashing p.68（表述不完整）**：「分配两倍大的新表」与「表长取素数」直接冲突（$2p$ 必为偶数），实际取 $\ge2p$ 的第一个素数。见 C9.1。
