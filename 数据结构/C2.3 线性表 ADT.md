## 一、五个基本操作（课件的环形图）

课件用一张环形图给出 **Basic Operations of List**，围绕中心的 "Operation" 排了 5 个编号气泡：

| 编号 | 操作 | 英文 | 语义 |
| --- | --- | --- | --- |
| 1 | 初始化 | **Initialization** | 建立一个空表 |
| 2 | 取值 | **Retrieve** | **按位置取元素**（get element according to **index**） |
| 3 | 查找 | **Find** | **按元素找位置**（get index according to **element**） |
| 4 | 插入 | **Insert** | 在第 $i$ 个位置前插入元素 |
| 5 | 删除 | **Delete / Erase** | 删除第 $i$ 个元素 |

> [!important] 2 和 3 是一对互逆操作，必须分清
> - **Retrieve(index) → element**：给下标要元素。顺序表 $O(1)$，链表 $O(n)$。
> - **Find(element) → index**：给元素要下标。两者都是 $O(n)$（无序时）。
>
> 中文教材常把两者都叫"查找"，是混淆的重灾区。**记法：Retrieve 是"按图索骥"，Find 是"按人找座位"。**

> [!note] 为什么只有 5 个操作
> 回到 [[C1.2 抽象数据类型与容器操作]] 的原则："实际需要的操作往往只是全部可能操作的一个子集。"
> 这 5 个是**最小完备集**：有了它们就能组合出别的（求表长 = 数一遍；判空 = 长度是否为 0；清空 = 反复删除；合并 = 反复插入）。但为了效率，实现时仍会把 `getLength`、`empty` 这类做成 $O(1)$ 的直接成员，而不是每次现算——见下面的"Easy Functions"。

## 二、完整的 ADT 描述

线性表是**n 个同类型数据元素的有限序列**，记为 \(L=(a_1,a_2,…,a_n)\)，n 为表长，n=0 时是空表。它属于线性结构，逻辑上元素排成一条直线，除表头只有后继、表尾只有前驱，其余每个元素都有唯一前驱和唯一后继。

> [!important] List ADT = (D, R, O)
> - **D（数据对象）**：$D=\{a_i \mid a_i \in \text{ElemType},\ i=1,2,\dots,n,\ n\ge 0\}$ —— 同一类型的有限个元素。
> - **R（关系）**：$R=\{\langle a_{i-1}, a_i\rangle \mid a_{i-1}, a_i \in D,\ i=2,\dots,n\}$ —— 线性序，每个元素至多一个直接前驱和一个直接后继。
> - **O（操作）**：初始化、取值、查找、插入、删除（+ 销毁、清空、判空、求长度、求容量等辅助操作）。

## 三、课件在两种实现中给出的完整接口

两种实现的类定义（这里先并排看接口，实现细节见后两节）：

**顺序表 SqList（[[C2.4 顺序表实现]]）**

```cpp
template <typename T>
class SqList {
public:
    SqList(int);              //initialization 初始化
    ~SqList();                //destroy 销毁
    bool empty();             //whether empty 判空
    T get(int);               //retrieve one element 按下标取值
    int getLength();          //get the length 求长度
    int getCapacity();        //get the capacity 求容量
    int find(T);              //find one element 按值查找
    bool insert(T, int);      //insert one element 插入
    void erase(int);          //delete one element 删除
private:
    T* elem;                  //array head address 数组首地址
    int capacity;             //capacity of the SqList 容量
    int length;               //length of the SqList 当前长度
};
```

**链表 LL（[[C2.5 单链表实现]]）**

```cpp
template <typename T>
class LL {
public:
    LL();                     //initialization
    ~LL();                    //destroy
    int getLength();          //get the length
    T get(int);               //get the i-th data
    Node* find(T);            //find the node
    bool insert(T, int);      //insert a node
    void erase(int);          //erase a node
    bool empty();             //whether empty
private:
    int length;               //length of the LL
    Node* head;               //head pointer 头指针
    Node* tail;               //optional 可选的尾指针
};
```

> [!important] 对照着看能学到的四件事
> 1. **public 部分几乎一模一样** —— 这正是 ADT 的意义：**接口相同，实现不同**。用户换实现时代码几乎不用改。
> 2. **private 部分完全不同** —— 顺序表存 `(elem, capacity, length)`，链表存 `(head, tail, length)`。差异全被封装在 private 里。
> 3. **`find` 的返回值不同**：顺序表返回 `int` 下标，链表返回 `Node*` 指针。因为链表没有"下标"这个自然概念，**指针就是链表的"位置"**。这是两种结构最本质的接口差异。
> 4. **顺序表有 `getCapacity`，链表没有** —— 链表**没有容量上限**（No capacity limit），所以这个函数无意义。

> [!note] 为什么两边都保存 `length`
> 完全可以每次现数一遍（链表 $O(n)$、顺序表也要遍历），但把它作为成员变量维护，`getLength()` 就变成 $O(1)$。
> 代价是：**每个 insert 和 erase 都必须记得更新 length**。这是典型的"用一点空间和维护责任，换查询的常数时间"——同样的取舍在树里体现为"结点存子树大小"，在数据库里体现为"物化视图"。
> **易错点：写 insert/erase 时忘了 `length++` / `length--` 是最常见的 bug。**

## 四、辅助函数（Easy Functions）

两种实现都提供的一组"简单函数"：

| 函数 | 顺序表 | 链表 |
| --- | --- | --- |
| Destroy 销毁 | `if (elem) delete[] elem;` | 循环 `delete` 每个结点 |
| Clear 清空 | `length = 0;` | （课件未给，需逐个 delete） |
| Is empty? 判空 | `return length == 0;` | `return length == 0;` |
| Get length 求长度 | `return length;` | `return length;` |

> [!warning] Clear 的两种语义天差地别
> 顺序表的 `clear()` 只写 `length = 0` —— **不释放内存，容量保留**，数组里的旧数据还在（只是不可见）。这是刻意为之：清空后马上又要装东西，不必反复申请释放。
> 但链表的"清空"必须真的 `delete` 每个结点，否则**内存泄漏**。
> 这也提醒：`clear()` 之后顺序表里的残留数据仍在内存中，**不适合用于清除敏感数据**。

## 本节自测 Self-Test

> [!question] Q1：Retrieve 和 Find 的区别？各自在顺序表/链表中的复杂度？
> **A**：Retrieve 按下标取元素（顺序表 $O(1)$、链表 $O(n)$）；Find 按元素找位置（两者都是 $O(n)$）。

> [!question] Q2：为什么链表的 `find` 返回 `Node*` 而顺序表返回 `int`？
> **A**：链表元素没有可直接计算的下标，"位置"的自然表示就是结点指针；顺序表的位置就是数组下标。

> [!question] Q3：为什么链表类里没有 `getCapacity`？
> **A**：链表按需动态分配结点，没有预设容量上限，容量概念不适用。

> [!question] Q4：`length` 作为成员变量维护带来什么好处和什么风险？
> **A**：好处是 `getLength()` 变 $O(1)$；风险是每次增删都必须同步更新，漏改就出 bug。

> [!question] Q5：顺序表的 `clear()` 只写 `length = 0` 有什么隐患？
> **A**：数据仍留在内存中未被清除，且容量不释放；作为"清空"在语义上够用，但不能用于清除敏感信息。
