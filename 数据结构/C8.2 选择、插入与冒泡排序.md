# C8.2 选择、插入与冒泡排序

> [!abstract] 这一讲的任务
> 上一讲把"有多乱"量成了逆序数 $d$。这一讲把三种最朴素的排序摆上桌：选择、插入、冒泡。三个都是 $\Theta(n^2)$，**只看这个结论这一讲就白学了**——差别全在"这个 $\Theta(n^2)$ 是怎么来的"：选择排序的比较次数恒定、交换最少；插入排序精确到 $\Theta(n+d)$，基本有序时是 $\Theta(n)$；冒泡排序的比较次数和 $d$ 无关，怎么改都输给插入排序。

## 选择排序

### 背景：把数组切成两段

思路一句话：**数组左边已经排好，右边还没排；每轮从右边挑出最小的，换到分界处。**

![[C8-选择排序-有序段与无序段的分界.png]]

左边 8 个（`5 7 12 19 21 26 33 40`）已经排好，右边 5 个（`55 41 84 50 94`）还是乱的。分界处是下标 8——下一个该放元素的位置。

![[C8-选择排序-在无序段里找最小值.png]]

无序段的最小值是 **41**，在下标 9。

![[C8-选择排序-把最小值换到分界处.png]]

**一次交换**：分界处的 55 和 41 换位。左边的有序段就多了 41，且它一定比左边都大、比右边剩下的都小——**放进去就不用再动**。

这里有个容易忽略的点：41 不是"挪"过去，是**换**过去，55 被甩到 41 原来的位置。选择排序交换少，代价是**把元素甩得很远**，讲稳定性时会回来算这笔账。

### 实现

```cpp
template <typename Type>
void selection_sort( Type *const array, int const n ) {
    for ( int i = 0; i < n - 1; i++ ) {
        int lowindex = i;
        for ( int j = n - 1; j > i; j-- ) {
            if ( array[j] < array[lowindex] ) {
                lowindex = j;
            }
        }
        Type temp = array[i];
        array[i] = array[lowindex];
        array[lowindex] = temp;
    }
}
```

两个细节：内层从**后往前**扫，只记下标、不移动元素，扫完再换一次；外层只到 `n - 1`——最后一个元素只剩它自己时必然就位。

### 代价：比较次数恒定

内层对每个 $i$ 都要跑完 $n-1-i$ 次，没有提前退出的可能：

$$\text{比较次数}=\sum_{i=0}^{n-2}(n-1-i)=\frac{n(n-1)}{2}=\binom{n}{2}.$$

交换次数是 $n-1$——每轮恰好一次。

| 情况 | 运行时间 | 说明 |
| --- | --- | --- |
| 最坏 | $\Theta(n^2)$ | |
| 平均 | $\Theta(n^2)$ | |
| 最好 | $\Theta(n^2)$ | 已经有序也一样要扫 $\binom{n}{2}$ 次 |

> [!important] 选择排序的代价
> **比较次数恒为 $\binom{n}{2}$，与数据无关；交换恰好 $n-1$ 次。**
> 所以三种情况都是 $\Theta(n^2)$。"最好情况"对它没有意义——表再有序，也要把右边扫一遍才知道哪个最小。

这个性质在一种场合反而有用：**交换很贵、比较很便宜**时（元素是很大的结构体，交换要拷贝几百字节），选择排序的 $n-1$ 次交换是所有 $\Theta(n^2)$ 算法里最少的。

### 稳定性（补充）

选择排序**不稳定**。反例 `[2₁, 2₂, 1]`：第一轮在无序段找到最小值 1，和分界处的 2₁ 交换，得到 `[1, 2₂, 2₁]`——两个 2 的相对次序反了。

根因就是"远距离交换"：一次交换跨过整段，把相等元素的相对次序打乱。插入和冒泡只做**相邻**交换，所以稳定（前提是判断写成严格大于，见下文「搬移版实现」）。

## 插入排序

### 把第 $k$ 个插进前 $k-1$ 个

![[C8-插入排序-从后往前腾出位置.png]]

左边 8 个已经排好（`5 7 12 19 21 26 33 40`），现在要把下标 8 的 **14** 插进去。

从后往前比：14 比 40 小，40 右移一格；比 33 小，33 右移；26、21、19 依次右移。移到 14 前面是 12，**12 < 14**——停，把 14 放进空出来的位置。

结果：`5 7 12 14 19 21 26 33 40 | 9 18 21 2`。

**为什么遇到 12 就可以停？** 因为前 8 个**已经有序**。一旦遇到一个不大于 14 的元素，它前面的只会更小，没有比较的必要。这个"提前停"是插入排序省时间的关键，下一节会把它算成 $\Theta(n+d)$。

算法本身：把第一个元素看成长度为 1 的有序表；对 $k=1,2,\dots,n-1$，把第 $k$ 个元素插进前 $k$ 个里，使前 $k+1$ 个有序。

### 交换版实现

```cpp
for ( int j = k; j > 0; --j ) {
    if ( array[j - 1] > array[j] ) {
        std::swap( array[j - 1], array[j] );
    } else {
        // As soon as we don't need to swap, the (k + 1)st
        // is in the correct location
        break;
    }
}
```

包在函数里：

```cpp
template <typename Type>
void insertion_sort( Type *const array, int const n ) {
    for ( int k = 1; k < n; ++k ) {
        for ( int j = k; j > 0; --j ) {
            if ( array[j - 1] > array[j] ) {
                std::swap( array[j - 1], array[j] );
            } else {
                break;
            }
        }
    }
}
```

注意那个 `break`：**它是整个算法唯一的"聪明"之处**。没有它，内层要跑满 $k$ 次，总代价回到 $\binom{n}{2}$；有了它，内层跑到"第一个不比它大的元素"就停。

### 代价：$\Theta(n+d)$

逐句数：

| 部分 | 次数 | 代价 |
| --- | --- | --- |
| 外层初始化、条件 | $n$ 次 | $\Theta(n)$ |
| 内层比较 | 每次交换一次比较，加最后失败的那一次 | $d+n$ |
| 内层交换 | **恰好等于逆序数 $d$** | $\Theta(d)$ |

关键在第三行：每次 `swap` 消掉一个逆序（上一讲逆序数的结论），每个逆序恰好被消一次。所以

$$T(n)=\Theta(n+d).$$

| 情况 | 运行时间 | 说明 |
| --- | --- | --- |
| 最坏 | $\Theta(n^2)$ | 完全反序，$d=\binom{n}{2}$ |
| 平均 | $\Theta(n+d)$ | 随机表 $d=\Theta(n^2)$，所以平均是 $\Theta(n^2)$ |
| 最好 | $\Theta(n)$ | 已有序，$d=0$，每轮只比一次就停 |

这个公式解释了两件事：

- **为什么它对"基本有序"特别快**：$d=O(n)$ 时总代价 $\Theta(n)$，线性。
- **为什么它对随机数据没优势**：随机表 $d\approx n^2/4$，平方级。$2^{23}\approx8\times10^6$ 个随机数，按材料实测要跑大约**一天**；同样规模，优化过的快排不到 **4 秒**。表长翻倍，代价翻四倍——这就是平方级的形状。

材料还给了一张实测表：8 → 175 ns，16 → 750 ns，32 → 2700 ns，64 → 8000 ns。前三行大约合**每个逆序 12.5 ns**，最后一行只合 7.9 ns，不自洽（见篇末勘误）；趋势对，具体数字随机器变，别背。

### 用搬移代替交换

交换一次要三次赋值（`temp = a; a = b; b = temp`）。但插入排序里的交换有个特点：**被换的元素总往同一个方向走**——新元素一直往左，被挤开的元素一直往右。所以不必真"换"，只要**把大的元素往右搬一格**，最后把新元素填进空位：

![[C8-插入排序-搬移代替交换.png]]

- 交换版：每次比完换一次，3 次赋值；
- 搬移版：每次比完搬一格，1 次赋值，最后填一次。

赋值次数降到 **1/3**，实测速度大约快一倍。

### 搬移版实现

```cpp
template <typename Type>
void insertion( Type *const array, int const n ) {
    for ( int k = 1; k < n; ++k ) {
        Type tmp = array[k];
        for ( int j = k; j > 0; --j ) {
            if ( array[j - 1] > tmp ) {
                array[j] = array[j - 1];
            } else {
                array[j] = tmp;
                break;
            }
        }
        if ( array[0] > tmp ) {
            array[0] = tmp;   // only executed if tmp < array[0]
        }
    }
}
```

最后那个 `if` 是补丁：如果内层一路搬到了 `j = 0`，循环是**正常结束**而不是 `break` 出来的，`tmp` 还没被放进去——这一句负责收尾。

> [!warning] 稳定性就在这个比较符上
> 内层写 `array[j - 1] > tmp`（严格大于），遇到相等就停，相等元素留在前面——**稳定**。
> 写成 `>=`，相等的也会被搬走，**不稳定**。归并排序也有同样的一处（见 C8.4）。

## 冒泡排序

思路：从前往后遍历，找出最大的，把它"冒"到末尾；下一轮找次大的，冒到倒数第二格。

这一节的开头有一段题外话，值得留着：

> [!quote] 原稿
> "the bubble sort seems to have nothing to recommend it, except a catchy name and the fact that it leads to some interesting theoretical problems." — Donald Knuth
>
> Jargon file 里对它的称呼更直接：**"the generic bad algorithm"**。

它的名声就是这么来的：名字好记、想法简单，但比插入排序明显更差。还有一段视频——被问到"排一百万个数最快的方法"时的回答，链接是 <https://www.youtube.com/watch?v=k4RRi_ntQc8>。

### 基本版：每趟把最大的顶到末尾

从前往后，相邻两个比，大的往后换。走完一趟，最大的必然在末尾；下一趟范围缩一格。

![[C8-冒泡排序-第一趟的六帧.png]]

```cpp
template <typename Type>
void bubble( Type *const array, int const n ) {
    for ( int i = n - 1; i > 0; --i ) {
        for ( int j = 0; j < i; ++j ) {
            if ( array[j] > array[j + 1] ) {
                std::swap( array[j], array[j + 1] );
            }
        }
    }
}
```

代价很好算：外层第 $i$ 趟内层跑 $i$ 次，

$$\sum_{i=1}^{n-1} i=\frac{n(n-1)}{2}.$$

**比较次数恒为 $\binom{n}{2}$，与 $d$ 无关**——这是它和插入排序最根本的差别：不管表多乱，它都把该比的不该比的全部比一遍。

### 例子：`7 14 12 33 5 19`

这张表 6 个元素，逆序数是 **6**。走一遍基本版：

| 趟 | 比较与交换 | 结果 |
| --- | --- | --- |
| 起始 | — | `7 14 12 33 5 19` |
| 第 1 趟 | 7·14 不换；14·12 换；14·33 不换；33·5 换；33·19 换 | `7 12 14 5 19 33` |
| 第 2 趟 | 7·12 不换；12·14 不换；14·5 换；14·19 不换 | `7 12 5 14 19 33` |
| 第 3 趟 | 7·12 不换；12·5 换；12·14 不换 | `7 5 12 14 19 33` |
| 第 4 趟 | 7·5 换；7·12 不换 | `5 7 12 14 19 33` |
| 第 5 趟 | 5·7 不换 | `5 7 12 14 19 33` |

一共 **15 次比较、6 次交换**。6 次交换恰好等于逆序数——不是巧合，冒泡每次交换也消一个逆序。

![[C8-冒泡排序-第五趟没有交换说明已有序.png]]

第 5 趟一次都没换，说明表已经有序——可基本版还会把这一趟走完。这就是第一个改进的动机。

### 四次改进

![[C8-冒泡排序-四种改法的比较次数.png]]

#### 少交换：搬移代替交换

和插入排序的改进一样：`max` 一直往后带，遇到小的就把它往前搬。交换没了，赋值少了，但**比较次数一点没变**——每次仍要把整趟扫完才知道谁是最大的。

#### 加旗标：一整趟没换就停

```cpp
template <typename Type>
void bubble( Type *const array, int const n ) {
    for ( int i = n - 1; i > 0; --i ) {
        Type max = array[0];
        bool sorted = true;
        for ( int j = 1; j <= i; ++j ) {
            if ( array[j] < max ) {
                array[j - 1] = array[j];
                sorted = false;
            } else {
                array[j - 1] = max;
                max = array[j];
            }
        }
        array[i] = max;
        if ( sorted ) {
            break;
        }
    }
}
```

> [!warning] 原稿这一行写错了
> 印刷版的内层是 `for ( int j = 1; j < i; ++j )`，少扫一个元素：循环结束时 `array[i] = max` 会把下标 $i$ 上从未参与比较的元素覆盖掉。最小反例 `[3, 1, 2]` 会排成 `[1, 1, 3]`。**必须写成 `j <= i`。** 详见篇末勘误。

#### 缩范围：记住最后一次交换的位置

最后一趟交换之后的部分已经有序，下一趟不必再扫到那里：

```cpp
template <typename Type>
void bubble( Type *const array, int const n ) {
    for ( int i = n - 1; i > 0; ) {
        Type max = array[0];
        int k = 0;
        for ( int j = 1; j <= i; ++j ) {   // 原稿此处为 j < i
            if ( array[j] < max ) {
                array[j - 1] = array[j];
                k = j - 1;
            } else {
                array[j - 1] = max;
                max = array[j];
            }
        }
        array[i] = max;
        i = k;
    }
}
```

> [!warning] 这里也是同一个坑
> 原稿写成 `j < i`，和上一版是同一个错误；改成 `j <= i` 才能正确排序。

![[C8-冒泡排序-限定本次范围.png]]

直觉上这一招能省很多比较，实测**几乎没有区别**——一趟里最后一次交换的位置通常已经靠前，省下的只是常数。

#### 上下交替：一趟冒泡、一趟下沉

只往一个方向顶有个天然的浪费：一趟走完，末尾定了，但**开头可能还很乱**，下一趟仍要从头扫。交替方向可以两头同时收：

```cpp
template <typename Type>
void bubble( Type *const array, int n ) {
    int lower = 0;
    int upper = n - 1;
    while ( true ) {
        int new_upper = lower;
        for ( int i = lower; i < upper; ++i ) {
            if ( array[i] > array[i + 1] ) {
                Type tmp = array[i];
                array[i] = array[i + 1];
                array[i + 1] = tmp;
                new_upper = i;
            }
        }
        upper = new_upper;
        if ( lower == upper ) {
            break;
        }
        int new_lower = upper;
        for ( int i = upper; i > lower; --i ) {
            if ( array[i - 1] > array[i] ) {
                Type tmp = array[i];
                array[i] = array[i - 1];
                array[i - 1] = tmp;
                new_lower = i;
            }
        }
        lower = new_lower;
        if ( lower == upper ) {
            break;
        }
    }
}
```

![[C8-冒泡排序-交替冒泡与下沉.png]]

这是四次改进里唯一**真正有效**的一个。

### 实测：为什么怎么改都输

材料拿 32768 组、每组 1024 个数做实验，横轴是逆序数 $d$，纵轴是比较次数：

![[C8-冒泡排序-插入排序始终更少.png]]

四条结论：

- 基本版：比较次数恒定 $\binom{n}{2}$，一条水平线；
- 加旗标 / 缩范围：初期大约 $n+3d$；
- 上下交替：初期大约 $n+1.5d$；
- **插入排序是 $n+d$，在所有情况下都更低**——只有两个端点例外：完全有序（$d=0$）和完全反序（$d$ 最大）时三者持平。

为什么冒泡怎么改都追不上？因为它每趟都要把整段扫一遍才能确定最大值，**大量比较是"白比"的**；插入排序每轮只走到该停的地方。渐近阶一样，常数不一样——而这个常数差距，在 $n$ 大时就是几倍的运行时间。

> [!important] 这一讲的结论
> 三个 $\Theta(n^2)$ 算法里，**插入排序是默认选择**（数据基本有序时尤其好）；选择排序只在"交换极贵"时考虑；冒泡排序除了好记，没有优势。

### 收口表

| 情况 | 运行时间 | 说明 |
| --- | --- | --- |
| 最坏 | $\Theta(n^2)$ | $\binom{n}{2}$ 个逆序 |
| 平均 | $\Theta(n+d)$ | $d=\omega(n)$ 时慢 |
| 最好 | $\Theta(n)$ | $d=O(n)$，一趟就发现有序 |

> [!bug] `j < i` 为什么会让排序失败
> 这两版的内层职责是"扫过 $0\sim i$ 这 $i+1$ 个元素，把最大的挑出来放到 $i$"。写成 `j < i` 只扫到 $i-1$，**下标 $i$ 上的元素从未参与比较，却被 `array[i] = max` 覆盖掉**——它就这么丢了。
>
> 最小反例 `[3, 1, 2]`：$i=2$ 时 `max=3`，只比 `array[1]=1`，于是 `array[0]=1`；循环结束 `array[2]=3`，得到 **`[1, 1, 3]`**，原来的 2 不见了。改成 `j <= i` 得 `[1, 2, 3]`。
>
> 随机测试：印刷版在旗标版上失败 **1812/2000**，在缩范围版上失败 **2857/3000**；改成 `j <= i` 后两版都 **0 失败**。同节的 p.82（`j <= i`）是对的——**同一节三个版本，只有第一个写对了上界。**

## 速查

| 算法 | 比较次数 | 交换/移动 | 稳定性 |
| --- | --- | --- | --- |
| 选择排序 | 恒为 $\binom{n}{2}$ | $n-1$ 次交换 | 不稳定 |
| 插入排序 | $n+d$ | $d$ 次交换（搬移版 $d$ 次赋值） | 稳定 |
| 冒泡排序（基本） | 恒为 $\binom{n}{2}$ | $d$ 次交换 | 稳定 |
| 冒泡（旗标/缩范围） | 初期约 $n+3d$ | 同左 | 稳定 |
| 冒泡（上下交替） | 初期约 $n+1.5d$ | 同左 | 稳定 |
