# 从零构建 courseware-to-obsidian 技能的提示词（零上下文版）

> 用途：对方没有旧版、没有任何前情。整段喂进去，她就能从零写出等效技能。
> 要点：这份是「写技能」的指令，不是技能本身；判断用判据，事实用硬话。

---

## 可复制正文

```
# 任务

你要写一份**技能文档**，不是整理笔记。

它的使用者是"执行者"：拿到课件（PDF / 图片 / pptx）、有时还有课堂语音转写稿，
照这份技能去做 Obsidian 课程笔记。这份技能会被反复用于不同课程、不同老师、不同体例，
所以它必须自足——执行者手边不会有别的说明。

交付物是一份文档，不是一份大纲，也不是几段提示语。

# 一、先分清两种产物（这决定你写出什么）

- **资料卡**：把材料拆成知识点，一条一块，标上标题，保证不漏。它好检索、经得起核对。
- **讲义**：读者先产生一个疑问，然后被下一段回答。

判据只有一条：**读者看完这份笔记，能不能不上这节课。**

技能里凡是能打勾的东西（frontmatter 有几个键、callout 用哪个类名、双链怎么写），执行者一定会做到；
凡是需要判断的东西（这一段该不该展开、这里该不该开框、这句"显然"要不要拆开），才是技能真正要教的部分。

所以技能的重点不是规定形状，是**给出判断的方法**。

# 二、这类任务会自然滑向哪里（技能要预先防住）

拿到课件和教材，最省力的动作是：抽取知识点 → 一条一块 → 加标题 → 保证不漏。
这条路产出的就是资料卡。它有七种可辨认的形态，写技能时要一种一种堵住：

1. **格式全对，判断全无。** 能校验的项目满分，需要判断的项目归零。
2. **复制形式，不承担动作。** 会学着用疑问句当小标题，但不会把那个疑问真正答完。
3. **均匀覆盖代替取舍。** 各小节一样长——那是没有判断过哪里难，只是把注意力平均分了。
4. **禁令堆多了，退到最保守的体裁。** 什么都说到了，什么都没说透。
5. **把"忠实于材料"当成"讲清楚了"。** 手上材料越完整，越只写材料里有的。
6. **把"严谨"当成"设防"。** 免责声明多到读者分不清哪一句是真提醒。
7. **用目录树模拟思路树。** 用多一级标题假装内容的层次。

这七条不是让你在技能里写"禁止这样"。禁令会把人推回资料卡。
每一条都要配上**替代动作**和**正样本**——告诉执行者"那该长什么样"，比告诉他"不许长什么样"有用。

# 三、构建这份技能时的五条硬规矩

1. **所有内容长在它该在的位置。** 不许在正文之外另立"补充""说明""附录""附：""以上"这类章节。
   一个要求如果属于读材料，就写在读材料那一节，不要放到文末统一交代。
2. **不许先列目录再填格子。** 技能各节的顺序要按**执行者依次遇到的处境**排
   （先摸底 → 再读材料 → 再决定怎么拆 → 再写 → 最后交付校验），
   不要按知识分类排（"总论/方法/规范/附录"）。
   按知识分类排出来的技能，会产出按知识分类排出来的笔记。
3. **不许把风格写成配额。** 不设字数、不设行数、不设 callout 个数。理由见第五节。
4. **不许把操作事实简化成一句话。** 第四节里那些踩过的坑，一句话写不清就会静默出错，
   而且错了看不出来（比如笔迹被整份丢弃这件事）。
5. **不许把这份提示词里的句子直接抄进技能。** 这里的句子是给你理解的；
   技能里要出现的是执行者能直接用的判断和动作。

# 四、技能必须覆盖的十个工作面

每一面我指出"最容易漏的坑"。你要把每个坑转写成执行者能用的指引——
转写不是复述，要写成"你会看到……这说明……这时应当……"。

## 1. 交付物的判据

坑：把"信息齐全"当成"讲清楚了"。执行者会本能地追求覆盖，于是每一条都写两句、每一条都不展开。

技能里要立的是判据，不是篇幅：哪些地方必须展开到"合上书能自己复现"，哪些地方一句话带过是尽责。

## 2. 动手之前先摸底

坑：不看已有笔记就开写，产出和库里其他篇不像同一门课。

要教执行者先看清楚：这门课已有的编号方式、图片命名、frontmatter 键、标题层级、callout 用法、
课程索引的骨架。**各门课的惯例并不统一，按所在课沿用现状，不许"顺手统一"。**
如果要升级体例，先告诉用户并给选择，不要默默造出两种风格并存的库。

## 3. 读材料：手写墨迹是最大的雷

坑：把课件当印刷品读。这一条如果不写进技能，会整份漏掉，而且漏了看不出来。

要写清楚：
- **pptx 里的手写笔迹是独立对象，转成 PDF 时会被整体丢弃**，转出来的 PDF 里一笔都没有；
  渲染出来的页面图也不含笔迹。所以"读图读得再仔细，也救不了文件里根本没有"。
  必须专门查一次有没有笔迹，并把检查结论写进交付说明。
- **PDF 里整页空白的页，往往整页内容都是手写的。** 看到空白页不要当过渡页跳过。
- **墨迹有时间戳。** 如果远早于本学期，它是"课件自带的权威讲解"：内容要全部录入，
  但不能用来判断本学期课堂讲没讲到。这个区别要写进课程索引，不能混。
- **渲染图会吞字。** 中文可能变成方框，嵌在特殊对象里的文字会整块消失。
  所以读完图必须回头核对一遍原始文本；两者不一致时以文本为准，并把差异当成导出问题记下来。
- **公式、图表、手写解法、随堂测的正确选项标记，只有看图才拿得到。** 只提取文本层一定会漏。
- 逐页读图很贵。遇到连续多页内容几乎相同的分步动画，可以只读首帧、末帧和有新增标注的帧，
  但必须先确认它们确实是同一组，并在交付说明里讲清跳了哪些页、依据是什么。**正文页不许跳。**

## 4. 开工前先判断是哪一种输入

坑：把所有输入当成同一种。

至少三种：只有课件；课件加转写稿（整理前就给）；先有笔记、后补转写稿。
三种做法不同——第一种要靠推演补出课堂上会讲的那段；第二种以课件分节为骨架、把转写稿内容归位，
转写稿里真实讲过的优先于推演；第三种走增量合并，知识只增不减。

## 5. 拆分与课程索引

坑：把课程索引当成"追加一行表格"。

要教：按材料自己的分节拆，不按页数机械切；编号按知识依赖顺序排，不必照搬文件顺序，
并在索引里写明对应关系与理由；材料很大时，先把拆分方案（篇名 + 页码范围 + 排序理由）给用户确认再动手。
文件名有禁用字符（半角冒号、斜杠、竖线等），中文和全角标点安全。

课程索引每次都要同步若干处：笔记索引表、内容地图、公式速查、阅读顺序说明、
授课进度与材料问题清单。**材料的问题要逐条指到具体篇目**，不要笼统说一句"有若干缺陷"。

## 6. 图的取舍

坑一：不分场合全靠裁图，或者全靠自绘。
坑二：把板书当"画面"去描述，而不是当"内容"来讲。

判据可以这样立：**图里的信息你能不能无损重述？** 能——自己画，因为重述之后关系更清楚；
不能（实物、电路、界面、真实测量、手写解法）——裁原件，因为重述一定失真。
纯数据对照用表格。

板书是讲课人当场写下的**内容**，不是需要向读者描述的**画面**：
裸嵌入，不写"圈出了什么、箭头指向哪里、用什么颜色画了"；其中的推导、数值、结论要融进正文的叙述流。
每张图放在对应内容讲完之后做印证，不要先贴图再解释。

总判据：**把所有图删掉，正文仍然完整可读。** 做不到，就说明知识还留在图里没讲出来。

## 7. 一篇怎么组织（技能的核心）

坑：把"有结构"理解成"有标题层级"。用四级标题加每级一个框，假装出了层次。

要教的是这条推进链，而且不许跳步：
提出问题 → 让读者先猜 → 给出朴素尝试 → **撞墙** → 引出概念 → 正式定义 → 手算验证 → 回头总结。

撞墙是重点：朴素做法**具体坏在哪**要写透，要给一个会失败的具体反例。看懂失败比记住结论重要。

还要教两件容易被省掉的事：**伏笔与回收**（暂时解释不了的先明说"第 X 节再讲"，然后一定要讲），
以及**开场**（必须是具体场景：有人、有任务、有一个会卡住的时刻；不能用"本节介绍……"开头）。

## 8. 写作契约（格式与禁用项）

坑：把格式规范当成技能的全文，于是执行者只学会了格式。

这里要把 Obsidian 的具体写法写清：frontmatter 必备键、callout 的语义分工、双链与图片嵌入的裸文件名、
行内与行间公式的写法、代码块的语言标签、mermaid 里数学符号用 Unicode 不用公式语法。

同时要有这些硬约束：叙述层不出现"课件"二字（页码可以留作定位）；不写篇末自测板块；
不在正文里逐处标注出处（出处写在 frontmatter 与课程索引里）；
讲课口吻用"我们/你"，但教师姓名、职称、联系方式属于知识点，必须保留；
数字要用脚本独立复算，材料上印的数值也要复算，对不上就标出来；
不确定的地方要诚实标明，绝不把推测写成事实。

**还有一条最容易漏、也最伤**：callout 是"语义事件"，不是排版容器。
正文的默认形态是平铺的裸段落；只有定义、定理、例题、易错、提问、拓展这些明确功能节点才开框，
而且框里必须真的承担那个功能。连着好几个框、中间没有一段平地——那是资料卡的外观。
反过来，禁止空标签式的框名（"解析与说明""题目与思路"这类），要求框名写成"这句话在做什么"。

## 9. 必须补的内容

坑：材料上有结论就照抄结论，材料没写的就不写。

那些"课上一定会讲、材料上只有一行"的地方，要逐条列出该补什么：
公式的来源、被"显然/可以证明/同理"跳过的那一步、为什么用这个形式而不是另一个、
默认你会但没讲的前置知识、图表怎么读（轴、单位、标注、两张图的坐标系差异）、
易错点、材料自带的随堂测（题目原样抄录、标出正确项、逐项给解析）、
以及这个结论后面哪一章会用到。

补的尺度也要写：不编造课堂上不可能讲的内容，补的是该课程指定教材对应位置的展开与公认易错点。

## 10. 合并与交付

坑：交付时不报告自己做了什么检查，用户没法判断可靠性。

合并：拿到转写稿后要做增量合并，铁律是**知识只增不减**；
但"拓展"这类标记是状态不是知识，讲过之后要退役；每次拿到新稿要回扫整个库的相关章节，
不能只看新讲的那一篇；用过的转写稿要改名标注已合并。

交付：先在临时目录产出全部文件，跑一遍自检，再复制进库；
复制后必须再跑一次自检，这次要全绿；最后抽查图片，确认路径生效、中文不是方框。
交付说明里要报告：每份材料的笔迹检查结论（有 N 处还是无）、拆分依据、
哪些图是裁的、哪些是自绘的、哪些是还原的板书、跳读了哪些页及依据、
补充了哪些材料没讲透的地方、以及发现的材料错误或印刷笔误。

# 五、判断不固化，事实必须固化（这条最重要）

写这份技能时，你会遇到两种不同的东西，处理方式相反：

- **风格、取舍、长度、什么时候可以短** → 用判据和破绽来描述，**不设数字**。
  数字看起来精确，实际会被当成配额：凑够了就停，不管凑的是什么。
- **工具的真实行为、文件格式契约、路径与命名规则** → 必须精确、可照做。
  这些是踩过的坑，写得含糊就会静默出错，而且出错了看不出来。

一条要求，如果换个课程就得改数字，它属于风格，别写数字；
如果换个课程依然成立、而且照做才不出错，它属于事实，写死。

技能里讲判断的部分，用这种句式：**"你会看到 X。这说明 Y。这时应当 Z。"**
不要用"必须/严禁/一律"去堆。禁令堆多了，执行者只会退到最安全的体裁。

# 六、技能文档自己的长相

- 前三百字必须是取向（这份文档要产出什么、判断标准是什么），不能是清单。
- 每一条禁令后面，除了一个三到五行的**正样本**，还要并排放一个意思相同、但写成资料卡的**反例**。
  只有正样本，样本会被抄成格式；有对照，执行者才看得出差别在哪。
- 允许各节长短不齐。技能自己若像栅栏一样均匀，它产出的笔记也会是栅栏。
- 给退路："如果拿不准，就……"，比再加一条规则有用。

# 七、交付前自测（把结果贴给我）

1. **反向测试。** 把技能文字当成模板，设想执行者照着它生产一小节。产出的会不会又是一份资料卡？
   会的话，指出是哪一句导致了这个结果，然后改那一句。
2. **样本检查。** 随机挑三条禁令，检查是否都配了正样本与反例。把其中一条的正反例实写出来（各三五行的样子）。
3. **数字巡检。** 全文搜数字，逐个判断它是"事实"还是"风格"；属于风格的一律删掉。
4. **节序检查。** 各节顺序是否按执行者遇到问题的先后排？如果读起来像"总论—方法—规范—附录"，重排。
5. **替换动作检查。** 搜出全文所有"必须/严禁/一律/不要"，看每一条后面有没有"这时应当……"。
   只有禁令、没有替代动作的，补上。

# 八、输出

一份技能文档，加三行使用说明（这份技能什么时候用、第一步做什么、最常错的地方）。

不要在正文之外加"说明""附录""后续""以上"这类章节。不要输出两份技能。不要输出大纲代替正文。
```

---

## 用法

1. 整段贴进去。她不需要任何额外背景——所有前提都写在里面了。
2. 她若只给大纲，回："按第八节，我要完整技能文档。"
3. 她若在文末加"补充/附录"，回："第三节第 1 条。内容长在该在的位置。"
4. 交付后你只验三处：开头三百字是不是取向；每条禁令有没有正样本 + 反例；全文还有没有风格配额。
