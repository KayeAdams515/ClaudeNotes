# vault 体例（实测）

本文是对**会话工作目录（即 vault 根）**这一目标 vault 的实测结论，
调研范围覆盖库里多门课程的既有笔记。
新篇必须和旧篇放在一起不违和，所以这些是**硬约束**，不是建议。

## 1. frontmatter

- 每篇都带 YAML frontmatter，首行 `---`，结束 `---` 后空一行再写 H1。全库无例外。
- 必备 7 键：`title` `course` `chapter` `section` `tags` `aliases` `source`。
  （仅 MOC / 作业与错题 / 复习提纲可以缺 `chapter` `section` `source`。）
- `title` 必须等于文件名去掉 `.md`。含空格、数字、中文标点的值一律加双引号。
- `chapter` / `section` 裸数字或字符串皆可，**每门课内部保持一致**。
- `tags` / `aliases`：行内数组 `[a, b]` 与块状 `- ` 列表**两种写法在库里并存**，
  **接哪门课就照哪门课的既有写法，不要统一**。
- `source` = 「课件文件名 + 页码区间」，页码用 en dash `–`；多来源用 `；` 或 YAML 数组分条；
  **板书信息写在括号里，且带页数并加粗**，这是最新写法：`（**含 N 页课堂板书**）`、`（无手写笔迹）`。
- 可选键见过：`lecturer`、`instructor`、`teacher`、`note`、`type`、`created`、`merged_from`。
- 实例（均为占位写法）：
  - `source: 课件 <文件名>.pdf 全部；<文件名>.pptx p<起>–<止>（与前者同源，含课堂手写）`
  - `- "courseware/<文件名>.pptx p.<起>–<止>（无手写笔迹）"`

**YAML 必须可解析**：`.obsidian/core-plugins.json` 里 `properties: true`，Obsidian 会用新版属性视图接管 frontmatter。
含 `:` `#` `–` 中文逗号的字符串一律加双引号（现库就是这么写的：`title: "C<章>.<节> 中文标题 English Title"`、`section: "3.3"`）。

## 2. 骨架

```
frontmatter
# 标题
> [!abstract] 这一讲要解决什么
## <课件一级节号> <中文标题>
### <课件二级节号> <中文标题>
## 课堂实录
## 勘误
## 速查
## 下一讲
## 相关笔记 Related Notes
```

- H2 之间用 `---` 分隔。
- **H2 / H3 直接用课件原节号**（`## 8.4 <标题>`、`### 8.4.1 <标题>`）；课件本身没有编号的课，
  用 `## 1.` / `## 一、` 这类既有风格，**但同一门课内必须统一**。
- 页码随文写进正文（`（p.123）`），**不写进标题**；旧篇里带 `（课件 p.xx–xx）` 的是早先写法，别照抄。
- **篇首不写「怎么读这份讲义」，不画 mermaid 路线图**；正文里的 mermaid 仍可用于流程图与结构图。
- 篇末顺序固定：`## 课堂实录` → `## 勘误`（有才写）→ `## 速查` → `## 下一讲` → `## 相关笔记 Related Notes`，
  末三行是 `上一讲：[[…]]` / `下一讲：[[…]]` / `返回：[[课程 MOC]]`。
- **不写**逐页对照表、配图清单、课程信息 callout（2026-10 起）。

**体例冲突的裁决**：旧篇里还留着一批旧体例——`## 本节自测 Self-Test` 板块、篇首「怎么读这份讲义」、
mermaid 路线图、篇末逐页对照表与配图清单。**新写 / 重写的篇目一律不写**（见 SKILL.md 4.5 反面清单与第 8 节校验）；
旧篇已有的不主动删，除非用户要求。别被旧篇带跑。

## 2.1 叙述层不出现「课件」（2026-10 起，硬约束）

**这是一份讲义，不是课件的注释。** 读者要的是「这一节课」，不是「这份文件」。

- **正文任何位置都不写「课件」二字**（含「本课件」「原课件」「课件里」；`幻灯片` 同理）。
- 主语是**知识本身**，不是文件：
  「下面这张图把两个视角对齐了」，不写「课件 p.<页码> 画了……」；
  「这里埋了一个伏笔」，不写「课件在这里埋了一个伏笔」；
  「这一条不在主干里」，不写「课件没提，属于补充」。
- **页码可以留**：`（p.<页码>）` 是定位，不是出处声明。只删「课件」二字，不必删页码。
- 唯一的例外是**点名原始材料的缺陷**：写「原稿写 <错值>，实际 <正值>」「原印作 <错法>」——
  用「原稿 / 原文 / 原版」指代，仍然不写「课件」。

元数据层**可以而且应该**出现「课件」，把来历写清楚：

| 位置 | 允许出现「课件」的地方 |
|---|---|
| frontmatter `source` | 课件文件名 + 页码区间（如 `<课件目录>/<文件名>.pptx p.<起>–<止>`） |
| MOC 笔记索引表 | 列头「对应课件」、注明原编号 |
| MOC「授课进度与课件情况」 | 页数、覆盖范围、笔迹检查结论、问题清单 |
| 篇末「勘误」 | 勘误表（列头写「原稿写的」） |

机械判据：`scripts/vault_check.py` 的 `narrative` 段会列出**非 frontmatter、非表格行**里的
「课件 / 幻灯片」（MOC 整体跳过，因为 MOC 就是索引与进度记录），**正常应当为 0**。

**旧篇的处置**：早先写的篇目正文里有大量「课件 p.xx 说了……」，属旧口径。
重写或扩写这些篇目时顺手清掉即可，**不必为这一条整库返工**。

## 3. callout

类名一律小写英文，标题用中文。各类型语义固定，不要混用：

| 类型 | 语义 |
|---|---|
| `> [!important]` | 定义 / 必须记住的结论 |
| `> [!question]` | 停一下先自己想 / 课堂追问 / 自测题 |
| `> [!note]` | 补充说明 / 【拓展】 / 来源与板书来历 |
| `> [!warning]` | 考试易错点、命名坑、勘误 |
| `> [!example]` | 例题 |
| `> [!abstract]` | 这一讲的任务 |
| `> [!info]` | 标注说明、授课进度说明（MOC）、课程信息（MOC） |
| `> [!tip]` | 速查表、下一讲预告 |
| `> [!bug]` / `> [!todo]` / `> [!quote]` | 勘误 / 作业 / 讲稿式开场白 |

正文里抛出的问题，隔一段在叙述里直接给答案，不用折叠块藏答案
（`> [!success]- 答案` 是旧篇的自测板块用法，新篇不用）。

## 4. 双链与嵌入

- 内链只用**文件名裸名**：`[[C<章>.<节> <中文标题>]]`。不写路径、不加 `.md`。
- 别名用 `|`：`[[C<章>.<节> <中文标题> <English Title>|<显示名>]]`。标题锚点用 `#`：`[[C<章>.<节> <中文标题>#<小节标题>|…]]`。
- 图片嵌入用**裸文件名**：`![[C<章>.<节>-板书-<描述>.png]]`，**写路径即失效**。
- **表格单元格里的图片缩放必须写成 `\|60`**，否则整行断列。
- 全库 0 处用标准 Markdown 图片语法 `![](...)`，也没有块引用 `^id`。别引入。

## 5. 文件与目录

- 笔记文件名：`C<章>.<节> 中文标题.md`。禁用半角 `[ ] # ^ | : * ? " < > /`（实测 0 处违反）；
  中文、空格、`·`、全角 `：` 都安全且大量使用。
- 图片放 `<课程>/attachments/`，命名 `C<节>-<描述>.png`：
  - `C<章>.<节>-<描述>.png` —— 该节专用插图
  - `C<章>-<描述>-<描述>.png` —— 该章**跨节汇总**，用裸章号
  - `C<章>.<节>-板书-<描述>.png` —— **课堂手写板书**，必须带 `-板书-`
  文件名一次定稿：`attachments/` **不在** `.gitignore` 里，图片会进版本库。
- 课件目录名因课而异（有的课用短的英文目录名，有的课用 `courseware/`，后者内可再含子目录）：
  **接哪门课就沿用哪门课的现状，不要统一**。
- 转写稿目录名拼写**两套并存**（同一含义的两种拼法，属历史差异）：
  **新建时按所在课沿用，不要"统一"。**
- `source` 引用的课件大多在 `.gitignore` 里（课件目录、转写稿目录通常全被忽略），
  所以页码必须写清文件名，否则无法回溯。

## 6. MOC

每次整理都要同步这几处（不是只追加一行表格）：

```
# <课程>课程 MOC
（定位语）
## 课程信息                    → [!important] 成绩构成 / [!note] 教师联系方式 / [!note] 参考书 / [!warning] 考试提醒
## 课程内容地图                 → mermaid flowchart LR，章依赖链
## 笔记索引
   ### 第 N 章 <章名>
      | 笔记 | 对应课件 | 核心内容 |      ← 列头固定，三列
      ▸ 章后可挂 > [!note] 阅读顺序 / 原编号说明
## 标注约定                     → [!info] 标注说明（拓展图例）
## 授课进度与课件情况            → [!note] 关于「拓展」标注 + [!warning] 课件问题清单（笔迹来历写这里）
## 公式速查（第 N 章）           | 名称 | 公式 |
## 常用数值速查                  | 场景 | 数值 |
```

其他课的 MOC 骨架略不同（例如有的多出复杂度速查与作业板块，有的按主题分组，有的按章、每章一个 MOC），
**接哪门课就沿用哪门课的骨架**。

笔迹的来历、墨迹被 PDF 丢弃这类元信息**只写进 MOC**，不写进每篇正文——读者要的是课，不是文件考古。
**「课件」二字也按这条分界**：frontmatter `source`、MOC 索引表与进度板块、篇末勘误表
属于元数据层，照写；**叙述层不出现，见 2.1**。

## 7. 数学、代码、mermaid

- 行内 `$...$`、行间 `$$...$$`。**不用** `\(...\)` / `\[...\]`。
- 常用环境 `bmatrix` / `cases` / `aligned` / `array`；强调用 `\boxed{}`。
- 代码块语言标签按课选（C/C++ 类课程用 ` ```cpp `，Python / MATLAB 类课程用 ` ```python ` / ` ```matlab `）。
- mermaid 用得很多，两类用途：讲清推理链的失败转折、章级知识地图。
- **mermaid 节点标签用双引号包裹；数学符号用 Unicode（`θᵀx`、`⟹`），不要在里面写 `$...$`。**
- 已装 `execute-code`、`jupyter-viewer`，但全库 0 处可执行代码块，沿用纯展示块。
- 未装 Dataview / Templater，frontmatter 不会被查询插件覆写。

## 8. 「拓展」标记

两种形态，含义相同（课堂没讲到、由教材/通行讲法/你的补充延伸而来）：

- 标题后缀：`## <序号>. <小节标题>（p.<页>）（拓展：课堂未讲解）`、`### <序号> <小节标题>（**拓展**）`
- 段首行内：`**【拓展】** <补充内容正文>…`
- 归纳整理性质的板块写 `（拓展：归纳整理）`。

图例模板（全库一致，统一放 MOC 的「标注约定」，篇内不重复）：

```
> [!info] 标注说明
> 标有 **（拓展）** 或 **【拓展】** 的内容，是**课堂上没有展开讲、由教材与通行讲法延伸补充**的部分。
> 复习优先级：先掌握未标注的主干内容（考试考点集中在这里），行有余力再看拓展部分。
```

授课进度说明模板（转写稿还没覆盖到的章节用；某篇被完全覆盖后删掉它，只留图例）：

```
> [!info] 授课进度说明
> 目前拿到的授课转写稿覆盖到**第 N 节课**，内容截止于**第 X 章全部讲完**。
> **第 Y 章尚未在课堂上讲授**，因此本篇内容全部来自**教材与通行讲法整理**，暂不逐条区分"课堂讲过"与"拓展补充"。
> 等后续转写稿补充进来后，会按与第 X 章相同的规则（标题后加 **（拓展）**、段落前加 **【拓展】**）标注出课堂未讲的内容。
```
