# 课件 → Obsidian 讲义笔记

## 核心目标

**用户看完笔记，既不用再听这节课，也能拿课件一页页对上。**

两件事都要做到：

1. **还原这节课**：页序、节号、例子、黑板题、课上写的代码，和实际讲授一致。读者拿着课件，应当能对着页码找到笔记里对应的那一段。
2. **补足这节课**：课件上只有一行结论、老师口头展开的那半页，要写出来；没上过课的人顺着读也能懂。

所以落笔之前先回答一个问题：**这门课的老师会怎么讲这一页？** 他在这里停多久、先问什么、会在哪一句上补一句"注意下标"、哪几页会直接翻过去。判断方法见 4.7。

**固定的模板会把课压成同一个形状，这是最常见的失败方式。** 结构要跟着课走，见第 4 节。

## 0. 本机现实（动手前先读这一节）

### 0.1 工具映射

这套流程的原始版本是给另一套「远程设备」工具写的，在本机按下表等价替换：

| 原流程里的动作 | 本机怎么做 |
|---|---|
| 列远程目录 | `bash` 的 `ls`，或 `glob` |
| 把文件拉进工作目录 | **不需要**——文件本来就在本机，直接 `read` |
| 在用户电脑上执行命令 | `bash` |
| 把产物写回 vault | `write` / `edit`（见 0.2 的写入限制） |
| 直接读 PDF 的某几页 | **本机做不到**。`read_image` 只吃 PNG/JPEG/WebP/GIF，必须先把 PDF 渲染成图 |

### 0.2 沙箱：读得到 vault，写可能受策略限制

**vault 根 = 本会话的工作目录**（先用 `pwd` 确认）。课程目录、`attachments/`、课件目录都在它下面；
若目标 vault 不在工作目录里，把本节所有相对路径按实际位置调整。

- **读**：直接 `read` / `bash` 就行，不受限。
- **写**：工作目录内可以直接写。目标路径在工作目录之外时（技能目录、别的 vault、系统临时目录），
  默认策略下会 `Operation not permitted`。这时用一次 `sandbox_permissions: danger-full-access`
  重试**同一条命令**（会向用户请求批准），写成功后继续。**不要**因此放弃交付，也不要反复试探。

交付流程固定成：**先在工作目录下的 staging 目录里生成全部产物 → 跑校验 → 复制进 vault**。
staging 目录约定：`<工作目录>/课件笔记-staging/<课程>/`，结构照抄 vault：`*.md` + `attachments/`。

### 0.3 脚本

都在本技能的 `scripts/` 下，用系统 `python3`（已装 pymupdf / Pillow / matplotlib / numpy）：
`pdf_tools.py`（PDF 体检/渲染/裁图/联络表）、`pptx_ink.py`（墨迹体检/叠图）、
`pptx_render.py`（纯 Python 渲染 pptx，含板书叠加）、`vault_check.py`（交付前体检）。

```bash
S=<技能目录>/scripts

# PDF：体检（逐页文本/图/矢量/注释，标出疑似整页手写的空白页）
python3 $S/pdf_tools.py survey "<课件>.pdf" --pages 1-37
# PDF：渲染成图，供 read_image 逐页读
python3 $S/pdf_tools.py render "<课件>.pdf" -o <输出目录> --dpi 140 --pages 1-10
# PDF：看图找裁切范围 / 按矩形或按图片 xref 裁切
python3 $S/pdf_tools.py images "<课件>.pdf" --page 6
python3 $S/pdf_tools.py crop "<课件>.pdf" -o <输出图>.png --page 6 --rect 100,150,500,400 --scale 3

# pptx：墨迹体检（不渲染，一分钟出结论：N 处笔迹分布在 M 页）
python3 $S/pptx_ink.py check "<课件>.pptx"
# pptx：dump 每页 XML 原文——**读图之后必须做这一步**，因为渲染图会吞字（中文变方框）
python3 $S/pptx_ink.py text "<课件>.pptx" --cjk-only
# pptx：【推荐】用 LibreOffice 出底图——版面保真度最高（公式、图表、表格、SmartArt 都对）
#       注意：它和所有转 PDF 的路径一样**会丢板书**，板书要靠下一步叠回去
python3 $S/pptx_ink.py base "<课件>.pptx" -o <底图目录> --dpi 140
# pptx：把板书按原色叠到底图上
python3 $S/pptx_ink.py render "<课件>.pptx" -o <板书图目录> --base <底图目录> --dpi 140
#      然后 read_image 逐张看 <板书图目录>/ink-007.png
# pptx：【退路】没有 LibreOffice 时用纯 Python 渲染器，一步出「印刷内容 + 板书」
python3 $S/pptx_render.py "<课件>.pptx" -o <输出目录> --dpi 140
#      加 --no-ink 只要印刷内容；--which-ink 额外打印每页墨迹定位（格式稳定，可供脚本消费）

# 交付前体检（frontmatter / 图片 / 双链 / 口吻 / 板书描述 / 叙述层不出现「课件」/
#             自测板块 / 拓展 / 板书覆盖 / 转写稿状态）
python3 $S/vault_check.py --course-dir "<staging 或 vault 的课程目录>" --vault-root "<vault 根>" [--notes "<篇名>"]
```

**读图的正确姿势**：`pdf_tools.py render` / `pptx_render.py` 出图 → `read_image` 一张一张看。
一批可以并行发多个 `read_image` 调用，但**单次不要塞太多页**，图多了会看不清细节。
公式、波形图、手写解法、随堂测上的正确选项标记，**只有看图才拿得到**，不能只提取文本层。

### 0.4 体例、墨迹、合并流程的细节在 references/

- `references/vault-conventions.md` —— 目标 vault 的体例（frontmatter / 骨架 / callout / 双链 /
  命名 / MOC / 数学与 mermaid / 拓展模板）。**写之前必须读。**
- `references/inkml.md` —— pptx 墨迹的包结构、InkML 解析要点、时间戳语义、三种载体形态怎么查。
- `references/merge-transcript.md` —— 第 7 节转写稿合并的完整流程（拓展标记怎么标、怎么退役、转写稿怎么标注）。
- `references/pptx-render-limits.md` —— pptx 渲染器的能力边界与**会静默出错**的情形。用它出图前扫一眼，
  出图后必须抽查。

## 三种输入情形（开工前先判断）

| 情形 | 做法 |
|---|---|
| **只有课件** | 走完整流程，第 6 节靠推演补充课堂上会讲什么 |
| **课件 + 语音转写稿（整理前给）** | 两者合并后再写：以课件分节为骨架，转写稿内容归位到对应小节；转写稿里真实讲过的优先于你自己的推演；写完按 7.4 给用到的转写稿改名标注「已合并」 |
| **先有笔记，后补转写稿** | 走 `references/merge-transcript.md` 的合并流程，**知识只增不减**；标「拓展」并**退役已被讲到的旧标记**；合并完给用到的转写稿改名标注「已合并」 |

还有第四种常见情形：**后来才发现课件里藏着手写笔迹**——按 7.5 处理。避免它发生的办法在 1.2。

## 1. 摸底与读取

### 1.1 先摸 vault 现状（不要跳）

动手写之前先搞清楚要接进什么环境，否则容易产出与已有笔记不一致的东西：

- `ls` 列出 vault 与课程目录，看清：已有哪些笔记与章节编号（本次该接哪个章号）、
  `attachments/` 的图片命名习惯、课件目录里哪些是本次新增、转写稿目录叫什么。
  **各课的目录名与命名习惯并不统一**（拼写、大小写、有无子目录都有差异），
  **按所在课沿用现状，不要"顺手统一"**。
- **读 MOC + 任意一篇已有笔记**（用 `read`），对齐：frontmatter 字段、标题层级、callout 用法、双链写法。
  **新篇要能和旧篇放在一起不违和。** 体例细节见 `references/vault-conventions.md`。
- 若本次要**升级体例**（如从整理体改为讲义体），先告知用户并给选择：只新篇用新体例 / 回头把旧篇也改。
  **不要默默造出两种风格并存的 vault。**

### 1.2 读课件之前：先确定有没有手写笔迹（每次必做，不要跳）

**手写笔迹是全部输入里价值最高的部分，也是最容易整份漏掉的部分。**
漏掉的典型原因不是「没看仔细」，而是**笔迹根本没出现在你看到的那份文件里**。

**A. `.pptx` / `.potx` —— 必查，风险最高**

墨迹以 InkML 存在包里，**用 LibreOffice / soffice 转 PDF 时会被整体丢弃**，转出来一笔都看不到。

```bash
python3 $S/pptx_ink.py check "<课件>.pptx"   # 或下面的 unzip 三连
unzip -o -q "<课件>.pptx" -d <解包目录>
ls <解包目录>/ppt/ink/ 2>/dev/null | wc -l      # 墨迹文件数
grep -l contentPart <解包目录>/ppt/slides/*.xml # 哪些页有墨迹
grep -ho 'timeString="[^"]*"' <解包目录>/ppt/ink/*.xml | sort -u | head   # 笔迹时间
```

只要 `ppt/ink/` 非空，就必须解析出来叠回幻灯片再读：

```bash
python3 $S/pptx_ink.py base   "<课件>.pptx" -o <底图目录> --dpi 140   # LibreOffice 底图（版面保真）
python3 $S/pptx_ink.py render "<课件>.pptx" -o <板书图目录> --base <底图目录> --dpi 140
# 然后 read_image 逐张看 <板书图目录>/ink-007.png；没有 LibreOffice 就改跑 pptx_render.py
```

**关键：LibreOffice 转出来的 PDF 仍然没有板书。** 本项目复测过：某页上明显的彩色板书，
在转换后的 PDF 里一笔都没有，必须靠 `render` 叠回去。

**隐藏幻灯片要注意**：LibreOffice 不导出隐藏页（实测一份报 24 张幻灯片的课件只导出 23 页），
所以 `base` 会按「可见幻灯片顺序」映射页码，输出文件名仍是幻灯片号（隐藏页那一号会缺号）。
若隐藏页本身带墨迹，它在 PDF 底图里没有对应页——这类页改用 `pptx_render.py`（它会渲染隐藏页）。

**按各 trace 自己的笔色原色还原**（蓝/红/品红常代表不同轮次的讲解，全画成一种颜色会丢信息）。
解析细节、坐标映射、时间戳语义见 `references/inkml.md`。校验对齐：抽查 1–2 页，
笔迹应压在对应文字/图上，不偏不飘。

**渲染图会吞字，读图之后必须对一遍 XML 文本。** 实测课件底部的一行小字在 PNG 里是若干个方框（tofu），
XML 里文字完好；嵌在 OLE 对象里的文字也会整块消失。所以出完图要跑：

```bash
python3 $S/pptx_ink.py text "<课件>.pptx" --cjk-only    # 与图对照，方框处的真实文字以这里为准
```

两者不一致时，**笔记按 XML 的文字写**，并把差异当成课件导出问题记进 MOC。

**B. `.pdf` —— 查两种形态**

- **注释形态**：`python3 $S/pdf_tools.py survey "<课件>.pdf"` 会报 `Ink注释×N`；渲染出来读。
- **压平形态**：笔迹已并入页面内容，逐页渲染读图就看得到（常见于扫描件或「打印成 PDF」的批注）。

**C. 图片课件** —— 逐页读图即可，留意与印刷字体不同的笔画。

**必须做的三件事**

1. **把检查结果写进回复**：每份课件明确说「有 N 处笔迹（分布在 M 页）/ 无笔迹」，不要沉默。
2. **先判断笔迹的来历，再决定它的地位**：读 `timeString`。若时间戳远早于本学期
   （见过早十几年的），它是「**课件自带的权威讲解**」：内容要全部录入，
   但**不能**用来判断本学期课堂讲没讲到——「拓展」标注仍以本校转写稿为准。**这一条要在 MOC 里写清楚。**
   若时间戳就是本学期，才可当作课堂讲过的证据。
3. **当心「PDF 里整页空白」**：转出来空白的页往往**整页内容都是手写的**。
   看到空白页不要当过渡页跳过，回源文件查墨迹。

> **教训**：曾有一次，两份 pptx 合计 40 余处板书、分布在 30 余页，全被转 PDF 时丢弃；
> 当时逐页读图一处都没发现，直到用户追问才查出来。**读图读得再仔细，也救不了「文件里根本没有」。**

### 1.3 读课件

- 先用 `pdf_tools.py survey`（或渲染器的文本摘要）打印每页文本摘要 + 图片数，规划分节与页码区间。
- **逐页渲染后读图**（`read_image` 分批，单次 ≤ 20 页）。不能只提取文本层——
  公式、图表、手写解法、随堂测的正确答案标记只有看图才拿得到。
- **大课件（数十页以上）的抽读规则**：逐页读图开销很大，遇到**分步动画帧**
  （连续多页内容几乎相同、只是逐步出现）可以只读**首帧 + 末帧 + 有新增标注的帧**。但必须：
  ①先从文本摘要确认它们确实是同一组动画；②在回复里说明跳了哪些页、依据是什么。**正文页不允许跳。**
- **区分「分步动画丢帧」和「手写补写」**：PDF 上公式缺一项时，
  先按 1.2 查墨迹再下结论——很可能那一项是手写补上去的。
  **没查墨迹就断言「这是丢失的动画帧」是错的。**
- **留意手写批注**：讲过的课件常带课堂手写（推导、数值例子、判例、圈注），这是最高价值的内容，逐条录入。
  同时注意哪些文件**没有**批注（可能尚未讲授），写进 MOC 的进度说明。
- **读图时顺手为每张要进笔记的图定来源**：记一句「裁 / 画 / 表」+ 它要说明的那句话（见 3.1.1）。
  裁切只能在手上还有原件时做，画图也只有在刚看完课件时才画得准——这一步留给写正文时补，通常要重读课件。

## 2. 拆分与 MOC

- 按**课件自己的分节**拆（1.1/1.2/…），不要按页数机械切；单篇超过 ~25 页内容就拆开。
- **编号按知识依赖顺序排，不必照搬课件文件名顺序**：若后面某节的记号、定义是前一节的前提，
  就把被依赖的那节排在前面。在 MOC 和每篇 `source` 里写明对应关系与理由。
- 文件名 `C<章>.<节> 中文标题.md`。**不要用**半角 `:` `/` `\` `|` 等字符（macOS/Obsidian/同步盘会出问题），
  全角 `：` 是安全的。
- **课件很大（预计拆 5 篇以上或 ≥ 60 页）时，先把拆分方案（篇名 + 页码区间 + 排序理由）发给用户确认再动手**，
  避免整体返工。
- **「重复课件」未必真重复**：同一份课件的 PDF 版和 pptx 版，印刷内容相同但 **pptx 可能多出全套板书**
  （页数不同就是一个信号）。向用户提「跟已有笔记重复、无需整理」之前，**必须先跑完 1.2**。
- **MOC 不只是追加一行表格**，每次要同步（骨架见 `references/vault-conventions.md` 第 6 节）：
  - 本章的笔记索引小节（篇名 / 对应课件页码 / 核心内容 / **是否含板书及页数**）
  - 课程内容地图 mermaid（新章要接上去）
  - 公式速查表、常用数值表（跨章累积）
  - 阅读顺序说明（当编号顺序 ≠ 课件文件顺序时必写）
  - 授课进度说明与「拓展」标注约定、**笔迹来历说明**
  - **课件问题清单**（笔迹被丢弃、整页空白、公式缺项、印刷笔误等，逐条指到具体篇目小节）
  - 该课程的**指定教材**（第 6 节补充内容时以它为准）

## 3. 图的处理

### 3.0 什么时候必须有图

**图的作用，是替掉你本来要用手比划的那一段话。** 一段叙述里只要出现下面这类句子，
说明它讲的是空间关系、读者得自己脑补构图——这种地方必须给图：

- 「这边高、那边低」「先升后降」「在这一点上下翻转」
- 「两条线叠在一起」「把其中一个挪过去对齐」「差一个相位」
- 「从左边进来，绕一圈回到前面」「分成两路，最后再汇合」
- 「落在这一块区域里」「分界线是这条曲线」
- 一句接一句出现三个以上「如果……就……」，而它们其实是在描述同一张图的不同走法

**反过来，这些不算该配图**：

- 图不承担任何判断，只是让页面好看（封面照、截图、装饰性示意图）
- 一段文字已经能独立讲清，图只是把同一句话说第二遍
- **图代替了本该写的推理**——把推导塞进流程图的节点里。这是最隐蔽的一种退步：
  看图的人以为自己懂了，关键那一步却被藏在箭头上
- 为了「每节都得配一张图」而硬凑出来的图

**图的多少跟着知识点走，不跟着小节数走。** 同一篇里，有的小节配三张还嫌不够，
有的一张贴上去都是多余；要问的是「这一段有没有需要读者在空间里想象的东西」，
不是「这一节该配几张」。

### 3.0.1 图要自足，但不能独自承载知识

- 图一贴出来就该能看懂：轴是什么、单位是什么、标出的那个点代表什么、几条线分别是谁——
  都在图上或紧邻的文字里交代清楚。
- 但**图不能是唯一的知识载体**：结论要由正文讲出来，图只做印证。
- 图放在**讲完之后**，不放在讲之前。先贴图再解释，等于把讲义写成了图注。

### 3.1 图从哪来：裁原件，还是自己画

问一句就能定：**这张图要承担什么？**

- **它要让人看出规律、对比、结构、走向 → 自己画。**
  这类图的价值在「关系」：统一坐标、标出关键点、只留必要的线，比原图清楚。
  典型是函数曲线与波形、频谱、分布与等高线、收敛过程、系统与流程框图、层级与分类结构、
  判别分支、坐标平面上的区域。
- **它本身就是「某个东西长什么样」，用坐标和文字重述不出来 → 裁原件。**
  这类图的价值在保真：照片与实物、真实测量记录、电路与器件连接、软件界面、
  子图多或排版复杂的图、讲课人手写的解法。**把它重画成示意图，等于把信息换成你的猜测**——
  画错的连接图比模糊的照片糟得多。
- **两种都不合适 → 用表格。** 纯数据对照、多个方案逐项比较，表格比图清楚。

**硬标准：图里的信息你能不能无损地重述？** 能无损重述，就自绘（重述之后更清楚）；
不能，就裁（重述一定失真）。

**别把它读成「能画就画、画不了才裁」的优先级。** 裁切不是退路，是某类内容的唯一正确做法；
反过来，能把信息重述清楚却偏要裁一张模糊、字号小、和笔记风格不搭的原图，也不算好图。
两者的取舍点只有一个：**换一种表达，信息是变清楚还是失真。**

**自绘的做法**：优先 mermaid（箭头、分层、流程）或 python 绘图（坐标、曲线、几何）。
画之前先把「这张图要说明的那句话」写下来，画完对着念一遍——念不通就是图画错了。
另外注意课件上那些**只有坐标轴、没有线**的图：那是留着上课现场画的。
**先查 1.2 的墨迹——墨迹里有现场画的曲线，就用还原出来的板书图**（那是讲课人真正画的曲线）；
确实没有墨迹时再自己补画，否则笔记缺一块核心内容。

**裁切的做法**：用 `pdf_tools.py images` 拿 `get_image_rects` 的坐标，取并集后
`pdf_tools.py crop --rect …` 渲染裁切——按并集裁比抽原图好，能保住子图布局和坐标轴标注。
裁完逐张检查：有没有带进页码、水印、邻页内容；缩进笔记后字号还看得清吗（不够就提高 `--scale`）；
坐标轴与图例是否完整。

### 3.1.1 读课件的时候就把来源定下来

每读到一张值得进笔记的图，当场记一句「**裁 / 画 / 表**」，并写下它要说明的那句话。

理由不只是效率：**裁切只能在手上还有原件的时候做**。等写正文时才发现某张图当时没裁、细节已经记不清，
就得回头重读课件；而判断为「画」的图，也只有在刚看完课件、上下文还在脑子里时才好画。
（板书墨迹同理——按 1.2，它就是读图阶段要一并还原的东西。）

### 3.2 板书图的处理（重要）

按 1.2 还原出的带墨迹幻灯片存入 `attachments/`，命名 `C<章>.<节>-板书-<描述>.png`。
**板书是讲课人当场写的「内容」，不是需要向读者描述的「画面」**，所以：

- 用 `![[<图片名>.png]]` **裸嵌入**，**不套** `> [!important] 课堂板书` callout，
  也不写「板书把 X 圈了出来 / 箭头指向 Y / 用品红画了 Z」这类画面描述（颜色、箭头、划线、打叉、框选一概不写）。
- 板书里的推导、数值、命名、结论，**全部融进正文的叙述流**，当成你自己的讲解讲出来。
  例如不写「板书在两个空坐标轴上画了曲线，左非凸右凸」，而写
  「画出来对比最清楚：非凸的那条是一条起伏的波浪线，凸的是一只光滑的碗」。
- **图放在对应内容讲完之后**作为印证，不要先贴图再解释图。

### 3.3 图的验收

- **判据（全节总判据）**：把所有图片删掉，正文仍然完整可读、不缺任何知识点。
  做不到就说明内容还留在图里没讲出来。
- **图做完必须 `read_image` 回看抽查**——裁切图、自绘图、还原的板书图都要查，
  自绘图反而更容易错（坐标范围不对、图例遮住数据、中文变方框、曲线被截断），板书图要查对齐。
  量大时至少抽查**每种类型各一张**，不是固定看两张。
- **文件名前缀只到章，不带小节号**（`C<章>-<描述>.png`）——小节会重排，带小节号会失配。
  **板书图是例外**：它绑定具体幻灯片、不随小节重排，可带节号。名字用中文描述性命名，保证 vault 内唯一。
- 纯装饰性的图（视频截图、封面照）不裁，知识点写进正文即可。
- 自己画图时用**英文标签**，避免 matplotlib 中文字体缺失变方框；
  matplotlib 缓存目录要设 `MPLCONFIGDIR` 指到可写目录，否则会报 `.matplotlib is not a writable directory`。

## 4. 一篇怎么组织（核心）

### 4.1 单篇骨架

```
frontmatter
# 标题
> [!abstract] 这一讲要解决什么   ← 2–3 句：接着什么问题、这一讲给什么答案、为什么值得学
## <课件一级节号> <中文标题>     ← 编号照抄课件：8.2、8.4 …
### <课件二级节号> <中文标题>    ← 8.4.1、8.4.2 …
#### <课件三级节号> <中文标题>   ← 需要时才用，如 8.4.3.1
## 课堂实录                     ← 可空，见 4.8
## 勘误                         ← 有才写
## 速查
## 下一讲
## 相关笔记 Related Notes
```

- **篇首只留 `> [!abstract]`。不写「怎么读这份讲义」，不画 mermaid 路线图。**
  这两块是给整理者看的，不是给读者看的；读者要的是课本身。
- **H2 / H3 直接用课件原编号**，中文标题跟在数字后面。读者手里拿着课件，应当能一页页对上去。
  课件本身没有编号时，用上一层自然顺序（`1.` `2.` …），但同一门课内必须统一。
- **篇内顺序 = 课件顺序**：不重排、不合并、不拆散课件小节；篇的边界仍按第 2 节的拆分方案。
- 篇末只留这几块：课堂实录、勘误、速查、下一讲、相关笔记。**不写**逐页对照表、配图清单、课程信息 callout：
  - 页码随文标注（`（p.123）`）；
  - 配图取自第几页，记在 MOC 或交付回复里；
  - 教师、联系方式、成绩构成只在课程信息篇与 MOC 各记一次。
- H2 之间用 `---` 分隔，沿用本 vault 习惯。

**不写篇首的「板书来源说明」板块。** 笔迹的来历、墨迹被 PDF 丢弃这类元信息写进 MOC，
不写进每篇正文——读者要的是课，不是文件考古。单篇里只在 frontmatter 的 `source` 注明。

**不写篇末自测板块。** 不要出现「课后自测 / 本节自测 / Self-Test」这类标题，
也不要在篇末排一组题目加折叠答案。检验理解靠正文里的「停一下，先自己想想」「课堂追问」，
以及课件自带的随堂测（按第 6 节逐项给解析）。
（库里个别旧篇还留着自测板块，那是旧体例，**新篇不要模仿**；旧篇不主动删，除非用户要求。）

### 4.2 小节写法：按内容选形状

**不要给每一节都套同一条链。** 30 秒能讲完的一节就写 30 秒；课件用半节课讲的一页就展开半页。
先判断这一小节是哪一类，再决定怎么写：

| 类型 | 长什么样 | 写法 |
| --- | --- | --- |
| 概念 / 定义型 | 引入一个新术语或新结构 | 提问 → 猜 → 朴素尝试 → 撞墙 → 定义（4.2.1 的准入检查仍适用） |
| 实现 / 代码型 | 有代码页，或课上手写了代码 | **代码先读**：贴原代码 → 逐行念 → 指出关键行（提前停、越界、稳定性、循环边界）→ 跑课件原例 → 算代价 |
| 推导 / 分析型 | 一个公式、一个和式、一个递推 | 直接推：条件 → 式子 → 化简 → 结论；每个等号给理由，配一张图 |
| 例子 / 动画型 | 逐帧动画、手算演示 | 状态表 + 关键帧图；标出"这里要停一下"的那一帧；不逐帧贴图 |
| 黑板题 / 随堂题 | `Black Board Example` 一类 | 题面原样 → 完整解答 → 手算最常见的错 |

四种最常见的失败形状：

- **实现型写成了概念型**：讲了一堆动机，代码最后才出现，读者上完课还是不会读代码。
- **推导型写成了概念型**：硬编一个生活场景，推导被挤到角落。
- **例子型写成了概念型**：动画一帧帧描述，读者看不出哪一步是关键。
- **每一节都一样长**：说明没有按内容取舍。

**概念型小节仍然要走「逼出来」的链条**：提出问题 → 让读者先猜 → 朴素尝试 → 撞墙 → 定义 → 手算 → 回头总结。
「撞墙」是重点：朴素做法为什么不行，要讲透。看懂失败比记住结论更重要，考试也常考这些「为什么」。
逐符号拆解公式、手算示例、易错点仍按第 6 节要求做，但要**嵌在叙述流里**，不要堆成一个「补充说明」板块。
**这条链只用于概念的展开；概念的出场另有一条更硬的准入规则，见 4.2.1。**

### 4.2.1 新概念的准入检查：第一次出现之前，必须先有一句人话

**任何新术语、新算法、新符号，在正文里第一次出现之前，必须先用下面五问过一遍。**
五问里任何一问答不上，就是「进入太快」，读者会在那里卡住并放弃。

1. **它解决什么问题？** 说名字之前，先让读者意识到有个坎过不去——上一节已经埋好那个坎，或者当场提一个具体问题。
2. **它是什么？用一句人话说。** 不许用「XX 是一种算法／方法」这种同义反复，要用「先……再……」讲动作。
   合格例：**「反向传播，说白了就一句话：先算出这次预测错得多离谱，再把这份『错』按连线的粗细一层层摊回去，看每个权重该负多少责任。」**
   不合格例：「反向传播是训练神经网络的核心算法。」
3. **为什么叫这个名字？** 逐字拆开。名字本身就是隐喻的（核 kernel、地标 landmark、集成 ensemble、注意力 attention、
   反向传播 back-propagation、梯度提升 boosting）尤其要拆：「反向」= 信息流与前向相反，「传播」= 一层层往回传。
4. **它依赖哪个前置工具？** 如果依赖读者可能已经忘掉的工具（链式法则、矩阵乘法、贝叶斯、梯度），
   **先把那个工具本身讲出来**（三五行即可），并且给一个**不带本课程符号**的例子（齿轮传动、水管、天平、投票）。
5. **正文里第一次提到它时，是不是已经在使用它了？** 如果是，过渡缺失，必须补。

**遇到下面三类概念，不许「加一段」了事——必须单独开一节**（该节不写公式，或只写一句最简形式）：

- 整章的核心算法（反向传播、EM、AdaBoost 这类）；
- 有专名、且名字本身是隐喻的；
- 需要读者调动一个前置工具的。

单独开的那一节写完之后，**下一节开头必须把它的结论接上**（典型做法：一张「第几步 → 问什么问题 → 得到什么式子」的路线表，
下一节照着表逐行推）。**表先认脸、公式后展开**，读者才不会在符号里迷路。

**两种实战里真实出现过的失败形态（都是被用户当面指出的）：**

- **「从零件直接跳到装配」**：上一节刚造出一个单元，下一节开口就是「三层结构」「隐藏层」——
  读者既没被告知「单元」是个什么东西（一个装置？一个数？），也没被告知**为什么**要用多个单元。
  修法：补一节「一个不够 → 并排放三个 → 再叠一个做裁决」，把「层」从**动机**里长出来，再给三层命名。
- **「先上公式再解释名字」**：直接开始推 $\delta$ 的链式回传，读者还不知道「反向传播」这个词指什么、
  凭什么快、为什么叫「反向」。修法：在公式之前插一整节，只讲一句话定义、链式法则（配齿轮类比）、三个直觉、名字拆解、路线表。

**验收办法（自己就能做）**：把这一节整段删掉——
若后面的正文读起来仍然通顺，说明它只是复述，没起到过渡作用，要重写；
若后面每处引用它都悬空、读不下去，说明它确实在承重。

### 4.3 开场：从上一页接着讲

**不再强制「具体场景」。** 优先用这三种开头：

1. **课件第一页给出的动机**：这一节在整个算法里的位置、要解决的那个问题。
2. **上一讲或上一节留下的缺口**：上一个做法在什么情况下失效了，于是非解决不可。
3. **上一页刚算出来的数、刚画出来的图**：直接接着看下去。

只有真的存在一个贴切场景时才写场景——为了「讲义体」硬编一个，读者一眼就能看出是编的，反而失真。
如果确实要写场景，它必须能落到这一节的具体机制上（有人要办的事正好需要这个知识），不能用「就像人生一样」这类空比。

### 4.4 伏笔与回收

- 暂时解释不了的细节，**明说「先记着，第 X 节专门解释」**，然后**一定要回收**。
  （典型是推导里突然冒出来的系数或归一化因子：先埋下，等到约掉或用到它的那一步回收。）
- 反复出现的约定要点明第几次派上用场。
- 每篇末尾写**下一讲预告**，用一句悬念收尾，多篇连起来能读成一条线。

### 4.5 反面清单（出现即返工）

- ❌ 以「课件给了两个候选模型」「本节介绍…」开篇——**这是整理体，不是讲课**。
- ❌ 先给完整定义，再用 callout 补「通俗解释」——顺序反了。
- ❌ 把所有补充堆成一个「补充讲解」大板块。
- ❌ 只罗列结论不讲来路。
- ❌ **把课件里「不像知识点」的东西丢掉**：引用与名言、视频链接、工具的原始命令与输出、实测曲线、
  每节末尾 Summary 的原话、随堂问答、作业编号。这些在课上占时间，也常被考。
- ❌ **把课件原例换成自己「更好讲」的例子**：课上跟着算的就是那组数，笔记里必须还是那组数；
  自己的例子另起一段并标（补充）。
- ❌ 「老师说……」的转述口吻（见第 5 节）。
- ❌ 正文出现「课件」（含「本课件」「原课件」；`幻灯片` 同理）——「课件 p.<页码> 画了……」
  「课件在这里埋了一个伏笔」「课件没提，属于补充」都是整理体。**改法：删掉归因、留下断言**，
  指图用「上图 / 下面这张图」。见第 5 节与体例 2.1。**页码可以留**（`（p.<页码>）` 是定位，不是出处声明）。
- ❌ 篇末加「课后自测 / 本节自测 / Self-Test」板块。
- ❌ 只把板书图贴上去、内容没有讲进正文。
- ❌ **新概念第一次出现就直接使用或直接进公式**：还没说「单元」是什么就开始讲「三层网络」；
  还没说「反向传播」是什么就开始推它的四个公式。判据与修法见 4.2.1。
- ❌ **把读者当成已经听过这节课的人**：用「显然」「值得一提的是」带过一个术语的出场。
  新术语的出场永远要占篇幅，哪怕只有一句。

### 4.6 详细程度：按信息增量定，不按篇幅定

**详细不是写得多，是该讲的地方一步不跳。** 课堂上一页内容讲半节课、另一页三十秒带过，
笔记也该是这个形状。所以**不给每节设长度配额，也不让每节长得差不多**——
小节长度整齐均匀，本身就是「没有按内容取舍」的证据。

（每个小节内部的写法见 4.2 与 4.2.1；本节只管一件事：哪一段该长、哪一段该短。）

**该展开的地方，一句都不能省**

- **被压成一行结论的地方**。凡是「由于……因此……」只剩半句、或者只留一个结论词的地方，
  把中间那一步补回来。
- **跳过一步就断链的地方**。从 A 到 C 中间那个 B，只要读者自己补不出来，就必须写出来。
- **「显然」「可以证明」「类似可得」「同理」**。这几句话通常意味着讲课的人口头补了一段，
  笔记里那段要落地。
- **一切「为什么」**。为什么用这个形式而不是那个、换掉会坏在哪里。这类内容最常考，
  也最常是读者卡住的地方。
- **读者会停下来的地方**。一个反直觉的结论、一处和前面印象矛盾的表述、一个符号的来历——
  凡是能让人冒出「等一下，为什么」的点，当场回答，不要留到后面。
- **课上真实发生过的细节**。口头补充、临时举的例子、被追问后改口的说法、
  当场算错的数字（要复算并说明错在哪）。这些恰恰是「照着课件写」永远写不出来的部分。

**该收敛的地方，不要注水**

- **同一件事说第二遍**。讲透一次，后面要提就回指，不要重讲。
- **没有信息量的强调**。「非常重要」「值得注意的是」「不言而喻」——强调本身不是知识。
- **读者已经具备的前置知识**。带一句或直接引用即可，不要把先修课重讲一遍。
- **与主干无关的旁支**。有价值但离主线的，按拓展处理，不要塞进主叙述。
- **用形容词代替机理**。多写一句「这个函数非常陡」，不如说清「陡意味着什么」。

**取舍时问自己两个问题**

- 删掉这一句，会不会有知识点消失？会——留着；不会——那是废话。
- 再加上这一段，会不会产生新的理解？会——加上；不会——那是在凑篇幅。

**必要冗余与有害冗余**

同一个结论在**引入处**和**回收处**各出现一次，是结构需要——读者第二次看到，
才会意识到「原来那里用上了」。同一件事在同一层里换个说法再说一遍，才是有害冗余。

### 4.7 预测这节课：老师会怎么讲

**先给课件做一次「风格指纹」，再决定笔记的重心。** 判断项：

| 课件里的信号 | 课上大概率发生 | 笔记里怎么落 |
| --- | --- | --- |
| 每节有 Outline / Summary 页 | 老师照着这个骨架走 | 笔记就用它当骨架，Summary 的原话保留 |
| 有 Black Board Example / 随堂题 | 课上留时间手算 | 给完整解答 + 手算最常见的错 |
| 有代码页 | 逐行讲，可能另写一版 | 代码先读；课上写的版本优先 |
| 有 Maple / MATLAB / 命令行 | 现场算给学生看 | 保留原始命令与输出 |
| 有实测曲线、对比图 | 边指边讲「谁在上面、差多少」 | 图保留，并写出它要说明的那个数 |
| 有视频、名言、彩蛋页 | 会放、会念，顺带讲背景 | 保留链接 + 一句「课上放过」 |
| 一整页只有一句结论 | 老师会口头展开半页 | 这正是「补充」的位置 |

**判断「会停 / 会跳」**：公式推导、反直觉结论、容易错的下标与边界、和上一章衔接的地方——会停；
重复动画帧、纯导航页、纯目录页——会跳。

**写法上的分寸**：不写「老师会说……」，写成祈使句或断言——「这里要停一下」「注意下标从 0 开始」。
预测是拿来决定详略的，不是拿来写进正文的；没有依据的推测不要写。

### 4.8 课堂层

- 每篇末尾 `## 课堂实录`：老师强调的、口头补充的、随堂提问、布置的作业、下节预告。
  没有转写稿就写 `（待补：本节暂无转写稿）`，不要编。
- **用户在笔记里粘贴的任何东西，都是课堂证据**，优先级高于你的推演：课上手写的代码、板书照片、
  口诀、临时举的例子。必须收进正文对应位置，不删、不挪到附录；有明显的记录笔误就改正，
  并在旁边注明「记录原样是……」。这是最容易造成不可逆丢失的地方（见第 8 节）。
- 合并转写稿见第 7 节。

## 5. 写作规范

- **语言**：中文正文 + 英文专业术语对照，首次出现写成「代价函数 Cost Function」这样。
- **不得省略任何知识点**，包括随堂测题目、课堂手写批注、课件里的引用与视频链接、工具的原始命令与输出。
  课程信息（教师、联系方式、成绩构成、参考书与 ISBN）在课程信息篇与 MOC 各记一次即可，**不在每篇重复**。
- **Obsidian 格式**：YAML frontmatter（title/course/chapter/section/tags/aliases/source）、
  callout（`> [!abstract]` 本讲任务、`> [!important]` 定义与结论、`> [!question]` 提问与追问、
  `> [!example]` 手算、`> [!warning]` 易错点、`> [!note]` 前置知识与拓展）、`$`/`$$` LaTeX、
  `![[文件名.png]]` 裸文件名嵌入、`[[笔记名]]` 双链。
  正文里抛出的「停一下」问题，隔一段在叙述里直接给答案，不用折叠块藏答案。
- **讲课口吻用「我们 / 你」，不写「老师说……」的转述。** 把「老师给的窍门是……」写成「速判窍门：……」。
  **但课程信息篇与 MOC 里的教师姓名、职称、联系方式是知识点，必须保留**——被禁的是转述口吻，不是「老师」二字。
- **句子的主语是「我们 / 你 / 事物本身」，不是课件、板书、这一页、这张图。** 主语一变成课件，
  你就从讲课退回成解说。把「课件手写标注 $m=47$」写成「这里 $m=47$」；
  把「课件用粉框圈出第二个」写成「第二个更好」；把「课件把这个方案打垮了」写成「现在往数据里加一个样本……」。
  动词同理：用「画出来看 / 代进去 / 我们来看」，不用「课件画了 / 课件给了 / 课件印着」。
- **正文里不出现「课件」二字**（含「本课件」「原课件」；`幻灯片` 同理）——硬约束，完整分界与替换表
  见 `references/vault-conventions.md` **2.1**。**页码可以留**，要删的只是把文件当主语的说法。
  元数据层（frontmatter `source`、MOC 索引表与进度板块、篇末勘误表）照旧写「课件」，把来历说清。
- **不逐处标注内容出处。** 印刷内容、课堂板书、你的补充，读起来应当是同一个人在连贯地讲一节课，
  不要逐句标「课件原文」「课堂板书」。出处统一写在 frontmatter 的 `source` 与 MOC 的索引表、进度板块；
  只有成段的延伸补充（整节都不在课件里）才在小节标题上加一次（补充）。
  **例外：原始材料本身的缺陷仍然要在正文点名**，且三者措辞要分清——印刷与板书都写错的是**原始笔误**
  （写「原稿写 X，实际 Y」，不写「课件写错了」）；
  只在导出件里缺、原件里有的是**导出丢失**；两边都没有、但按数学必须存在的是**你补全的**。
- **课件的原例、原数、原命令不改**：课上跟着算的是那组数，笔记里就必须还是那组数；要换例子另起一段标（补充）。
- **数字双向验证**：你写的每一个数字要用 python 算过；**课件上印的数值也要独立复算**。
  对不上就在笔记里标出来（可能是课件笔误），不要默默照抄。
- **不确定的地方要诚实标明**：图看不清、相邻页几乎相同分不出差异、靠教学常识补的论证——
  写明「此处为分步动画」或「以下为标准讲法的补充推论」。**绝不把推测写成课件事实**——笔记要替代听课，就不能骗人。

## 6. 必须补充的内容（关键）

课件上是一行结论的地方，笔记要展开成课堂上会讲的那一段：

- **公式来源**：只给结果的公式，要写它是怎么解出来的。
- **省略的推导**：课件写「mathematically equivalent」「可以证明」的地方，把过程写全。
- **设计动机**：为什么用这个函数/这个损失，换成别的会怎样（这类「为什么」课件几乎从不写，却最常考）。
- **前置知识补课**：课件默认你会但没讲的（记号约定、log 的底、i.i.d.、偏导数、NP-hard 等）。
- **图表读法**：坐标轴含义、标注数字代表什么、图与图之间的递进关系、
  **同一页左右两张图的坐标系区别**（初学者最容易卡在这）。
- **易错点**：符号方向、上标下标含义、边界点取值、两个相似概念的混淆。
  具体清单因课而异——按这门课真实的坑写，不要套用别的课。
- **随堂测**（课件自带的题，不是你出的自测题）：题目原样抄录，标出课件里的正确选项（常以绿色高亮），
  **逐项给解析**；填空题自己算出答案并写出完整步骤和数值。
  写在它在课件里出现的位置对应的正文段落里，**不要挪到篇末**。
- **前后联系**：这个知识点在后面哪一章会被用到、是哪个更大结论的种子。
- **专业关联**：vault 的使用者是 AI 方向，把知识点接到 CNN/DSP/图像处理/PyTorch 实践等具体场景上。

**补充的尺度**：不编造课堂不可能讲的内容；补的是**该课程指定教材**
（先从课件/MOC 里确认是哪本，不要默认某本经典书）对应位置的展开，以及公认的易错点。

## 7. 转写稿合并

完整流程见 **`references/merge-transcript.md`**（含「拓展」怎么标、怎么退役、ASR 误识别怎么处理、
转写稿改名标注「已合并」的全部规则）。核心是三条：

- **铁律：知识只增不减**；但标记是状态不是知识，必须随进度退役。
- 每次拿到新转写稿，都要**回扫整个 vault 的相关章节**，不能只看本次新讲的那一篇。
- 最后一步给用到的转写稿改名加 `-已合并`（只改名，不移动不删除），并确认没有误标无关文件。

## 8. 交付与校验

1. **在工作目录的 staging 目录里产出**：`<工作目录>/课件笔记-staging/<课程>/`，
   `.md` 与 `attachments/*.png` 都放这里，结构照抄 vault。
2. **合并已有笔记时，先 `read` vault 里的当前版本**（用户可能自己改过），在它基础上改，再写回同一路径。
3. **重写整篇前先把用户自己加的批注抽成字符串清单**（手写解析、口诀、易错举例、粘贴的图片嵌入、脚注），
   改完逐条 assert 仍存在。这是最容易造成不可逆丢失的地方。
4. **先做一遍「新概念准入」人工检查**（脚本查不出来，见 4.2.1）：把本篇所有术语／算法名／专有符号的**首次出现位置**
   列出来，逐个问「它前面有没有一句人话」。重点看：小节标题里出现的名词、速查表里出现但从没定义过的名词、
   课堂实录里提到的名词。**这三处最容易漏**——读者正是照着标题和速查判断「我到底懂了没有」。
5. **跑校验**：`python3 $S/vault_check.py --course-dir "<staging 课程目录>" --vault-root "<vault 根>"`。
   它会查：frontmatter 键齐全与 title=文件名、每个 `![[x.png]]` 是否存在、每个 `[[笔记名]]` 是否有落点
   （含标题锚点）、转述口吻、板书画面描述、**叙述层是否出现「课件」**（MOC 与表格行除外，见体例 2.1）、
   自测板块、板书图是否都用上、转写稿合并状态，
   并列出全部「拓展」标记供人工核对退役/补标。
   staging 阶段图片与双链会大量报缺失（vault_root 指错），此时应 `--vault-root` 指向 vault 根、
   `--course-dir` 指向 staging，再人工区分哪些是"还没复制过去"。**复制进 vault 后必须再跑一次，这次要全绿。**
6. **复制进 vault**：一次提权的 `bash`（`sandbox_permissions: danger-full-access`），
   `cp` / `rsync` 到 `<vault>/<课程>/`。vault 常放在同步盘里，**不要留下 `.tmp` 之类的临时文件**。
7. **`read_image` 抽查**写进 vault 的图（每种类型至少一张），确认路径生效、中文不是方框。
8. **回复里说明**：
   - **每份课件的笔迹检查结果（有 N 处 / 无）**、拆分依据；
   - 哪些图是裁切、哪些是自绘、**哪些是还原的板书**；
   - **覆盖情况**：这一篇覆盖 p.<起>–<止>；**哪些页没进正文**（导航页 / 重复动画帧 / 只一句标语）及原因；
     哪些动画帧是压缩的、依据是什么；
   - **补充了哪些课件没讲透的地方**（用户最看重）；
   - 若动过标记，另报退役/补标清单；若标注了转写稿「已合并」，列出具体文件名；
   - 若发现课件数值对不上或印刷笔误，点名。
